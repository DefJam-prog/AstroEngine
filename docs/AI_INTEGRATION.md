# Codex / AI Integration и безопасность

Статус: требования пользователя из раздела 09. AI Editor API, адаптер Codex, sandbox и AI Game Tester ещё не реализованы. Документ не описывает текущие возможности или гарантии внешних AI-продуктов.

## Граница интеграции

AI Editor API доступен локально через типизированные команды. Для Codex предусматривается отдельный адаптер. Интеграция не требуется для запуска игры или редактора.

AI не изменяет внутреннее состояние сцен в обход команд. Общие контракты команд, транзакций и ограничений обратимости определены как требования в [ARCHITECTURE.md](ARCHITECTURE.md).

## Возможности по мере развития

- Чтение дерева проекта и анализ сцен.
- Создание и изменение объектов, материалов, UI, графов логики и шаблонов игр.
- Предложение изменений, тестирование и составление отчётов.

Эти возможности вводятся по мере готовности необходимых подсистем, в явно назначенных подэтапах. Изменения шаблонов подчиняются требованиям [GAME_TEMPLATES.md](GAME_TEMPLATES.md).

## Пайплайн операции

Запрос → план → проверка схемы и разрешений → dry-run/diff → подтверждение для рискованных операций → транзакция → тесты → отчёт.

Применимость dry-run и обратимость конкретной команды должны быть документированы. Наличие этапа транзакции не означает, что любое runtime-действие можно отменить. Контрольные точки и откат AI-изменений следуют P09 из [PRODUCT_REQUIREMENTS.md](PRODUCT_REQUIREMENTS.md).

## Ограничения доступа и выполнения

AI не получает неограниченного доступа к файловой системе, секретам и сети. Требуются:

- Список разрешённых директорий.
- Sandbox для сборок и тестов.
- Журнал действий.
- Контроль затрат и времени.
- Возможность остановки долгих операций.

Конкретный локальный транспорт, механизм разрешений, изоляция процессов, политика доступа к секретам и сети, лимиты и механизм остановки пока не выбраны. Локальность API сама по себе не подтверждает изоляцию. Эффективность ограничений должна быть проверена при реализации.

## AI Game Tester

Требуются детерминированные сценарии ввода и проверки коллизий, прохождения уровней, поведения транспорта и save/load; сбор логов и скриншотов, поиск регрессий.

Не обещать, что AI гарантирует отсутствие ошибок. Отчёты должны указывать выполненные сценарии, результаты и ограничения проверки.

Предложения оптимизации проверяются на изменения поведения и визуальные отличия. Исходные пользовательские ресурсы сохраняются при генерации оптимизированных копий.

## Будущая проверка реализации

При реализации соответствующих подэтапов проверить пайплайн команд, отклонение недопустимых схем и неразрешённых действий, подтверждение рискованных операций, ограничения директорий/секретов/сети, изоляцию сборок и тестов, аудит, лимиты и остановку. Проверить запуск игры и редактора без AI-интеграции и повторяемость детерминированных сценариев тестера.

Зависимости: Typed Command API, схемы, модель проекта/сцены, транзакции, диагностика и тестовая инфраструктура. Конкретные SDK, модели, протоколы и версии не выбраны. Исполняемых тестов и подтверждений безопасности пока нет.
