# Графический редактор и UX

В меню «Файл» → «Открыть проект» поле пути к `project.astro` имеет кнопку «Обзор…» для выбора `.astro` файла. В «Новый проект» кнопка выбирает существующую родительскую папку, а указанное имя задаёт новую дочернюю папку. Уже существующая папка с таким именем не заменяется. После выбора путь подставляется в поле; выбор можно отменить без изменения текста. Оба действия используют системный диалог Windows через SDL3.

## Жесты Rendered Scene View (07.2bb)

В Scene View правой кнопкой вращается камера, средней — панорамируется, колесом выполняется zoom при наведении. Если drag начат внутри Rendered viewport, удерживаемый жест продолжается за его границами до отпускания. Нажатие снаружи viewport игнорируется. Это управление временной камерой редактора; оно не меняет сцену. Проверено автоматическими synthetic SDL events на Windows; физическая мышь и другие платформы отдельно не подтверждены.

## 3D-просмотр модели в Project (07.2av)

Выбери зарегистрированную glTF-модель в Project — миниатюра геометрии появится вместе со сводкой количества мешей, примитивов, вершин и индексов. На изображении: правая кнопка мыши вращает камеру, средняя двигает, колесо меняет зум. При выборе viewport кадрирует все импортируемые primitives. При выборе другого ресурса GPU cache предыдущей модели очищается. Ошибки/лимиты импорта отображаются в Project. Это изолированный preview: изменения камеры и временные `MeshRenderer` не попадают в рабочую Scene.

## Предпросмотр ресурсов (07.2au)

После выбора зарегистрированного изображения в Project показывается фиксированная миниатюра 192×144 через BGFX texture cache; при отсутствии cache entry используется только зарегистрированный кэшированный путь и WIC. Выбранная модель отображает число meshes, primitives, vertices и triangle indices и диагностическое сообщение importer при ошибке. 07.2av дополняет эту сводку отдельным вращаемым 3D viewport. Preview не меняет Scene или source assets; model importer может записать производный кэш в Library. Material/script preview не реализован.

В 07.2as окно Project получило ограниченный выбор зарегистрированного ресурса из Game View диагностики. В 07.2at добавлен первый read-only Asset Browser поверх AssetRegistry: типовой фильтр, UTF-8 substring поиск по source-relative path/AssetId и выбор записи для карточки с type, ID и путём реестра. Список охватывает только зарегистрированные assets; поиск регистрозависим. Незарегистрированные файлы, дерево папок, drag-and-drop и открытие ресурса не поддерживаются. Внешний индекс перечитывается при повторном открытии проекта. Поддерживаемый минимальный preview описан выше.

## Asset Browser (07.2at)

В окне Project выбери тип ресурса или `All asset types`, затем введи фрагмент относительного пути либо decimal AssetId. Поиск сопоставляет точный UTF-8 substring с учётом регистра. Нажатие на строку показывает запись в карточке выбранного зарегистрированного ресурса. `Refresh asset catalog` перестраивает список из открытого AssetRegistry; чтобы получить изменения index, записанные другой программой, переоткрой проект. Каталог не добавляет, не удаляет и не открывает файлы.

Статус: требования пользователя из раздела 05. Документ не определяет окончательный макет интерфейса. На 02.3 есть первые панели Scene View (структурное дерево), Hierarchy и Inspector для schema properties сущности; остальные области и рабочие пространства не реализованы.

## Встроенный редактор кода C# (P15)

Editor должен включать отдельную Code workspace/window для ручного редактирования игровых скриптов на C#. В контексте требований это текстовый редактор исходного кода внутри Editor, а не произвольная командная оболочка ОС.

Минимальные критерии будущей реализации: создавать/открывать/сохранять `.cs` файлы проекта; корректно обрабатывать UTF-8 и несохранённые изменения; показывать ошибки и предупреждения компиляции с переходом к строке; компилировать скрипты текущего проекта и сообщать диагностируемый результат. Скрипт должен подключаться к объекту/сцене через явную схему и документированный runtime API, с Inspector-свойствами только для публично поддержанных типов.

Подэтап 04.15 добавил базовую Windows workspace на существующем Dear ImGui: файловый список `Scripts/**/*.cs`, создание/открытие/атомарное UTF-8 сохранение, dirty prompt, явный запуск локального build pipeline и compiler diagnostics с переходом к source line. Открытие ограничено `.cs` внутри `Scripts` и 4 MiB на файл. Платформенная оценка host/SDK и лицензий остаётся открытой; syntax highlighting, LSP, debugger, refactoring и sandbox отсутствуют. См. [C# scripting API](CSHARP_SCRIPTING_API.md) и [отчёт 04.15](reports/04.15-csharp-code-workspace.md).

Подэтап 04.16 добавил в C# Code workspace сворачиваемую форму Build settings для `.astro/csharp-build.json`: закреплённый SDK 10.0.x, фиксированный `net10.0`, имя сборки и список bindings из `Scripts/**/*.cs`. Изменения сохраняются только по кнопке. Некорректный существующий манифест нельзя заменить без подтверждения. Поддерживаются только SDK/framework текущего prototype; см. [отчёт 04.16](reports/04.16-csharp-build-manifest-editor.md).

Подэтап 04.17 уточнил сообщения в Project → C# scripts: они различают отсутствующую регистрацию, несовпадающий managed type, устаревший source hash и output другой сборки. **Register current C# build** синхронизирует выбранные manifest bindings и сохраняет AssetId для тех же исходников. Это сравнение manifest/build/index; CLR тип не загружается автоматически и проверяется только при явном одобренном Play.

Отдельный от текстового редактора source-code, в 04.14 Inspector получил раннее authoring существующих `ScriptBehavior`: выбор актуального registered binding проекта, создание выключенного компонента, toggle enabled и удаление с Undo/Redo. Для включения требуется свежая C# build registration; код скрипта здесь не редактируется и не компилируется. См. [C# API](CSHARP_SCRIPTING_API.md) и [04.14 report](reports/04.14-scriptbehavior-editor-authoring.md).

## Команды и сохранность изменений

Редактирование свойства через GUI и через Command API должно быть эквивалентным. GUI использует единый механизм команд согласно [архитектуре](ARCHITECTURE.md).

Требуются Undo/Redo, история изменений, обработка конфликтов и несохранённых правок. Конкретные сценарии разрешения конфликтов и предупреждения о несохранённых изменениях подлежат дальнейшему проектированию.

## Материалы

Требуются PBR-параметры: цвет, металл, шероховатость, прозрачность и эмиссия, а также замена текстур. Узловой редактор шейдеров относится к более поздним возможностям.

## Камеры

Режимы: First Person, Third Person, Isometric, Top-Down, Platformer, Strategy.

Возможности: следование, сглаживание, границы, зум и переключение. Кат-сцены относятся к более поздним возможностям.

## UI

Требуются визуальные панели, кнопки, HUD, меню, адаптивная вёрстка, темы, навигация с клавиатуры и геймпада, локализация и масштабирование.

Статус Inspector (07.2d7): числовое поле интенсивности PointLight3D и DirectionalLight3D принимает значение с клавиатуры через SDL/ImGui; smoke подтверждает изменение черновика и неизменность Scene до Apply. Это синтетическая SDL-проверка, не ввод с физической клавиатуры. Apply/Undo по клавиатуре и геймпад не подтверждены; Apply/Undo покрыты отдельным мышиным/командным smoke. См. [результат 07.2d7](reports/07.2d7-light-inspector-numeric-keyboard-edit.md) и предыдущую [оценку доступности](reports/07.2d3-inspector-accessibility-assessment.md).

## Зависимости и проверка реализации

Реализация опирается на механизм свойств, Typed Command API, Undo/Redo, модель сцен и ресурсов из архитектурных требований. Выбор конкретных библиотек остаётся предварительным согласно [TECH_STACK.md](TECH_STACK.md).

При реализации соответствующих подэтапов необходимо проверять эквивалентность GUI и команд, Undo/Redo и сохранность несохранённых правок. GUI Inspector применяет Name через `entity.set_property` Command API; интеграционные и smoke-тесты это проверяют. Полноценный редактор, визуальные эталоны и ручная UX-проверка мышью пока отсутствуют.

## Камеры (04.3)

В 04.3 реализован programmatic runtime CameraRig API для pose/follow и параметров. Это не renderer и не визуально проверенная камера. Для изображения необходима последующая интеграция с Game View/runtime renderer; требования к camera modes описаны выше.

## Hierarchy: reparent через перетаскивание (09.3l)

В Hierarchy перетащите сущность на другую, чтобы сделать её дочерней; drop на **Scene root (drop here to unparent)** отвязывает её. Ctrl+Click добавляет/убирает строки из выбора. Перетаскивание уже выбранной строки перемещает выбранные верхние корни вместе; обычный клик по выбранной строке без drag оставляет только её. Если вместе выбраны родитель и потомок, перемещается только родитель, потомок остаётся внутри него. Одна группа — одна команда Undo/Redo. Сцена помечается несохранённой. Локальные Transform сохраняются, мировая поза может измениться. Smoke ввод синтетический; ручная проверка мышью отдельно не проводилась. См. [09.3l](reports/09.3l-hierarchy-drag-reparent.md) и [09.3n](reports/09.3n-group-reparent.md).

### Массовый Inspector — Transform (09.3p)

Выберите несколько объектов в Hierarchy: Inspector покажет общий блок **Transform (Local)** и укажет число объектов. Если поле различается, оно помечено как **Mixed values**; введите новое число и нажмите **Apply to selected**. Меняется только это поле у всех выбранных объектов; остальные локальные координаты, вращение и масштаб сохраняются отдельно для каждого. **Reload selection** отменяет ещё не применённый черновик. Если Scene или Transform изменили другим действием, применение заблокировано до обновления черновика; при смене выбора незаписанный черновик отбрасывается с сообщением. Одно применение — одно действие Undo/Redo. Значения локальные относительно разных родителей, поэтому одинаковое локальное число не гарантирует одинаковой мировой позиции. Остальные редакторы компонентов подписаны как применимые только к основному объекту. Массовые компоненты, материалы и скрипты пока не редактируются. Автоматический smoke проверяет SDL-ввод и фиксацию Enter, но ручной ввод физической клавиатурой не проверялся. См. [09.3q](reports/09.3q-multi-transform-keyboard-stale-draft.md).

### Сброс группового Transform draft при смене выделения (09.3r)

Если во время группового редактирования Transform изменить набор сущностей в Hierarchy, незаписанный draft сбрасывается и Inspector показывает предупреждение. Новое выделение получает свежие значения; старые правки к нему автоматически не применяются. Это поведение покрыто Editor smoke; подробности — в [отчёте 09.3r](reports/09.3r-multi-transform-selection-draft-discard.md).
