# Игровые системы и расширения

Статус: требования пользователя из раздела 07. Все перечисленные функции добавляются только после проверенной основы. Реализация отсутствует; перечень не задаёт очередность работ и не означает готовность функций.

## Рендер

2D: спрайты, слои, батчинг. 3D: mesh, материалы, тени, освещение, постобработка, instancing, LOD, VFX/частицы и профили качества.

## Физика

2D/3D коллизии, rigid bodies, триггеры, joints, raycasts; настраиваемые физические материалы и фиксированный timestep.

## Транспорт

Колёса, подвеска, руление, торможение, коробка, двигатель, повреждения, сцепка/прицеп и камеры. Не создавать отдельный core для машин: транспорт строится в общей архитектуре компонентов и модулей.

## Вода

Плоскости и объёмы, отражения и преломления по бюджету платформы, плавучесть, эффекты и параметры качества.

## Ландшафты

Terrain heightmaps, текстурирование, растительность, дороги, редактор кистей и коллизии.

## Большие миры

Разбиение на ячейки, стриминг, асинхронная загрузка, LOD, culling, memory budgets, instancing и ссылки между частями мира.

## Анимация

Клипы, состояния, blend trees, скелетная и покадровая анимация, Timeline, события анимации и кат-сцены. Кат-сцены остаются более поздней возможностью согласно [EDITOR_UX.md](EDITOR_UX.md).

## Звук

2D/3D звук, музыка, микшеры, категории, затухание и триггеры.

## NPC / AI

Navigation mesh/pathfinding, состояния поведения, восприятие, простые деревья поведения, спавн и сохранение состояния по выбору. Выбор сохраняемого состояния подчиняется правилам [SAVE_SYSTEM.md](SAVE_SYSTEM.md).

## Игровая логика

События, условия, таймеры, переменные, визуальные узлы, обратная связь об ошибках, reusable graphs и интеграция с компонентами.

## Smart Object Builder

Сборка объектов из компонентов, шаблоны взаимодействий, генерация и настройка через команды.

## Профилирование

CPU/GPU кадр, память, draw calls, загрузка ресурсов, сигналы превышения бюджетов и автоматические предложения оптимизации. Предложения не означают автоматического применения изменений.

## Условия реализации

- Основой служат контракты из [ARCHITECTURE.md](ARCHITECTURE.md), включая модульность, единый Command API и стабильные ID.
- Необязательные подсистемы включаются только при необходимости согласно P02; библиотеки и версии не выбираются этим документом.
- Реализация каждого расширения начинается только в явно назначенном подэтапе после проверки необходимой ему основы. Конкретные критерии готовности основы ещё предстоит определить.
- Для подэтапа определяются зависимости, критерии приёмки, подходящие unit/integration/smoke-тесты и проверка регрессии. Для функций с бюджетами производительности нужны измерения на обозначенных целевых платформах; значения бюджетов пока не утверждены.
- Исходные игровые ресурсы сохраняются неизменными при генерации производных данных и оптимизаций.

Риски будущей реализации: взаимозависимость подсистем, ограничения платформ, расход памяти и времени кадра, сохранность ссылок при стриминге. Их оценка относится к соответствующим техническим подэтапам; работоспособность и производительность пока не подтверждены.
