# Предлагаемая структура репозитория

Статус: предварительное предложение пользователя из раздела 12. Это целевая структура, а не перечень уже существующих файлов. Codex может предложить изменения с обоснованием; изменения фиксируются в журнале решений.

## Предложение пользователя

Пути указаны относительно корня репозитория; начальный `/` не обозначает корень диска Windows.

```text
/CMakeLists.txt
/CMakePresets.json
/README.md
/LICENSE                         (после выбора лицензии)
/docs/ARCHITECTURE.md
/docs/ROADMAP.md
/docs/STATUS.md
/docs/DECISIONS.md
/docs/TESTING.md
/docs/COMMAND_API.md
/docs/FILE_FORMATS.md
/docs/SAVE_SYSTEM.md
/docs/BUILD_GUIDE.md
/engine/core/
/engine/commands/
/engine/scene/
/engine/assets/
/engine/prefabs/
/engine/runtime/
/engine/modules/
/editor/
/tools/
/tests/unit/
/tests/integration/
/tests/smoke/
/samples/
/templates/
/third_party/                    (только по согласованной политике зависимостей)
/scripts/
```

## Согласование с ранее заданными требованиями

Дополнительно сохранить docs/TEMPLATE_GUIDE.md в целевом комплекте: он требуется в [TESTING.md](TESTING.md), хотя не перечислен в разделе 12. Существующие документы требований и .gitignore также сохраняются; предложенный список не является указанием удалить остальные файлы.

Разделение каталогов соответствует слоям из [ARCHITECTURE.md](ARCHITECTURE.md), но само по себе не определяет CMake targets, публичные заголовки и зависимости между библиотеками. Эти детали уточняются при реализации.

## Условия создания

- Структура реализуется в назначенных подэтапах [ROADMAP.md](ROADMAP.md), начиная с 00.1. Документирование списка не означает начала или завершения 00.1.
- LICENSE создаётся после выбора лицензии; лицензия проекта пока не выбрана.
- third_party используется только по согласованной политике зависимостей; политика пока не согласована. Этот список не разрешает загрузку или включение библиотек.
- Шаблоны в templates создаются только после готовности необходимых подсистем; пустые каталоги не подтверждают наличие функций или тестов.
- Обоснованные изменения структуры должны сохранять модульность и разделение Editor, Runtime и Build/Export.
