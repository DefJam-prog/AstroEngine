# Статус проекта

## 07.1i — профиль полного кадра 3D Scene View (Windows Release)

`astro_editor.exe --benchmark-3d` запускает временный проект с локальной glTF fixture и четырьмя сценами: 1/100/500/1000 видимых MeshRenderer. После 24 прогревочных кадров измеряются 48 кадров: CPU подготовки и отправки 3D геометрии, всей Scene 3D CPU-фазы, полного времени кадра редактора, CPU до `bgfx::frame`, вызова `bgfx::frame`, BGFX full-frame GPU timer, построения сцены/импорта, памяти процесса и размера EXE. В трёх Windows D3D11 Release прогонах 1000 мешей занимали 1,42–1,60 ms CPU p50; полный кадр редактора — 16,65–16,68 ms p50, около 60 FPS из-за VSync. Это baseline на одной машине, без утверждённых бюджетов. Полная Release-сборка актуальна; полный CTest **51/51 за 15,60 с**. CTest добавил профильный smoke с проверкой всех сценариев и метрик. BGFX GPU timer охватывает полный кадр окна с VSync, поэтому не отделяет GPU время 3D-прохода. См. [отчёт 07.1i](reports/07.1i-editor-3d-frame-profile.md), [проверки](TESTING.md#071i-editor-3d-frame-profile), [D132](DECISIONS.md#d132--editor-3d-frame-profile-scope-071i).

## 07.1h — визуальный smoke и диагностика нескольких мешей

Изолированный Editor smoke теперь строит сцену с двумя валидными MeshRenderer и одним незарегистрированным AssetId. Проверяется, что валидные meshes продолжают отправляться в отрисовку, missing reference даёт диагностику, а Frame All объединяет валидные bounds и центрирует их по `x=4`. Smoke снимает BGFX swapchain и анализирует нормализованный crop Scene View; на Windows D3D11 в этом запуске найдено **11 900** ярких пикселей мешей. Это coarse threshold smoke, не committed golden и не гарантия одинаковой метрики на других backend/драйверах. Focused CTest **5/5 за 4,85 с**, полный Release CTest **50/50 за 9,47 с**. См. [отчёт 07.1h](reports/07.1h-editor-scene-visual-smoke.md), [проверки](TESTING.md#071h-scene-view-visual-smoke-and-mesh-diagnostics) и [D131](DECISIONS.md#d131--scene-view-visual-smoke-and-mesh-diagnostics-071h).

## 07.1g — камера и кадрирование 3D Scene View (Windows prototype)

Опциональная 3D-Scene View теперь поддерживает вращение правой кнопкой мыши, панорамирование средней кнопкой, масштабирование колёсиком и кнопку **Frame All**. Кадрирование объединяет bounds видимых мешей после преобразования всех восьми углов локального AABB через world transform с иерархией; некорректные, не конечные и выходящие за установленный диапазон bounds пропускаются с диагностикой. Ввод ограничен областью изображения viewport. Камера выделена в backend/GUI-независимый editor-модуль, покрытый unit-тестом. Windows x64 Release сборка успешна; focused проверки **5/5 за 5,02 с**, полный CTest **50/50 за 9,82 с**. Прямой smoke: 139 3D submissions, child origin `(2.75,0,0)`, `frameAll=1`, дистанция камеры `5.36656`. Сборка содержит три существующих предупреждения MSVC C4189 в C# metadata smoke locals. Нет pixel-golden проверки, Game View/runtime 3D, материалов/света/picking и подтверждения на других платформах. См. [отчёт 07.1g](reports/07.1g-editor-scene-camera.md), [руководство 3D](3D_RENDERING.md#editor-scene-view-mesh-preview-071f), [проверки](TESTING.md#071g-scene-view-camera-and-framing) и [D130](DECISIONS.md#d130--scene-view-camera-and-frame-all-071g).

## 07.1f — 3D MeshRenderer в Editor Scene View (Windows prototype)

Опциональная сборка Editor с `astro_gltf` теперь рисует видимые `MeshRenderer` в отдельном BGFX 3D-проходе внутри Scene View. 2D-содержимое сцены сохраняется, Game View не изменён. Отдельный depth attachment, GPU-буферы с повторным использованием, очистка при удалении/смене ссылки и изменении размера, ручная кнопка Reload; position/rotation/scale компонуются по иерархии. Editor smoke импортирует изолированный glTF fixture, проверяет draw submission и вычисленную world-позицию дочерней сущности. Итоги Release: importer-on CTest **49/49 за 9,90 с**, focused Editor/BGFX smoke **3/3**; importer-off Editor build и focused smoke/localization **2/2**. Это базовый Scene preview на Windows D3D11, не Game View/runtime и не production renderer: одна фиксированная камера, позиции/color-only геометрия, лимит 65,536 vertices/196,608 indices; normals/materials/lighting, bounds framing, picking и автоматическое обнаружение изменения файла не реализованы. См. [07.1f report](reports/07.1f-editor-scene-mesh-preview.md), [3D rendering](3D_RENDERING.md#editor-scene-view-mesh-preview-071f), [D129](DECISIONS.md#d129--editor-scene-view-mesh-preview-071f).

## 07.1e — Standalone Scene Mesh BGFX preview (implemented prototype)

Optional Windows D3D11 smoke now consumes an actual serialized Scene v6 `MeshRenderer`: its project fixture is copied to a unique temporary directory; the model is imported/registered/resolved; the selected geometry is uploaded and drawn by BGFX; readback validates visible pixel area/bounds and the selected AssetId/indices. Final Windows Release CTest passed **45/45 in 6.10 s**, including the new Scene BGFX visual smoke; focused graphics smoke passed **2/2**, and importer-off procedural smoke passed **1/1**. The default headless build remains free of 3D/BGFX targets. This does not connect Editor Scene/Game View or gameplay runtime and does not apply Scene transforms. See [07.1e report](reports/07.1e-scene-bgfx-preview.md), [sample guide](../samples/3d_prototype/README.md), and [D128](DECISIONS.md#d128--standalone-scene-mesh-bgfx-preview-071e).

## 07.1d — Scene MeshRenderer resolution (implemented prototype)

Optional `astro_gltf` now resolves a Scene `MeshRendererComponent` into the selected backend-neutral `MeshData`. It validates component schema/AssetId, resolves the registered source, imports current model inputs, compares the importer content digest (including external buffers), and checks mesh/primitive bounds. Changed input is rejected until explicit import/register updates the stable AssetId record. This provides geometry data but does not issue draw calls or connect Scene/Game View. Windows x64 Release clean build passed 159/159 actions; final focused integration passed 1/1 and full CTest passed 42/42 in 2.51 s. Headless reconfigure/build passed and contains no 3D/import targets. Tests and limits: [07.1d report](reports/07.1d-scene-mesh-resolution.md), [D127](DECISIONS.md#d127--scene-meshrenderer-resolution-071d).

## 07.1c — Scene model asset references (implemented prototype)

Scene v6 now stores an opt-in `MeshRenderer` component with model AssetId, mesh/primitive indices and visibility; the typed `entity.set_mesh_renderer` command supports transactional validation and undo/redo. Asset index v3 adds bounded `.gltf/.glb` records with main-source size/hash and importer content digest. `GltfImporter::importAndRegister` links successful static geometry imports to stable registry IDs. Scene v1–v5 and asset index v1–v2 remain readable. A fresh Windows x64 Release build passed 158/158 actions; focused tests 5/5, final full CTest 42/42 in 7.94 s; fresh default headless Release build with importer/tests disabled passed 32/32 actions. This does not draw models in Scene/Game View; prefab capture refuses MeshRenderer instead of silently losing it. External-buffer dependencies are not stored individually and are rechecked by explicit reimport. See [07.1c report](reports/07.1c-scene-model-asset-reference.md), [file formats](FILE_FORMATS.md), and [D126](DECISIONS.md#d126--scene-model-asset-references-071c).

## 07.1a — 3D camera/mesh prototype (implemented, not Scene-integrated)

`astro_runtime_render3d` supplies validated right-handed camera matrices and bounded indexed mesh data with a colored cube. Optional Windows x64 D3D11/bgfx smoke performs backbuffer readback and checks broad pixel thresholds: three runs each found 85,155 foreground pixels, 169 color buckets, bounds (280,135)–(658,498). Across those runs the VSync CPU frame-interval median p50 was 16.735 ms (range 16.701–16.764 ms), and median p95 was 32.824 ms (range 32.055–34.120 ms), for this single-cube test only. Windows Release build completed 161/161 actions; full CTest passed 46/46 in 13.94 s. This is not a golden-image check, representative performance workload or target budget. The module is not connected to Scene, asset serialization or Editor views. See [guide](3D_RENDERING.md), [07.1a report](reports/07.1a-3d-camera-mesh-prototype.md), and [D123](DECISIONS.md#d123--3d-camera-mesh-prototype-boundary-071a).

## 07.1b — bounded glTF/GLB static mesh import (implemented prototype)

The opt-in `astro_gltf` module uses pinned fastgltf v1.0.1, simdjson 5.1.0 and simdutf 9.3.3 from the ignored local `build/07.1b-deps` cache; configure verifies the parser commit and helper-source SHA-256 values, and explicitly disables fastgltf downloads. `GltfImporter::importFile` accepts project-relative `.gltf`/`.glb` files under `Assets/`, imports static triangle POSITION data and optional indices, and writes a checksummed geometry cache under `Library/Derived/gltf`. Inputs and decoded counts are bounded; external buffers must be plain relative paths inside Assets; source files are read-only. Windows x64 Release build completed 95/95 actions and full CTest passed 42/42 in 8.92 s. The separate default headless Release configure/build also passed with importer OFF and no `astro_gltf` target. This is not a production asset pipeline or 3D Scene feature: no normals, UVs, materials, nodes/transforms, animation, image loading, Scene references or Editor integration. Path checks are not race-safe against a hostile process concurrently replacing filesystem entries; fuzz/sanitizer testing and non-Windows builds remain outstanding. Details: [07.1b report](reports/07.1b-bounded-gltf-importer.md), [D125](DECISIONS.md#d125--optional-bounded-gltf-static-mesh-importer-071b).

## 06.57 — оценка macOS/POSIX durability

Завершена документационная оценка без изменений runtime/API. Apple документирует требуемые descriptor-relative вызовы и флаги; `flock` остаётся advisory, same-directory `linkat` — no-replace публикацией только в пределах одной файловой системы. Обычный `fsync` не подтверждает power-loss durability, а поведение `fsync` каталога на целевой macOS/APFS не проверялось. Windows Release полный CTest: 44/44 (14,36 с); WSL Ubuntu Release полный CTest: 39/39 (1,07 с). Windows Release Editor build: 154/154 Ninja actions, без ошибок, с тремя прежними C4189 warnings. macOS не собирался и не тестировался. Детали и дальнейшие критерии: [отчёт 06.57](reports/06.57-posix-macos-portability-assessment.md), [D120](DECISIONS.md#d120--macos-posix-copy-aside-portability-assessment-0657).

## 06.58 — переносимость C++ unit-тестов после прогона на Mac

В двух тестах C# Editor заменено неявное преобразование platform-specific `file_time_type::duration::rep` на явный `long long` перед `std::to_string`. Это устраняет зависимость выбора перегрузки от типа счётчика часов на разных стандартных библиотеках; production API и runtime не затронуты. По сообщению пользователя, первоначальная Mac-сборка остановилась на этих двух ошибках, а 39 CTest ошибок были каскадными из-за отсутствующих исполняемых файлов/headless binary. После исправления Windows Release build завершился успешно; focused CTest 2/2 и full CTest 44/44 (13,33 с). WSL Ubuntu Release build завершился успешно; focused 2/2, full 39/39 (3,92 с). Пересборка и повторный CTest на Mac ещё ожидаются, поэтому устранение Apple Clang/libc++ ошибки пока не подтверждено непосредственно на Mac. См. [отчёт 06.58](reports/06.58-macos-test-portability-fix.md), [D121](DECISIONS.md#d121--explicit-time-count-conversion-in-cross-platform-tests-0658).

## Зафиксированная цель продукта

AstroEngine — будущий универсальный модульный 2D/3D-движок и редактор, ориентированный на создание игр с ИИ через общий typed Command API. AI-assisted authoring — ключевая продуктовая возможность; AI adapter/provider остаётся необязательным для запуска движка и игр. Puzzle — текущий проверочный пример, не ограничение жанров. Это целевое направление, не текущая функциональная готовность. См. [PRODUCT_REQUIREMENTS.md](PRODUCT_REQUIREMENTS.md) и решение [D067](DECISIONS.md#d067-универсальный-ai-first-профиль-продукта).

## Профилирование и оптимизация плотных Scene/Game сцен (06.12)
Профиль 10k Debug показал ~136 ms на композицию Scene sprite list из ~142 ms на вид. Причина — `Scene::transform(id)` выполнял линейный поиск сущности для каждого спрайта (квадратичный полный проход), плюс повторный линейный поиск родителей. `appendSceneSprites` теперь один раз строит индекс EntityId, получает мировые affine-матрицы за кэшируемый проход по иерархии и повторно использует их для дочерних спрайтов; нулевой Z-поворот использует точную ветвь без sin/cos, осевые длины не вызывают hypot при нулевом коэффициенте. Публичный Scene API и результат affine-преобразований сохранены. CTest Debug **37/37**. Один и тот же инструментированный Debug тест на 10k: Scene/Game CPU p50 **142.218/141.326 ms → 26.086/24.348 ms** (≈81.7%/82.8% меньше). Полная Editor Release-сборка теперь успешна после сборки локальных bgfx Release зависимостей; Editor smoke прошёл напрямую. Финальный Release 10k CPU p50/p95: Scene **4.913/7.184 ms**, Game **4.682/7.240 ms**; сумма p50 двух окон ~9.596 ms без UI composition/vsync. Release CTest не запускался (`BUILD_TESTING=OFF`). См.
