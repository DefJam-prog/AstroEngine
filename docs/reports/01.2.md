# Отчёт подэтапа 01.2

Дата: 2026-11-13. Объём: ModuleRegistry, lifecycle, разрешение зависимостей и ошибки. Следующий подэтап не начат.

## Исходное состояние

Git: ветка `main`, последний коммит `fc16987 Checkpoint before 00.3: requirements and build foundation`. Рабочее дерево уже содержало незакоммиченные изменения 00.3/01.1; они сохранены и не перезаписывались. До изменений сборка `build/stack-spike` прошла (`ninja: no work to do`), CTest — 5/5 passed: три headless smoke, `core.unit`, `stack_spike.smoke`.

Проверенная среда: Visual Studio 2022 Build Tools 17.14.45 Developer Command Prompt x64, MSVC 19.44, CMake 3.31.6, Ninja 1.12.1, Windows SDK 10.0.26100.0. В обычном PowerShell CTest не доступен в PATH; команды сборки/тестирования запускались через `VsDevCmd.bat`.

## Изменения

- `engine/core/include/astro/core/IEngineModule.hpp`: контракт имени, зависимостей, initialize и shutdown с общим `EngineContext`.
- `engine/core/include/astro/core/ModuleRegistry.hpp`, `engine/core/src/ModuleRegistry.cpp`: владение модулями через `unique_ptr`, проверка графа до запуска, детерминированный топологический порядок, rollback уже инициализированных модулей, обратное завершение и сбор ошибок shutdown. Повторный запуск и изменение состава после успешного старта запрещены.
- `engine/core/include/astro/core/Result.hpp`: добавлены коды `DependencyError` и `InvalidState`.
- `engine/core/CMakeLists.txt`, `tests/unit/core/CoreTests.cpp`: подключена реализация и unit-проверки валидного порядка, недостающей/циклической/дублирующей зависимости, запрета повторного lifecycle, rollback и обработки ошибок shutdown.
- Обновлены README, ARCHITECTURE, ROADMAP, STATUS, DECISIONS и TESTING; добавлен этот отчёт.

Модуль, чья инициализация вернула ошибку, обязан самостоятельно освободить частично созданные им ресурсы: реестр вызывает rollback для модулей, которые до этого успешно завершили initialize. API `tick` не добавлялся, поскольку он входит в 01.3.

## Проверки

Перед изменениями: build exit 0; CTest **5/5 passed**.

После изменений выполнены последовательно в Visual Studio Developer Command Prompt x64:

```powershell
cmake --build build/stack-spike --parallel 4
ctest --test-dir build/stack-spike --output-on-failure --no-tests=error
```

Сборка — exit 0. CTest — **5/5 passed**: `headless.startup`, `headless.help`, `headless.invalid`, `core.unit`, `stack_spike.smoke`; время последнего запуска 2.16 s. `core.unit` включает новые случаи ModuleRegistry. CTest также повторно проверил ранее существующие headless и графический smoke сценарии.

Integration-тесты команд/сериализации пока неприменимы: эти подсистемы ещё не созданы. Отдельного smoke приложения модулей нет; lifecycle проверяется unit-тестом. Визуальное ручное тестирование spike в этом подэтапе не проводилось.

## Известные ограничения

- Реестр одноразовый после успешного старта; динамическая регистрация и потокобезопасность не поддерживаются.
- Имя и зависимости модулей должны быть стабильными и детерминированными между вызовами.
- Неуспешный initialize должен сам очистить собственные частичные побочные эффекты.
- `tick`, EventBus и TimeService остаются вне объёма.
- Лицензия проекта не выбрана; сторонние зависимости подэтапом не добавлялись.

Рекомендуемый следующий подэтап: **01.3 — EventBus, TimeService и fixed timestep**, только после ручного подтверждения пользователя.
