# Отчёт подэтапа 01.4

Дата: 2026-11-13. Объём: CommandRegistry, typed schema, validation, execute/result/errors и локальный audit. Следующий подэтап не начат.

## Исходное состояние

Git: ветка `main`, последний коммит `fc16987 Checkpoint before 00.3: requirements and build foundation`. Рабочее дерево до правок содержало незакоммиченные результаты 00.3 и 01.1–01.3; они сохранены. Baseline `cmake --build build/stack-spike --parallel 4` завершился без пересборки; CTest — 5/5 passed.

Проверенная среда: Visual Studio 2022 Build Tools 17.14.45 Developer Command Prompt x64, MSVC 19.44.35230, CMake 3.31.6, Ninja 1.12.1, Windows SDK 10.0.26100.0. Обычный PowerShell не имеет CTest в PATH.

## Изменения

- `engine/core/include/astro/core/CommandRegistry.hpp`, `engine/core/src/CommandRegistry.cpp`: registry, версия и проверка dotted ID, типизированная регистрация payload/output, обязательный validator, executor, validation-only `validate`, типизированный `execute`, Error diagnostics и audit entries.
- `engine/core/include/astro/core/Result.hpp`: добавлены ErrorCode `ValidationError`, `VersionMismatch`, `TypeMismatch`; существующие значения enum сохранены.
- `engine/core/CMakeLists.txt`, `tests/unit/core/CoreTests.cpp`: подключена реализация и тесты успешной/отклонённой валидации, отсутствующего ID, неверной версии и типов, duplicate/invalid ID, value/void results, ошибок и исключений callbacks, audit.
- Создан пользовательский документ [COMMAND_API.md](../COMMAND_API.md); обновлены README, ARCHITECTURE, ROADMAP, STATUS, DECISIONS, TESTING, BUILD_GUIDE; добавлен этот отчёт.

Это локальный ранний C++ контракт: schema включает ID/version и точные типы C++ payload/result, а валидатор содержит реальные проверки предусловий. `validate` не вызывает executor, но не резервирует состояние; `execute` всегда валидирует повторно. Registry не может откатить побочные эффекты executor при последующем отказе. Транзакции и Undo/Redo оставлены 01.5.

## Проверки

До изменений: build exit 0 без пересборки; CTest **5/5 passed**.

После изменений выполнены из Visual Studio Developer Command Prompt x64:

```powershell
cmake --build build/stack-spike --parallel 4
ctest --test-dir build/stack-spike --output-on-failure --no-tests=error
```

Сборка завершилась с кодом 0; журнал `build/01.4-build.log` не содержит compiler warning/error. CTest — **5/5 passed**: `headless.startup`, `headless.help`, `headless.invalid`, `core.unit`, `stack_spike.smoke`; время 2.32 s. Unit-тесты проверяют новый CommandRegistry; headless и графический smoke/regression прошли.

Во время проверки после изменения ErrorCode один инкрементальный запуск повторно использовал старый объект `CommandRegistry.cpp`; это проявилось как расхождение числовых enum-кодов в тестах. Для итогового запуска принудительно обновлена временная метка исходника, объект перекомпилирован, затем CTest прошёл 5/5. Итоговый исходный текст проверен; отдельную полностью чистую пересборку графического spike в новом каталоге в этом подэтапе не выполнял.

Integration проверок команд Scene Model пока нет: модели сцен и production-команды ещё не реализованы. Вызов CommandRegistry тестируется напрямую unit-тестами. Отдельный smoke runtime/editor пока неприменим.

## Известные ограничения

- Schema пока не сериализуется и доступна только внутри процесса; формат JSON/межпроцессный API не создан.
- Одновременная регистрация нескольких версий одного ID не поддерживается; миграции payload отсутствуют.
- Validation-only не формирует diff и не гарантирует, что предусловия останутся истинными к execute; validator должен быть без побочных эффектов.
- Audit trail хранится в памяти без лимита/сохранения и не включает payload.
- Registry не потокобезопасен. Output должен быть copy-constructible или `void`.
- Нет разрешений AI, транзакций, inverse/rollback и Undo/Redo.

Рекомендуемый следующий подэтап: **01.5 — транзакции, Undo/Redo и тесты необратимых действий**, только после ручного подтверждения пользователя.
