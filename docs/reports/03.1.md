Каждая сущность теперь создаётся с одним `astro.Transform` версии 1 и отдельным стабильным в пределах сцены `ComponentId`. Transform хранит position, Euler rotation в градусах и scale, все значения ограничены конечными числами. C++ API: `Scene::transform(entityId)`, `Scene::findTransform(componentId)`, `Scene::setTransform(entityId, value)`. Component ID глобально уникальны в пределах сцены, монотонны, сохранённые ID восстанавливаются; ID удалённого компонента не переиспользуется текущим экземпляром сцены.

Astro Scene v2 сохраняет Transform и его ID. Загрузчик принимает v1 и выполняет миграцию: добавляет Transform по порядку сущностей с нулевыми position/rotation и единичным scale. Следующее сохранение записывает v2; исходный v1 файл при открытии не изменяется.

## Что работает

- Каждая новая Entity содержит один Transform с default position/rotation (0,0,0), scale (1,1,1).
- Transform можно прочитать и изменить через API Scene; NaN и бесконечность отклоняются.
- Entity ID и Component ID сериализуются; компонентный ID доступен поиском в сцене.
- Astro Scene v1 мигрирует к Transform по умолчанию; v2 сохраняет компоненты и значения.
- Неизвестный тип компонента или неподдерживаемая версия компонента дают ошибку, данные не пропускаются молча.

## Ограничения и известные проблемы

- В модели реализован только Transform; универсальная регистрация/схема компонентов и остальные типы отсутствуют.
- Transform является локальными данными. Композиция родительских матриц, координатные пространства, gizmos, редактирование Transform в Inspector и spatial rendering не реализованы.
- Transform edits пока не проходят через Command API, не имеют Undo/Redo и не помечают сцену dirty из Inspector, поскольку Inspector Transform ещё не добавлен.
- Для v1 Component ID отсутствовали, поэтому миграция выдаёт новые ID в порядке ENTITY-записей; последующие сохранения v2 их стабилизируют.
- Публичная структура `Entity` расширена полем components; внешний ABI ещё не объявлен стабильным, но существующий API Scene для создания/удаления/parenting сохранён.
- В одном раннем полном CTest после изменения публичной модели два тестовых процесса дали access violation. После пересборки затронутых целей это не воспроизвелось в двух следующих полных прогонах (оба 9/9); точная причина раннего падения не установлена, поэтому риск отмечен.
- Проверена только Windows x64/MSVC; чистая сборка без build-кэша, другие ОС и графические эталонные снимки не проверялись.
