# Отчёт подэтапа 03.3 — SpriteRenderer и отображение изображений

## Реализовано

- Типизированный `SpriteRendererComponent`: стабильный scene-local ComponentId, обязательный AssetId и флаг видимости. У сущности сохраняется не более одного такого компонента.
- `entity.set_sprite_renderer` v1 с валидацией ссылки по ненулевому AssetId и транзакционным Undo/Redo; Inspector использует команду.
- Формат Astro Scene v3 сериализует SpriteRenderer. Загрузчик сохраняет чтение v1 (default Transform) и v2 (существующий Transform); миграция становится файлом v3 только при явном сохранении.
- Windows Editor импортирует PNG/JPEG в project-local AssetRegistry, использует системный WIC для декодирования кэшированной копии и BGFX для показа preview выбранного компонента. Есть ограничения preview 16384 px на сторону / 64 млн пикселей.
- Diagnostics показывает отсутствующие исходные файлы по AssetId; Inspector сообщает о ссылке на AssetId, которого нет в текущем registry. Изменённый source требует предусмотренного 03.2 явного reimport.
- Editor smoke генерирует собственный маленький PNG в уникальном временном проекте, проверяет import, WIC decode/BGFX upload, назначение SpriteRenderer и round-trip сцены; исходники проекта не затрагиваются.

## Известные ограничения

- Preview живёт в Inspector и не является пространственным Scene View renderer или рендером runtime-игры. Пока нет камеры, сортировки/слоёв, геометрии, tint, UV, атласа, анимации или draw batching.
- Декодирование реализовано только в Windows Editor через WIC. Межплатформенный decoder adapter/API ещё не определён. Размерные ограничения снижают риск больших аллокаций, но не заменяют проверку/изоляцию недоверенных файлов.
- Importer metadata checks сами не декодируют сжатые потоки; WIC отклоняет изображения, которые не может декодировать. Не выполнялась визуальная эталонная pixel-diff проверка.
- Видимость хранится, но preview пока не использует её для изменения рендера компонента.
- Не реализованы reimport UI, asset browser, watcher, cleanup cache, общий multi-component container и автоматические миграции пользовательских схем.
