# Отчёт подэтапа 03.4 — Nested prefabs и обновление экземпляров

## Реализовано

- Новая библиотека `astro_prefabs` без внешних зависимостей. Она хранит `<project>/Prefabs/<PrefabId>.astro-prefab` (ASTRO_PREFAB v1) и умеет атомарно сохранять/загружать файл.
- Prefab содержит ровно один корневой узел, уникальные локальные ID, дерево, Transform, необязательный SpriteRenderer/AssetId и optional PrefabId для nested prefab. Есть `capturePrefab` для копирования поддерева Scene.
- `instantiatePrefab` раскрывает nested assets в Scene, закрепляет source keys и EntityId, проверяет отсутствующие файлы, циклы, лимит 64 уровней вложенности и 100000 результирующих сущностей до изменения исходной Scene.
- Overrides явно задаются для Name, Transform и SpriteRenderer. Обновление применяет новые значения asset к экземпляру, сохраняет прежние EntityId при совпадающих source keys и затем повторно применяет локальные overrides.
- Если новая версия удаляет source key с локальным override либо устаревший prefab node имеет сторонние дочерние сущности, обновление отклоняется на копии и оставляет текущую Scene без изменений.
- Добавлены транзакционные команды `prefab.instantiate`, `prefab.set_override` и `prefab.update_instance`.
- Scene v4 сериализует identity/mapping/overrides экземпляров; загрузка v1/v2/v3 сохранена, миграция происходит только при явном сохранении.

## Использование C++ API

```cpp
auto libraryResult = astro::prefabs::PrefabLibrary::open(projectRoot);
if (!libraryResult) { report(libraryResult.error().message); return; }
auto library = libraryResult.value();

auto asset = astro::prefabs::capturePrefab(scene, selectedRoot, 42, "Wooden Crate");
if (!asset || !library.save(asset.value())) { report("Prefab could not be saved"); return; }

auto instanceRoot = astro::prefabs::instantiatePrefab(library, scene, 42);
if (!instanceRoot) { report(instanceRoot.error().message); return; }
```

Для изменений через Command API вызовите `registerPrefabCommands(commands, library, scene)`. Source keys находятся в `scene.prefabInstance(root)->sourceToEntity`; пользовательский override применяется через `prefab.set_override` или `setPrefabOverride`. После изменения prefab asset вызовите `prefab.update_instance`/`updatePrefabInstance`.

## Ограничения

- UI для capture/edit/instantiate/update prefab в редактор не добавлен; проверены C++ API и typed commands.
- Только формат prefab v1; автоматические миграции самого prefab asset, variants, granular merge изменений asset и instance, истории изменений и shared overrides отсутствуют.
- Undo/Redo хранит полные снимки Scene и может заметно расходовать память на больших проектах.
- В Scene override хранит значение компонента, а не произвольную property schema. Все разрешённые типы перечислены явно.
- Prefab authoring API не переписывает исходные игровые файлы; тесты удаляют только собственный уникальный временный каталог.
