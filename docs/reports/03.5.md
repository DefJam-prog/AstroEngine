# Отчёт подэтапа 03.5 — граф ресурсов и платформенные производные

## Объём

Реализован только первый безопасный слой пайплайна: явный граф AssetId и deterministic package reachable images с target tag. Автоматическое извлечение зависимостей Scene/Prefab, image transcoding, оптимизация, runtime package loader и платформенные export toolchains не входят.

## Изменённые файлы

- `engine/assets/include/astro/assets/AssetRegistry.hpp` — read-only доступ к project root для project-local build output.
- `engine/assets/include/astro/assets/AssetBuild.hpp`, `engine/assets/src/AssetBuild.cpp` — dependency graph, versioned persistence, cycle/ID checks, closure, package generation and validation.
- `engine/assets/CMakeLists.txt` — подключён build source.
- `tests/integration/assets/AssetRegistryTests.cpp` — graph serialization/closure/cycle, selected closure package, cache reuse, damaged artifact repair, target tag distinction.
- `docs/ASSET_PIPELINE.md`, `docs/FILE_FORMATS.md`, `docs/ARCHITECTURE.md`, `docs/ROADMAP.md`, `docs/STATUS.md`, `docs/DECISIONS.md`, `docs/TESTING.md`, `README.md` — контракт и ограничения.
- `build/03.5-build.log`, `build/03.5-ctest.log` — фактические логи (build/ игнорируется Git).

## Что работает

- Явный `AssetDependencyGraph` сериализуется как `ASTRO_DEPENDENCIES 1`; выход closure сортирован, нулевые ID и циклы отвергаются.
- `buildAssetPackage` принимает корневые AssetId, включает только замыкание графа, проверяет registry metadata, исходник и кэш SHA-256/размер.
- Пакет содержит platform tag и исходные PNG/JPEG bytes, content-addressed SHA-256. Идентичный файл переиспользуется; повреждённый derived artifact публикуется заново через временный файл и atomic replacement.
- Выходы находятся в `Library/Derived` и не меняют исходные пользовательские изображения.

## Ограничения и риски

- Граф не пополняется автоматически из сцен, компонентов или prefab.
- Target tags — метаданные; отсутствуют platform texture formats/codecs, аппаратная проверка, runtime loader и standalone export.
- Payload остаётся исходным PNG/JPEG; importer ранее проверяет структуру метаданных, не полностью декодируя изображение.
- Атомарность и Unicode/Windows сценарий проверялись только на Windows/MSVC; другие файловые системы не проверены.
- Сценарии concurrency и аварийного завершения при записи отдельно не тестировались.
