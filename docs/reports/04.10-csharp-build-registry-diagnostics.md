# 04.10 — C# build handoff, AssetRegistry sync, and Project diagnostics

**Status:** complete. This supplemental step stops before RuntimeSession ScriptBehavior lifecycle work.

## Delivered

- Added optional `scriptBindings` manifest entries pairing an exact compiled source path with an explicitly chosen managed type name. Validation rejects unknown fields, duplicate/missing source paths, invalid UTF-8/control characters, and paths outside the compiled `Scripts/` set.
- The C# builder now writes a bounded UTF-8 `Library/Scripts/asset-bindings.state` handoff and records its relative path and SHA-256 in `build-state.json` schema v2. Assembly/runtimeconfig outputs remain immutable generation files; source files are copied for compilation, never rewritten.
- `AssetRegistry::inspectScriptBuild()` reports `Missing`, `Current`, `Stale`, or `Invalid`, compares the manifest and full `.cs` source inventory, validates output paths/hashes, and shows bindings that need registration or have drifted. The registry checks the sidecar digest recorded in build-state and rejects symlinked project build directories/files.
- `registerScriptsFromBuild()` validates all configured bindings before writing the shared index once. Existing source paths retain their AssetId. Opening/inspecting a project does not compile or execute C#.
- The Project panel displays C# status, bindings, and diagnostics; provides Refresh and an explicit Register current C# build action; and has Russian labels. A managed type's existence is checked only by explicit `CSharpScriptHost::loadScriptAsset`.
- Added AssetRegistry and host integration coverage for the handoff. Existing Editor smoke checks that the Project C# status is drawn.

## Limits

- The manifest shape and type-name syntax are checked; the CLR is not reflected to confirm that a type exists until explicit host load.
- Registration success does not guarantee that the assembly can be loaded or that its `FixedUpdate` entry point is valid.
- Build freshness/digest checks detect accidental or one-sided tampering. They are not a signature/trust boundary against someone who can rewrite both local build state and the referenced digest.
- The host remains optional Windows x64, .NET 10 remains a prototype candidate, and C# executes in-process with current-user privileges. No sandbox, hot reload, automatic ScriptBehavior lifecycle, Code workspace, mobile hosting, or runtime packaging was added.
- Prior immutable output generations remain retained; cache pruning is not implemented.
