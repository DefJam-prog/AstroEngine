# Подэтап 04.12 — подтверждение C# перед Play

## Реализация

- Добавлен Editor-only `CSharpPlayApproval`: снимок project root, пути/ID/имени Scene, включённых `ScriptBehavior`, AssetId, исходника и SHA-256, managed type, fingerprint сборки, пути и SHA-256 assembly/runtimeconfig.
- Перед Play с включёнными скриптами Editor показывает русский/английский диалог с точным набором. `Allow` заново снимает Scene и AssetRegistry, принимает только идентичный снимок и запускает обычную изолированную RuntimeSession. `Cancel`, неверный binding, отсутствующая/устаревшая сборка и несовпадение снимка не дают grant.
- Approval живёт только в памяти. Он отзывается при Stop, новом Play, открытии/создании сцены или проекта, а также Faulted runtime.
- `ScriptBuildReport` дополнен путями и SHA-256 выходов и SHA-256 каждого выбранного исходника; формат project build-state не менялся.
- Play по-прежнему не вызывает C# host: окно сообщает, что скрипты не запустятся. `CSharpScriptHost::loadScriptAsset` остаётся trusted in-process API без sandbox и может вызываться низкоуровневым C++ кодом вне Editor gate.

## Проверки

Добавлены `editor.csharp_play_approval.unit` и расширение `assets.registry.integration`. Unit проверяет отключённые компоненты, fail-closed на отсутствующей сборке, отклонение пустого снимка, изменение исходного/выходного хеша и отзыв grant. Integration проверяет успешный снимок зарегистрированного ScriptBehavior по настоящему fixture свежей сборки и верифицированным output hashes. `editor.localization.unit` проверяет русские видимые подписи; `editor.smoke` проходит штатную графическую smoke-сцену.

## Ограничения

ImGui modal не прогоняется автоматическим кликом; smoke проверяет запуск окна редактора и перевод подписей. Положительный путь capture/approve покрыт интеграционным тестом модели, а не UI automation. Подтверждение сейчас не разрешает вызовы C# — их подключение к RuntimeSession и проверка grant непосредственно перед host load остаются следующим отдельным подэтапом. Gate защищает от случайного запуска через Editor UI, но не является границей безопасности для доверенного in-process C++ кода.
