# 04.13 — C# ScriptBehavior runtime lifecycle

Date: 2026-11-15. Scope was limited to connecting the existing persistent `ScriptBehavior` and 04.12 Editor consent flow to `RuntimeSession`; no Code workspace, new gameplay feature, or later roadmap substage was started.

## Implementation

- Added `CSharpScriptRuntime` to resolve every enabled ScriptBehavior before Play. It validates each component binding against the project AssetRegistry, groups host instances by stable AssetId, and calls the Editor's approval recheck immediately before each unique `loadScriptAsset` call.
- Added component lifecycle ABI v1. Components are invoked in Scene entity insertion order and component insertion order: `OnCreate`, then `FixedUpdate` on each RuntimeSession fixed step, then `OnDestroy` in reverse successful creation order.
- Added `RuntimeSession::playWithLifecycle` and `stopChecked`. Failed creation rolls back previously created components and discards the candidate Scene; Stop attempts all teardown callbacks, always clears runtime state, and reports the first callback error. Existing `play` and `stop()` remain available.
- Connected Editor Play/Stop/fault/shutdown paths to the manager. Plain projects without enabled scripts keep the existing Play flow. Script-enabled Play refuses when the optional host is not built, consent is absent/stale, a binding is invalid, or a callback fails.
- Added a real C# sample lifecycle that changes Transform in each callback; expanded native lifecycle and host integration tests.

## Compatibility and safety

Serialized Scene v5 schema did not change. Source compatibility changes for users of `CSharpScriptHost::loadScriptAsset`: the bound managed type must now provide static `UnmanagedCallersOnly` callbacks `OnCreate(IntPtr,int)`, `FixedUpdate(IntPtr,int)` and `OnDestroy(IntPtr,int)`. The existing generic `CSharpScriptHost::load` single-entry API remains.

C# executes in-process with Editor process privileges; consent is not sandboxing or crash containment. Managed module initializers may execute during assembly load, and unload is not guaranteed. There is no managed instance-state model, hot reload, mobile host, or production packaging/license review. Editor modal input is not click-automated.
