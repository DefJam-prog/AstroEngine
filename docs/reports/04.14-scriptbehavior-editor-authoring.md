# 04.14 — ScriptBehavior authoring in the Editor

Date: 2026-11-15. This substage adds authoring controls for existing registered C# bindings to the selected entity Inspector. It does not add a C# source editor, compiler UI, hot reload, sandbox or new serialized component schema.

## What changed

- Inspector lists ScriptBehavior components with their component ID, AssetId, managed type, source path, and missing/mismatched/stale build status.
- Project build report supplies candidates. Only currently registered entries from a current build appear in the add selector. Add re-inspects the build report, matches AssetId/type/source against AssetRegistry, resolves the script, and creates a **disabled** component.
- Enabling a component rechecks that its build and binding are still current. Disabling and removing remain available to fix a stale scene. Changes mark the Scene dirty; Ctrl+S persists the record in existing Astro Scene v5.
- Added transactional commands `script_behavior.add`, `script_behavior.set_enabled`, and `script_behavior.remove`. Their schemas are present in the `CommandRegistry`/`AIEditorApi` catalog. Add/remove Undo/Redo restore the same `ComponentId` and component-list insertion order. `restoreScriptBehavior` rejects malformed records, out-of-range insertion, and any ID colliding with Transform, SpriteRenderer or ScriptBehavior.
- Added Russian translations for the new Inspector workflow and diagnostics.

## Behavior, compatibility and limits

No Scene file migration is required; Scene v5 already stores the stable asset/type/enabled/component identity. New components begin disabled, so adding one never implicitly executes code. Existing ScriptBehavior records retain their state. A binding can remain in a Scene while stale/missing so the user can inspect or remove it; Inspector blocks enabling until the project build is current. Runtime consent and the complete Play snapshot check remain unchanged.

The shared Scene command layer validates entity, stable AssetId and managed type shape but intentionally does not own an AssetRegistry. GUI candidates and enable operations additionally validate against the current project. An AI or other direct command caller may author an unresolved reference; Inspector reports it and the existing Play approval capture fails closed. The smoke is programmatic: it checks the same command path and Scene save/open, but does not synthesize ImGui clicks or exercise the current-build dropdown against a live C# project.
