# 04.15 — C# Code workspace

**Статус:** выполнен на Windows 11 x64. Подэтап 04.16 не начинался.

## Что добавлено

- Отдельная панель Editor `View → C# Code`: список файлов `Scripts/**/*.cs`, открытие по относительному пути, создание нового файла и многострочное редактирование.
- Проверка расширения и канонического пути: корень `Scripts` и открытый файл должны оставаться в проекте; выход через `..` и symlink/reparse path за пределы проекта отклоняются.
- UTF-8 чтение/запись (при чтении принимается BOM; source записывается UTF-8 без BOM), лимит 4 MiB, атомарная запись sibling temp-файла и Windows replace.
- Dirty-state индикатор и Save/Discard/Cancel перед переключением файла; несохранённый документ блокирует переключение/закрытие проекта и выход.
- Явная сборка через существующий `tools/csharp/build-project.ps1` с SDK root из CMake. Дочерний `pwsh` работает в фоне; ошибки/предупреждения компилятора показываются с путём и строкой, переход открывает файл и ставит каретку на начало строки. Полный output помогает увидеть ошибки manifest/SDK.
- UI-строки добавлены в English/Russian каталог. Файловое редактирование доступно отдельно от игрового C# host.

## Тесты и исходные данные

`editor.csharp_code_workspace.unit` покрывает UTF-8 Cyrillic round-trip, вложенное создание, защиту от перезаписи, dirty/save/reopen, traversal/неверное расширение/invalid UTF-8, лимит 4 MiB и parsing error/warning source locations. `editor.smoke` создаёт/удаляет свой временный проект, проверяет UTF-8 save/reopen и рендер Code workspace; пользовательские проекты и sample scripts не менялись. `runtime.csharp_project_build.integration` выполняет настоящий локальный offline .NET build и compile-failure сценарий. UI smoke не симулирует клики/набор текста или нажатие кнопки сборки.

## Ограничения и следующий подэтап

Это минимальный source editor: нет syntax highlighting, IntelliSense/LSP, refactoring, debugger, hot reload, multi-tab или sandbox. Для сборки нужен валидный `.astro/csharp-build.json`, локальный `ASTRO_DOTNET_ROOT` при конфигурации Editor и `pwsh` в `PATH`; manifest-авторинга в панели нет. Diagnostic parser обрабатывает стандартную MSBuild-форму `file.cs(line,column): error|warning CODE`; нестандартный формат остаётся в полном build output. Host/runtime — экспериментальный Windows x64 prototype, C# исполняется с правами процесса; consent не sandbox. Не проверялись графические клики, фактический caret скриншотом, macOS/mobile/export.

Рекомендуемый **04.16**: безопасная форма создания/редактирования `.astro/csharp-build.json` из Editor с показом выбранных SDK/framework, manifest round-trip и error tests. Не расширять runtime capabilities в этом подэтапе.
