# Подэтап 04.16 — настройки C# сборки в Editor

Дата: 2026-11-15.

## Реализация

В C# Code workspace добавлена сворачиваемая панель настроек проекта, сохраняющаяся в `.astro/csharp-build.json`. Автор может указать pin установленного .NET SDK 10.0.x, имя сборки и source/type bindings для файлов внутри `Scripts/`. Целевая платформа в этом прототипе фиксирована на `net10.0`. Существующий offline builder читает этот же манифест, поэтому сохранённые настройки используются при следующей явной сборке.

Добавлен ограниченный строгий JSON parser без внешней зависимости. Он отклоняет неверный UTF-8/JSON, дубли и неизвестные поля, неверные типы, schema/framework вне поддержки, некорректные/повторные bindings и traversal. Запись проверяет источники в проекте и публикует результат через временный файл и безопасную замену. Если существующий файл повреждён, Editor сохраняет диагностическое состояние; перезапись требует отдельного подтверждения. Smoke создаёт и перечитывает manifest и script в изолированном временном проекте.

## Изменённые файлы

- `editor/CSharpBuildManifest.hpp`, `editor/CSharpBuildManifest.cpp` — модель, strict parser/validator, безопасное чтение и атомарная запись.
- `editor/main.cpp`, `editor/Localization.cpp` — форма Build settings и русские подписи; сохранение по явной кнопке и подтверждение замены повреждённого файла.
- `editor/CMakeLists.txt`, `tests/CMakeLists.txt`, `tests/unit/editor/CSharpBuildManifestTests.cpp` — подключение реализации и unit-проверок.
- `README.md`, `docs/EDITOR_UX.md`, `docs/CSHARP_SCRIPTING_API.md`, `docs/ROADMAP.md`, `docs/STATUS.md`, `docs/DECISIONS.md`, `docs/TESTING.md` — пользовательское описание, статус, решение D081 и критерии проверки.

## Ограничения

- Доступна только конфигурация .NET SDK 10.0.x / `net10.0`; выбора framework и проверки на других платформах нет. .NET 10 остаётся экспериментальным решением проекта, не утверждённым для production.
- UI smoke вызывает операции программно во временном проекте; ввод мышью/клавиатурой для самой формы не автоматизирован.
- Настройки задают сборку и имена bindings, но не гарантируют, что объявленный managed type существует: это устанавливается последующей сборкой/проверкой build registry.
- C# остаётся недоверенным in-process кодом без sandbox.
- В рабочем каталоге сохранялись многочисленные незакоммиченные изменения предыдущих подэтапов. Их не удаляли и не переписывали намеренно; commit/push не выполнялись.
