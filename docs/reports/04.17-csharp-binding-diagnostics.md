# Подэтап 04.17 — диагностика C# build bindings в Editor

Дата: 2026-11-15.

## Изменения

Project → C# scripts теперь сообщает причину каждого рассогласования между текущим build handoff и `.astro/assets.index`: выбранный тип ещё не зарегистрирован, зарегистрированное имя managed type отличается от текущего binding, source hash устарел, либо запись ссылается на output другой сборки. Существующие сводные сообщения о незакреплённых исходниках и записях вне текущего манифеста остаются видимыми. Панель также предупреждает, что фактическое наличие CLR type проверяется только при одобренной Play-загрузке.

**Register current C# build** остаётся явным действием. После успешного текущего build оно обновляет запись для того же source path и сохраняет её AssetId. Refresh/открытие Project panel не запускает CLR и не исполняет проектный код.

В `AssetRegistry::inspectScriptBuild()` общая причина «type/output устарели» заменена отдельными диагностическими ветвями без изменения публичной структуры `ScriptBuildReport`. Тесты покрывают отсутствующий binding и расхождения type/hash/output, а также восстановление текущей регистрацией с сохранением ID. Русская локализация добавлена для причин и ограничения CLR-проверки.

Проверка CLR type/entry points через `CSharpScriptHost` намеренно не автоматизирована: host загрузка в процессе редактора может запустить module initializer до обычных callbacks. Для безопасной статической проверки metadata в текущем стеке нет отдельного проверенного инструмента; этот этап не добавляет новый кодоисполняющий путь.

## Ограничения

- Report сопоставляет build manifest/handoff с AssetRegistry; он не подтверждает существование CLR типа или ABI методов.
- При явном Play CLR загружается in-process с правами пользователя, и module initializer может выполниться; согласие не является sandbox.
- UI-клики не синтезируются smoke-тестом; Project panel smoke проверяет запуск окна, а детальная логика покрыта registry integration test.
- Рабочее дерево уже содержало многочисленные изменения прежних подэтапов. Их не удаляли и не коммитили; GitHub push не выполнялся.

Следующий рекомендуемый подэтап — отдельно оценить безопасную metadata-only проверку сборок и схему permission/изоляции для выполнения скриптов. Не начинать его без ручного подтверждения.
