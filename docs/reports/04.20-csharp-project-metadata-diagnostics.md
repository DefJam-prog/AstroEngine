# Подэтап 04.20 — Project diagnostics для C# metadata

Дата: 2026-11-15  
Область: только подключение Windows metadata-validator к панели Project; C# Play host и его ABI не менялись.

## Что сделано

- В Project → C# scripts добавлена явная кнопка **Inspect registered C# types**. Автоматический парсинг при открытии/обновлении Project panel не запускается.
- Перед проверкой Editor обновляет build report и план валидирует свежесть сборки, состояние регистрации, AssetId/type/assembly соответствие и наличие текущих registered bindings.
- Путь принимается только как нормализованный относительный `.dll` под `Library/Scripts`. Runner отвергает traversal, Windows reparse points, отсутствующий output и canonical path за пределами каталога проекта. Пути с Unicode поддерживаются.
- Worker запускается в отдельном процессе через локальный .NET runtime; проверка выполняется в имеющейся AppContainer границе и не загружает/не исполняет пользовательскую сборку. Работа асинхронна для Editor. Во время неё C# build отключён.
- Validator получил пакетный `inspect-many` для до 16 типов за один staging/worker запуск. Editor разбивает большие списки на пакеты; общий вывод ограничен 32 KiB и помечает усечение.
- Окно Project и кнопка локализованы для английского и русского интерфейсов. CMake собирает validator только в конфигурации с C# runtime и настроенным локальным .NET SDK; сетевое восстановление пакетов не требуется.

## Известные ограничения и риски

- Реально выполнена проверка Windows x64. UI button click по открытому пользовательскому проекту отдельно не автоматизирован; smoke проверяет появление панели, а unit/integration проверяют логику пути и validator.
- Для каждого пакета worker временно копирует .NET runtime и parser files. Списки больше 16 binding-ов создают дополнительные изолированные сессии и могут заметно замедлиться; latency на представительном пользовательском проекте пока не измерена.
- Результат ограничен 32 KiB; при превышении показывается маркер усечения.
- AppContainer и Job Object проверены предыдущим integration suite на этой машине, но это не security certification против уязвимостей metadata parser или всех поверхностей Windows. Worker — экспериментальная диагностика, не исполнение C#.
- In-process Play host по-прежнему исполняет только доверенный код и не стал sandbox; ABI/migration не менялись.
- В каталоге проекта уже было много пользовательских незакоммиченных изменений. Они не очищались, не коммитились и не отправлялись в GitHub.
