# 04.22 — C# metadata profile and large-report UX

## Scope

Measure metadata validation against the available actual C# project assembly and exercise the Editor's 128 KiB report area. No worker limits, batching policy, sandbox, persistent cache, or runtime ABI changes are included. Only the smoke path creates synthetic report text.

## Baseline and available project

The workspace contains one C# runtime sample, `AstroEngine.CSharpSample`, with the inspected type `AstroEngine.CSharpSample.SceneMotion`. No larger user project was present under the repository. The Release validator was run five times against this built assembly:

| ---: | ---: | ---: | ---: |
| 1 (cold) | 1 | 2068.5 ms | 282 bytes |
| 2 | 1 | 1456.1 ms | 282 bytes |
| 3 | 1 | 1373.7 ms | 282 bytes |
| 4 | 1 | 1465.1 ms | 282 bytes |
| 5 | 1 | 1450.9 ms | 282 bytes |

Median: **1456.1 ms**; range: **1373.7–2068.5 ms**. The sample assembly is a real project output, but its single type makes this a host baseline, not a representative large-project measurement.

## Local user-project candidate

The read-only search found a local Unity 6.5.2 project outside this repository with two scripts under `Assets/ProceduralIsoTerrain/`. Its cached `Library/ScriptAssemblies/Assembly-CSharp.dll` is 13,824 bytes, but was last written on 2026-08-18 at 22:41. `IsometricCameraController.cs` is timestamped later that day at 23:11, so the cached assembly does not include that current source. No root `.csproj`/`.sln` was present; Unity owns the project build. The absolute local path is intentionally omitted from repository documentation.

Read-only `inspect-many` attempts against this cached DLL requested `IsometricCameraController` and `IsoTerrainBootstrap`:

| Run | Exit | Wall time |
| ---: | ---: | ---: |
| 1 | 1 | 1192.0 ms |
| 2 | 1 | 1130.2 ms |
| 3 | 1 | 1121.1 ms |
| 4 | 1 | 1170.3 ms |

Median: **1170.3 ms**. These are rejected validations, not successful AstroEngine binding checks: the cached assembly has no `IsometricCameraController` type, while `IsoTerrainBootstrap` is a Unity `MonoBehaviour` without AstroEngine's required `OnCreate`, `FixedUpdate`, and `OnDestroy` ABI methods. The user's Unity project is therefore not an AstroEngine C# project for this validator. No Unity build was launched because that would rewrite generated state under the separate project directory. Raw output: `build/04.22-unity-profile.log`.

## Large report smoke

`editor/main.cpp` creates an explicitly marked synthetic UI fixture only when `--smoke` is active. It contains exactly 131,072 bytes (128 KiB), appears in the existing wrapped output region, and is discarded with the owned temporary smoke project. The Release smoke reported:

```text
[editor] syntheticMetadataReportBytes=131072 scrollable=1 maxTextDrawMs=3.2743
```

The test also enforces a generous 250 ms upper bound. This shows the widget can render and scroll this text volume on this machine. It does not verify visual legibility, navigation by mouse, truncation-marker placement by screenshot, or timing of real diagnostics. Computer Use could not capture the Editor because the fixed-duration smoke process closed before a window binding was made.


- Debug build: success; CTest **46/46**, 9.48 s.
- Release+C# build: success; CTest **49/49**, 66.31 s.
- Release Editor smoke: pass; 140 frames, Scene/Game View rendered, synthetic report was scrollable.
- Pre-change baseline in the existing build trees was Debug CTest **46/46** (9.82 s) and Release+C# **49/49** (64.94 s); the post-change full runs above preserve the same test counts.
- CTest/build logs and profile output are under `build/04.22-*`.
- Debug build output reports MSVC C4189 unused-local warnings for `csharpMetadataValidationBatchCount` and `csharpMetadataValidationPanelDrawn` in `editor/main.cpp`; no build failure resulted. Their introduction predates this substage and was not investigated here.

## Remaining evidence and next action

The 04.22 evidence-gathering work is complete with limitations: the available actual user project is a small Unity project, and its cached output is stale for one script and incompatible with the current AstroEngine C# binding ABI. The measured rejection latency is useful for that invalid-input path, but it is not a successful or representative AstroEngine project benchmark. The synthetic 128 KiB smoke confirms text rendering and scrollability, not visual readability. The measurements do not justify a persistent cache or changing worker limits, sandbox, or ABI. Unity-style managed-script compatibility is a separate product/architecture decision; no Unity files were modified. The next numbered item in the master requirements is 05.1; it was not started in this substage.
