## Реализовано

`InteractionSystem` регистрирует один `InteractableBehavior` на target EntityId: activation range, enabled state and callback. Один экземпляр системы закрепляется за одним `SceneId`; одинаковые EntityId из другой сцены отклоняются. Запрос отправляет `Requested`, проверяет actor/target, наличие behavior, enabled state, Transform и дистанцию, выполняет callback, затем отправляет `Activated` либо `Rejected` с диагностикой. Исключения callbacks преобразуются в `InternalError`. Typed events используют существующий синхронный `core::EventBus` с монотонным порядковым номером на экземпляр InteractionSystem.

Callback получает `scene::Scene&`, поэтому запрос можно направить в `RuntimeSession::runtimeScene()` и не изменять authoring Scene. Integration test выполняет именно это.

## Ограничения и проблемы

- `InteractableBehavior` — runtime code registration, не сериализуемый Scene component, prefab data или editor-authored component.
- Дистанция — простая 3D Euclidean check по локальному Transform; world transforms, hierarchy composition and physics trigger volumes отсутствуют.
- Callback and EventBus observers are synchronous and non-transactional. Callback side effects remain if callback fails partway; observer error on Activated occurs after behavior execution.
- Нет prompt UI, input mapping hookup, visual/audio feedback, line-of-sight or multiplayer synchronization.
