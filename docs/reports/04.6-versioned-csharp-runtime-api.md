# Отчёт 04.6 — versioned C# runtime bridge

Дата: 2026-11-14. Это технический шаг, предложенный после 04.5; в исходном разделе 10 мастер-ТЗ подэтап 04.6 отсутствовал. Реализован только Windows x64 experimental ABI v1; API и .NET не утверждены для production.

## План и границы

- Установить единый версионированный native/managed контракт для fixed update и ограниченного доступа к Transform.
- Проверить размер и версию данных, ссылки на Entity, timestep и сохранение валидного состояния сцены при некорректном результате скрипта.
- Не создавать встроенный Code workspace или persistent `ScriptBehavior`: пока не определены asset identity, schema, lifecycle, serialization/migration и multi-script ordering.

До изменений: Windows x64/MSVC baseline build `build/stack-spike` был актуален; CTest **42/42** за **7.35 s**. Сборка `build/04.5-csharp-host` была актуальна; CTest **36/36** за **1.12 s**. Код 04.5 host оставался выключенным в обычной конфигурации.

## Реализовано

- Добавлены ABI structs `CSharpScriptTransformV1`, `CSharpScriptApiV1`, `CSharpScriptUpdateV1` и `CSharpScriptStatus` с фиксированными версиями/размерами и типами `uint32_t`, `uint64_t`, `int32_t`, `double`.
- Добавлена C++ функция проверки update header: точный размер, версия 1, ненулевой EntityId/API pointer и конечный положительный fixed delta.
- `CSharpScriptHost::fixedUpdate` создаёт callback table, доступную только во время вызова, и синхронно передаёт `FixedUpdate` идентификатор сущности, delta и API функции чтения/записи Transform.
- C# sample зеркалит структуру через `StructLayout.Sequential`, проверяет размер/версию обоих контрактов, timestep и callbacks; читает/обновляет Transform через callback.
- Native `setTransform` делегирует в `Scene::setTransform`; invalid/non-finite values отклоняются. API не раскрывает полный C++ Scene или arbitrary memory.
- Low-level `invoke(span<byte>)` оставлен private; внешняя точка входа — typed `fixedUpdate`.
- Сохраняемый ScriptBehavior, asset references, property binding, serialization и migration не добавлялись.

Контракт подробнее описан в [CSHARP_SCRIPTING_API.md](../CSHARP_SCRIPTING_API.md). Он является экспериментальным и ABI-compatible только в границах проверенных Win64 сборок; версии выше 1 и структуры другого размера отклоняются.

## Ограничения и следующий рекомендуемый подэтап

Скрипт работает in-process с правами движка и не sandboxed. Callback pointers нельзя хранить/вызывать позднее. Нет внешнего plugin SDK, generic property/Command API, `ScriptBehavior`, serialization, editor integration, hot reload, crash containment, Android/iOS или export/runtime package checks. Числа ABI проверены фактической Win64 integration сборкой; другие ОС/ABI не проверялись.

Следующий рекомендуемый шаг — отдельно спроектировать persistent `ScriptBehavior`: stable script AssetId, имя типа/entrypoint, schema version, lifecycle и сериализация/миграции. После этого можно проектировать 06.6 Code workspace на реально определённом контракте. Никакая следующая реализация не начата.
