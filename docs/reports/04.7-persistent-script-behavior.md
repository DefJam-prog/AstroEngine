# 04.7 — persistent ScriptBehavior

**Статус:** подэтап выполнен; ScriptBehavior сохраняется в сцене, но пока не запускается runtime.

## Что добавлено

- Scene entity может хранить несколько ScriptBehavior: стабильные ComponentId и Script AssetId, component schema version 1, UTF-8 managed type name и enabled flag. Scene API поддерживает чтение, добавление, изменение и удаление с проверкой входных данных и без повторного использования ID.
- Формат Astro Scene повышен до v5. Reader принимает v1–v5; в старых версиях список ScriptBehavior пуст. Открытие файла само по себе не меняет его, а явное сохранение пишет текущий v5. Неизвестные/несовместимые компоненты и недействительные references дают диагностическую ошибку.
- Prefab capture поддерева с ScriptBehavior отклоняется, потому что текущий prefab format не сохраняет эти bindings. Это предотвращает тихую потерю данных.
- Описан предполагаемый lifecycle `OnCreate` → fixed-step `FixedUpdate` → обратный `OnDestroy`, но он пока не исполняется. Это контракт следующего этапа, а не готовая runtime-функция.

Изменены Scene model/parser, prefab capture boundary, unit/integration tests и документы: README, ARCHITECTURE, ROADMAP, STATUS, DECISIONS (D073), TESTING, FILE_FORMATS и C# scripting API. Изменения существующего workspace пользователя и предыдущие незакоммиченные правки сохранены; файлы сцен пользователя не переписывались.

## Ограничения

- Script AssetId не разрешается в `.cs` source или assembly: текущий AssetRegistry индексирует изображения.
- RuntimeSession/host does not instantiate serialized bindings or run the documented lifecycle. Missing-script diagnostics, transactional commands, Editor component authoring, hot reload and sandbox remain unimplemented.
- ScriptBehavior is not represented in `.astro-prefab`; capture is rejected instead.
- Scene v5 is a new serialized format version. Readers older than this code will not understand it. This project has no published compatibility promise yet.
- .NET 10 host is still experimental, optional and Windows x64 only. The in-process scripts are not sandboxed; do not load untrusted code.

## Рекомендуемый следующий подэтап

После ручного подтверждения определить project-local Script Asset registry/import/build и диагностику разрешения AssetId к managed assembly/type. Затем отдельно реализовать и тестировать lifecycle в RuntimeSession; не считать текущий serialized binding исполняемым поведением.
