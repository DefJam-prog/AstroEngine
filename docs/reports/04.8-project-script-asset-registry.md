# 04.8 — project Script Asset Registry и разрешение AssetId

**Статус:** выполнен; это дополнительный технический подэтап C# prototype, не lifecycle/runtime authoring.

## Реализовано

- `AssetRegistry` теперь выдаёт единый монотонный AssetId для image и script assets. Script metadata хранится в общем `.astro/assets.index`.
- Формат asset index v2 добавляет script source path, managed type name, сборочные DLL/runtimeconfig paths и SHA-256 исходника. Старый image-only v1 читается; одно открытие его не переписывает. Явная запись регистрации/reimport атомарно сохраняет v2.
- `registerScript` требует UTF-8 `.cs` под `Scripts/`, managed type name длиной 1–512 байт без пробельных/control символов и существующие DLL/runtimeconfig под `Library/Scripts/`. Файлы должны быть обычными файлами в пределах соответствующих каталогов. Источник не изменяется. Повторная регистрация того же source сохраняет ID.
- `resolveScript(id)` проверяет пути, наличие outputs и hash исходника. Если `.cs` изменился после регистрации, возвращает диагностический `InvalidState`, пока скрипт не пересобран и запись не обновлена.
- Optional Windows host получил `CSharpScriptHost::loadScriptAsset`: он разрешает ID и загружает указанный managed type и `FixedUpdate` через hostfxr. Простое имя .NET assembly предполагается равным имени DLL без расширения.
- `runtime.csharp_host.integration` проверяет реальный sample assembly по сохранённому Script AssetId. Тест использует дочерний процесс, чтобы Windows/CLR освободил загруженную DLL до удаления временного проекта.

Изменены `engine/assets` registry/API, `astro_runtime_csharp`, C# host integration, asset registry integration, небольшая диагностика SceneSprites test, README и документы ARCHITECTURE, ASSET_PIPELINE, CSHARP_SCRIPTING_API, DECISIONS (D074), FILE_FORMATS, ROADMAP, STATUS и TESTING.

## Ограничения и риски

- Registry не компилирует проектные `.cs` файлы. C# outputs должны быть собраны отдельно и лежать под `Library/Scripts/`.
- Registry валидирует метаданные и исходный hash, но не хэширует/проверяет содержимое DLL. hostfxr проверяет type/entry point при явном load; assembly исполняется внутри процесса и не sandboxed.
- Загружаемый host сейчас ожидает entry point `FixedUpdate` и assembly simple name, равное stem DLL. Более гибкая assembly identity/методы требуют следующего API-дизайна.
- Serialized `ScriptBehavior` ещё не связан с `loadScriptAsset`, RuntimeSession не управляет instances/lifecycle, Editor/Command API authoring отсутствует, Script assets не включены в image-only asset package/export.
- Изменение публичного `AssetRegistry` layout выявило `unscanned` downstream C++ targets в прежних Ninja-каталогах: четыре smoke/integration теста там завершились ошибкой, потому что потребители не пересобрались. Полные свежие Debug/Release сборки прошли. При будущих изменениях публичных header ABI следует собирать в новом каталоге; автоматическое сканирование заголовков нужно отдельно оценить, этот подэтап его не менял.
