# 05.10 — Self-contained Puzzle campaign runtime package

## Scope

Make the optional Windows runtime ZIP runnable with the checked-in Puzzle campaign after extraction. Keep the change limited to package contents, a relative launcher, package smoke coverage, and documentation. The source campaign remains project content and was not modified by package/test execution. No push, commit, project-wide export, or later substage was performed.

## Plan, dependencies, and risks

- Reuse the existing SDL3/ImGui runtime package and campaign/session/save code; add no third-party dependency.
- Include the existing two-level sample beneath an ASCII relative package path and resolve the launcher paths relative to `%~dp0`.
- Verify both clean menu startup and bundled campaign save/restore from a freshly extracted archive.
- Windows-specific risks are batch-file quoting and current-working-directory assumptions. CTest therefore starts the executable directly for campaign smoke; the `.cmd` launcher is separately run manually from an unrelated working directory.

## Changes

- `samples/game_ui_demo/CMakeLists.txt`: install the existing `samples/ПазлКампания/Puzzle` directory to `game-data/puzzle-campaign`, and install the launcher at the archive root.
- `samples/game_ui_demo/launch_puzzle_campaign.cmd`: start the adjacent executable with adjacent bundled project data and campaign ID `starter`; forward extra command-line arguments such as `--smoke`.
- `tests/smoke/windows_runtime_package.cmake`: require the executable, launcher, README, dependency license texts, campaign file and both level files; run menu smoke and campaign save/restore smoke against the package data.
- `samples/game_ui_demo/README-runtime.txt`, `samples/ПазлКампания/README.md`, `README.md`, `docs/BUILD_GUIDE.md`, `docs/GAME_UI.md`, `docs/ROADMAP.md`, `docs/STATUS.md`, `docs/DECISIONS.md`, `docs/TESTING.md`: document use, results, decision D092 and limits.

## Verification

Environment: Windows 11 x64, Visual Studio 2022 MSVC, CMake/Ninja, Release, existing local SDL3/ImGui dependency cache.

Baseline before edits:

```powershell
cmake --build build/05.10-runtime-package --config Release --parallel 4
ctest --test-dir build/05.10-runtime-package --output-on-failure
```

The build was up to date and package-profile CTest passed **45/45** in **3.47 s** (`build/05.10-prechange-build.log`, `build/05.10-prechange-ctest.log`).

Configure and build the new Release tree:

```powershell
cmake -S . -B build/05.10-runtime-package-bundled -G Ninja `
  -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON `
  -DASTRO_BUILD_GAME_UI_DEMO=ON -DASTRO_BUILD_WINDOWS_RUNTIME_PACKAGE=ON `
  -DASTRO_BUILD_STACK_SPIKE=OFF -DASTRO_BUILD_EDITOR=OFF
cmake --build build/05.10-runtime-package-bundled --target astro_game_ui_demo --parallel 4
cmake --build build/05.10-runtime-package-bundled --target package --parallel 4
```

Configuration, runtime build, and CPack package target succeeded. The focused package smoke passed **1/1** in **1.24 s**, and the full Release package-profile CTest passed **45/45** in **8.22 s**. The exact ZIP was extracted to a separate clean directory: menu smoke passed, campaign smoke passed with output `save=restore-pending end=save-restore`, and `launch_puzzle_campaign.cmd --smoke` was manually invoked from a different current working directory and exited successfully. The packaged source example is under an ASCII path, so the test covers the package's extracted data path as well as the separately existing Unicode source path.

Logs: `build/05.10-bundled-configure.log`, `build/05.10-bundled-build.log`, `build/05.10-bundled-package-target.log`, `build/05.10-bundled-package-smoke.log`, `build/05.10-bundled-package-ctest.log`.

## Limits and next recommended substage

This is a self-contained package for one sample campaign, not a general project exporter. It does not include the Editor or build tools. Campaign saves remain manual and live in SDL per-user data; autosave, save migration and checkpoint gameplay integration are absent. The `.cmd` launch path is manually verified; CTest exercises the packaged executable directly because the attempted CMake-to-`cmd.exe` wrapper invocation had unreliable quoting. No hardware mouse test or physical audio-device test was performed. Stage 05 acceptance remains incomplete.

Recommended next step: 05.11 should be chosen from the remaining Stage 05 acceptance gaps in the roadmap and separately confirmed before work begins.
