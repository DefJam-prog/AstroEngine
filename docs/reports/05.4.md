# Подэтап 05.4 — Save System v1

## Реализовано

- `astro_runtime_save` как отдельный C++20 target, gated через `ASTRO_BUILD_SAVE_RUNTIME` вне тестовых конфигураций.
- Пустой по умолчанию `SaveProfile`; каждое поле добавляется явно по Entity ID и property ID. V1 поддерживает `entity.name`, отдельные scalar fields Transform и `sprite_renderer.visible`.
- Нумерованные ручные слоты под user-data directory, заданной приложением; metadata содержит Scene ID, profile ID/version/fingerprint, game version, UTC timestamp и количество записей.
- UTF-8 text format `ASTRO_SAVE 1`, строгий разбор, лимит файлового размера, CRC32 целостности, unique temp file, flush и атомарная замена; валидный прежний слот сохраняется как `.bak`, load/inspect могут переключиться на backup.
- Load проверяет совместимость и все записи до применения к Scene copy. Отсутствующие Entity ID и components пропускаются и учитываются в результате; повторное применение не создаёт объекты.
- Обновлены `SAVE_SYSTEM.md`, `FILE_FORMATS.md`, ARCHITECTURE/ROADMAP/STATUS/DECISIONS/TESTING и README.

## Тестирование

Baseline перед изменениями, Windows x64/MSVC Debug: optional CTest **24/24**, headless **19/19**.

```powershell
cmake --build build/stack-spike --parallel 4
ctest --test-dir build/stack-spike --output-on-failure
cmake --build build/05.3-headless --parallel 4
ctest --test-dir build/05.3-headless --output-on-failure
```

После изменений обе сборки успешны: optional CTest **25/25**, headless CTest **20/20**. Windows-интеграционный тест блокирует замену файла handle без delete-sharing и подтверждает сохранность последнего committed slot. Отдельно проверяются corrupt main + backup fallback, checksum mismatch, unsupported format version, profile/game mismatch без частичного изменения Scene, пропущенные entity/component, повторный load, reopen store и orphaned temporary file.

Логи: `build/05.4-baseline-*`, `build/05.4-build.log`, `build/05.4-ctest.log`, `build/05.4-headless-build.log`, `build/05.4-headless-ctest.log`.

## Ограничения

Не реализованы schema migrations, autosave, quick-save policy, tags/groups, редактируемые templates, здоровье/инвентарь/игровые переменные, динамические object IDs, checkpoint/respawn, слоты с UI previews и автоматический выбор каталога платформы. Реализован `inspect()` с metadata/date/count, но не изображение preview. CRC32 обнаруживает случайное повреждение и не защищает от читов. Проверен отказ перед публикацией через заблокированный target и восстановление orphan temp, но не аварийное выключение процесса/устройства непосредственно во время системного вызова записи. Процесс игры не перезапускался; тест повторно открывает SaveStore на том же каталоге.
