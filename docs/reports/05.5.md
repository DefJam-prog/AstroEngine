# Подэтап 05.5 — Checkpoint v1

## Реализовано

- Optional `astro_runtime_checkpoint`, gated by `ASTRO_BUILD_CHECKPOINT_RUNTIME` and depending on existing `astro_runtime_save`.
- Runtime registration by Entity ID, validated XY activation rectangle around checkpoint Transform, explicit respawn position, optional `Result<bool>` condition callback, enabled state, and OneShot/Repeatable policy.
- Edge-triggered activation with typed `Activated`, `Rejected`, and `Respawned` events through the existing EventBus.
- Distinct modes: `RespawnOnly` changes the active spawn point without writing; `SaveSelectedProfile` requires named profile/store/slot and saves selected fields before activation.
- Explicit respawn policy: default `PositionOnly`; optional `SelectedProfile` load into a Scene copy, followed by setting the actor to the checkpoint position. Fallback position is available when no checkpoint is active.
- Documentation updated in SAVE_SYSTEM, FILE_FORMATS, ARCHITECTURE, ROADMAP, STATUS, DECISIONS, TESTING, README.

## Ограничения

Checkpoint definitions and active state are code-configured and runtime-only. Detection checks XY coordinates against an axis-aligned rectangle around the entity's stored Transform; it does not use hierarchy/world transforms, Z, physics queries, or serialized scene components. The host must call `update` and invoke `respawn` after its own death logic. Conditions are C++ callbacks. There is no editor authoring, visualization/audio, no-code condition graph, health/inventory respawn configuration, or automatic death detector. Event observer side effects are not transactional; `Respawned` observers run after state replacement.
