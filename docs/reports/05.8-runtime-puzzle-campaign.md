# 05.8 — Authored Puzzle campaigns in standalone runtime

Date: 2026-11-15  
Scope: load authored Puzzle campaign/level files in the optional SDL Game UI demo, advance gameplay through the runtime fixed step and expose explicit campaign transitions. Unity scripts were not run.

## Implementation

- Added optional command-line mode `--project-root <path> --campaign <id>`. Windows `wmain` converts UTF-16 command arguments to UTF-8, then the path is constructed from UTF-8 bytes. No-argument demo behavior remains the seeded 8×8 board.
- The demo uses `PuzzleCampaignSession::start` and existing project-level/campaign readers. It does not duplicate campaign parsing, validation or transition resolution.
- UI tile selection queues a move; `RuntimeSession::tick` applies it. After the level target is reached, an explicit **Continue campaign** action completes one transition and loads one authored level. `END` retains the final board and score.
- Added a read-only example project at [samples/ПазлКампания](../../samples/ПазлКампания/README.md), including `intro`, `finale`, a score threshold, DEFAULT and END.
- Added campaign state strings to the English/Russian runtime localization table and an end-to-end SDL smoke that launches the sample through its Unicode source path.

## Limitations

- The standalone demo reads campaign content but does not persist player progress or restore a campaign session.
- The Game UI library host uses a synchronous project-file load when Continue is selected; background/asynchronous loading is not implemented.
- The sample project is read-only and has no `.astro` editor manifest; it is consumed as a Puzzle content root by the runtime CLI.
- Release configuration and the 05.6 runtime ZIP were not rebuilt or clean-start tested. An existing ZIP still contains the prior demo executable.
- Physical mouse input, gamepad input, scene/campaign save integration and other platforms remain unverified.
