# 05.9 — Manual Puzzle campaign progress persistence

## Scope

Added explicit progress save/load for the standalone SDL Game UI campaign host. This substage did not add autosave, schema migration, Editor Game View slots, project-file writes, or a rebuilt Windows runtime package.

## Implementation

- Added `PuzzleCampaignSaveAdapter` on top of the existing versioned `SaveStore` and Puzzle snapshot adapter.
- Campaign progress opts into exactly four custom fields: campaign ID, active authored level ID, terminal-END state, and deterministic Puzzle snapshot. The demo does not select Scene properties.
- Added `PuzzleCampaignSession::resume`. It checks that the level belongs to the campaign, compares the saved board rules against the current authored level, restores the Puzzle state, and verifies terminal END against current transition rules. Target-complete progress resumes with the existing explicit Continue action pending.
- The standalone demo exposes a manual slot selector for slots 0–9 plus Save progress and Load progress. Saves live beneath SDL user data at `PuzzleCampaigns/<FNV-1a canonical project path key>/<campaign-id>`; the project's authored content is read-only in this flow.
- Save/load controls have English/Russian labels. Errors are shown through the existing Game UI diagnostic path.

## Limitations

- Migration is intentionally absent; SaveStore rejects incompatible profile/game versions.
- Only the standalone SDL demo has campaign slot controls. Editor Game View still has no campaign progress UI.
- The demo has manual saves only. It does not autosave, display slot previews/timestamps, or persist extra campaign variables.
- The project root's canonical UTF-8 string is hashed with non-cryptographic FNV-1a for a directory namespace. This is a collision-resistant-enough convenience key for local separation, not a security boundary or anti-cheat feature.
- The smoke is programmatic; it does not synthesize physical ImGui/mouse clicks or prove recovery after a separately launched process restart. Existing SaveStore integration tests cover slot persistence/reopen behavior.
- The modified source tree contained unrelated pre-existing user changes before this substage. They were preserved; no commit or GitHub push was made.
