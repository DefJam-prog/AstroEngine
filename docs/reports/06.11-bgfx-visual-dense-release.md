# 06.11 — Scene/Game View visual regression, dense benchmark and Release check

## Scope

This follow-up adds the requested validation for mixed sprite textures, alpha blending and framebuffer recreation during window resize; expands the renderer benchmark to denser scenes; and checks the available Release targets. It does not change the renderer API or start the next engine substage.

## Changes

- `editor/main.cpp`: smoke assets now include 32×32 opaque red, half-alpha green and opaque blue PNGs with distinct AssetIds. The rendered Scene contains three sprites, and the smoke asks SDL to resize the window from 1100×720 to 1280×800 and back. bgfx captures the final backbuffer to a temporary TGA; a bounded reader validates that the capture contains red, blue and green blended over the Scene/Game clear color. Project and capture remain in an owned unique OS temp directory and are removed after verification.
- `editor/main.cpp`: `--benchmark` now measures 1, 100, 1000, 5000 and 10000 sprites. The established 1k-and-below cases retain 8 warm-up and 40 measured frames; dense cases use 4 warm-up and 12 measured frames to bound run time.
- `docs/ROADMAP.md`, `docs/STATUS.md`, `docs/DECISIONS.md`, `docs/TESTING.md`, and `docs/RENDERER_2D.md`: record the new checks, measured limits and Release dependency gap.

## Dense-scene benchmark

Command: `build/stack-spike/editor/astro_editor.exe --benchmark`. All runs were at 960×540 on the current D3D11 Debug configuration. Times in milliseconds:

| Sprites | Scene CPU p50 / p95 | Game CPU p50 / p95 | Paired GPU frame p50 / p95 |
|---:|---:|---:|---:|
| 1 | 0.0297 / 0.0537 | 0.0140 / 0.0226 | 0.04432 / 0.04960 |
| 100 | 0.4067 / 0.5140 | 0.4026 / 0.4598 | 0.02528 / 0.04104 |
| 1,000 | 4.9543 / 5.5934 | 4.8271 / 6.3265 | 0.03908 / 0.12848 |
| 5,000 | 42.6173 / 48.1816 | 40.7013 / 44.0386 | 0.09500 / 0.10200 |
| 10,000 | 132.8710 / 144.2850 | 130.9290 / 137.7120 | 0.10812 / 0.11300 |

Full-frame host upload remains zero. The 10,000-sprite pair submits 1,840,000 transient vertex/index bytes per frame. At this density CPU scene traversal and geometry preparation dominate and are far above a 16.67 ms 60 FPS frame budget. These synthetic numbers are not a final performance target and should not be generalized to Release or other hardware.

Full output is in `build/06.11-dense-benchmark.log`.

## Remaining limits

- The image check is a pixel-color predicate over a TGA capture, not a checked-in full-frame golden or a per-view image diff. It can catch missing colors/blending but not every layout or visual regression.
- No manual interactive Editor walkthrough or other graphics backend/GPU was checked.
- Dense-scene timings are Debug-only; full Editor Release timing remains blocked until a Release bgfx library is built in the dependency cache.

## Next recommended substep

Profile and reduce per-entity scene traversal/vertex preparation at high sprite counts, then rerun the same benchmark in a complete Release configuration. Define the target frame budgets separately before treating them as acceptance thresholds.
