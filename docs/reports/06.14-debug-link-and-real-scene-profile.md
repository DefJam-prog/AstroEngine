# 06.14 — Fix Debug playground link targets and check real-scene availability

## CMake diagnosis and fix

The failure was not a misplaced `.lib` archive. In `build/stack-spike`, `ASTRO_BUILD_EDITOR=ON`, `BUILD_TESTING=ON`, and `ASTRO_BUILD_2D_PLAYGROUND=OFF`. The top-level CMake still adds `samples/2d_playground` for Editor tests, but `engine/runtime/CMakeLists.txt` only created `astro_runtime_sdl_render2d` and `astro_runtime_sdl_wic_image` when the standalone playground option was on. Since those target names were unresolved at configure time, the generated sample link command emitted bare library names.

An internal `ASTRO_BUILD_2D_RUNTIME_ADAPTERS` condition now enables these targets when either the standalone playground option is enabled or Editor tests consume the playground. No external dependencies or public C++ APIs changed.
