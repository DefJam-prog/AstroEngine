# 06.15 — Puzzle в Game View

## Реализация

Windows Editor получил опциональную кнопку `Play Puzzle`, если CMake target `astro_runtime_puzzle` включён. Game View рисует сетку 8×8 с текущими score/level и принимает выбор двух соседних клеток мышью. Перестановка ставится в очередь и выполняется внутри fixed-step callback `RuntimeSession`; Pause не исполняет очередь, Step применяет один ход. Обычный Play сцены остаётся самостоятельным режимом. Puzzle state и runtime Scene не заменяют и не изменяют authoring Scene.

В `editor.smoke` оставлена отдельная проверка исходного Scene/Game sprite screenshot; затем smoke запускает Puzzle preview, проверяет наличие drawable board, детерминированный успешный ход, паузу с ожидающим ходом, одинарный Step, возобновление и неизменность authoring Scene. Smoke проходит на реальном bgfx/D3D11 окне в тестовой среде.

## Ограничения

Это встроенный игровой preview, не T01 project template: нет создания проекта, авторинга/сохранения уровней, серий уровней, игрового HUD и подключения прогресса к SaveProfile/checkpoint. Smoke симулирует tile selection через ту же функцию обработки клика, но не генерирует физические mouse events. Puzzle режим доступен только если `astro_runtime_puzzle` включён; при `BUILD_TESTING=OFF` задайте `-DASTRO_BUILD_PUZZLE_RUNTIME=ON`. Проверена только Windows/D3D11 конфигурация.

Изменения не закоммичены и не отправлялись в GitHub. Следующий рекомендуемый подэтап — отдельно определить контракт авторинга и уровня T01 либо интеграцию сохранения Puzzle-прогресса; здесь они не начинались.
