# 06.16 — Puzzle SaveStore в Game View

## Что сделано

Game View Puzzle теперь предлагает ручное сохранение/загрузку в слоты 0–9. Реализовано через существующий `astro_runtime_puzzle_save`, без нового формата. Фиксированный profile `puzzle-preview` v1 выбирает ровно один custom key — строку `puzzle.snapshot`; никакие Scene-поля не добавляются. Автосохранения нет.

При первом нажатии Editor открывает SDL preference directory и подкаталог `Saves/PuzzlePreview`; фактический путь виден в Game View. Проектные исходники и ресурсы не используются для хранения прогресса. Если PuzzleSave target не собран, кнопки не включаются. Adapter остаётся optional: тесты собирают его автоматически; Editor + Puzzle target также включает его для обычной сборки.

Smoke использует временный каталог собственного тестового проекта, никогда не открывает пользовательский каталог. Он сохраняет прогресс после хода, меняет состояние board legal move, загружает слот и сравнивает весь PuzzleSnapshot; затем продолжает ранее существующие Pause/Step и authoring Scene isolation проверки.

## Ограничения

Сейчас это ручные слоты встроенного Puzzle preview, а не универсальный Save UI: profile ID, версия игры, ключ snapshot и каталог заданы кодом. В Game View пользователь может выбрать слот, но не каталог/профиль; SaveProfile authoring здесь отсутствует. Не проверялись повторный запуск приложения и другие SDL платформы. Пользовательский путь можно проверить по надписи `Save folder` в Game View после первого действия.

Изменения не закоммичены и не отправлялись в GitHub. Следующий рекомендуемый подэтап — дать SaveProfile и user-data path настройки на уровне проекта/игры, либо перейти к авторингу уровней Puzzle; дальше ничего не начиналось.
