# 06.17 — Настройки сохранений Puzzle на уровне проекта

## Что сделано

В Game View добавлена секция `Puzzle Save Settings`. Для открытого проекта в ней настраиваются ID SaveProfile, версия его схемы и подпапка пользовательских сохранений относительно SDL user-preferences каталога. Настройки применяются кнопкой `Apply project settings`.

Настройки редактора хранятся отдельно в `<project>/.astro/puzzle-save.settings` (UTF-8, формат v1 с ограничением 4 КиБ). Существующий `project.astro` версии 1 не менялся. Для проектов без sidecar используются профиль `puzzle-preview` версии 1 и относительный каталог `Saves/Projects/<hash корня проекта>/Puzzle`, поэтому разные проекты по умолчанию получают разные каталоги. Sidecar записывается через временный файл и атомарную замену.

Профиль по-прежнему явно выбирает только строковое поле `puzzle.snapshot`. Слоты остаются ручными (0–9); автоматическое сохранение не добавлено. Путь должен быть относительным и длиной 1–512 байт UTF-8; абсолютные/rooted пути и компоненты `.`/`..` отклоняются. ID профиля ограничен 1–64 ASCII символами `[A-Za-z0-9._-]`, версия схемы должна быть ненулевой.

При переключении проекта редактор сбрасывает привязанный SaveStore и состояние Puzzle, чтобы данные предыдущего проекта не могли попасть в новый. Некорректный sidecar не перезаписывается автоматически: редактор показывает диагностическое состояние и требует применить валидные настройки.

## Совместимость и ограничения

Файлы старого общего каталога `Saves/PuzzlePreview` не удаляются и не переносятся. Чтобы вручную продолжить пользоваться ими, укажите `Saves/PuzzlePreview` как относительную подпапку. Изменение ID или версии профиля не мигрирует старые слоты; SaveStore отклоняет несовместимую схему, сохраняя сами файлы. Пока это настройки встроенного Puzzle preview, а не универсальная система авторинга SaveProfile для игровых проектов. Пользовательский каталог открывается в обычном Editor только при ручном сохранении/загрузке; smoke использует исключительно временный каталог.

## Проверки после изменений

Среда: Windows 11 x64, MSVC, CMake/Ninja, bgfx D3D11, конфигурация Debug.

```powershell
$vs = 'C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat'
$cmake = 'C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe'
$ctest = 'C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\ctest.exe'
cmd /d /s /c "call `"$vs`" >nul && `"$cmake`" --build build/stack-spike --parallel 4"
& $ctest --test-dir build/stack-spike -R editor.smoke --output-on-failure
& $ctest --test-dir build/stack-spike --output-on-failure
```

Full build прошёл. `editor.smoke`: **1/1 passed** за **3.43 s**. Полный CTest: **38/38 passed** за **8.01 s**. Smoke проверяет настройки по умолчанию для двух корней проекта, UTF-8 round-trip, отклонение `../outside` без замены предыдущего валидного файла, отображение секции настроек и сохранение/изменение/восстановление `PuzzleSnapshot`; также проходят существующие проверки Pause/Step. Каталог пользователя SDL в smoke не затрагивается.

Логи: `build/06.17-project-puzzle-settings-build.log`, `build/06.17-project-puzzle-settings-focused.log`, `build/06.17-project-puzzle-settings-full-build.log`, `build/06.17-project-puzzle-settings-full-ctest.log`.
