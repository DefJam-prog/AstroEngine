# 06.19 — Puzzle progress slots per authored level

## Scope

Enabled manual Puzzle Save/Load while an authored level is active. A saved snapshot now carries an explicit level identity in the SaveProfile's custom fields. This is not a campaign, automatic-save policy, or finished T01 template.

## Implementation

- Added the selected string key `puzzle.level.id` and level-aware save/load helpers to the optional Puzzle Save adapter.
- Accepted IDs are 1–64 ASCII letters, digits, hyphens, or underscores. Saving records the requested identity; loading compares it to the active level and returns `VersionMismatch` for missing or different IDs. The caller Scene is unchanged on mismatch, and the adapter-only identity key is not returned as user custom state.
- Editor stores authored-level slots under `PuzzleLevels/<ID>` inside the project's existing SDL user-data namespace. The built-in Puzzle sample retains its previous profile and directory. The underlying SaveStore version and Puzzle snapshot payload are unchanged.
- Extended the Editor smoke to save a level, reject another level ID without changing its current board, and restore the matching slot. All smoke files use the test-owned temporary project directory.

No player/project save files were moved or deleted. Existing per-project save settings and authored level files remain compatible.

## Known limits

- Manual slots only; no campaign/level-list progression, autosave, respawn integration, or profile-schema migration.
- Slots isolate levels by a safe ID. Renaming an ID selects a different slot namespace; there is no rename/move workflow.
- Validation is exercised in Windows Debug on the configured build. No other OS, renderer, or process-restart/exported-game path was tested in this slice.
