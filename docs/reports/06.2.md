# Подэтап 06.2 — UI Editor prototype

## Что добавлено

- `astro_ui_editor` — backend-neutral C++20 document model для Panel/Text/Button, стабильных локальных IDs и иерархии.
- Встроенные Dark/Light theme tokens и preview в панели **View → UI Editor**.
- Responsive anchors в диапазоне 0..1 и offsets в пикселях; расчёт child layout относительно parent; Desktop 1280×720, Tablet 800×1000 и Phone 390×844 preview.
- Typed one-way Scene bindings: `Entity.Name → Text` для Text/Button и `SpriteRenderer.Visible → Visible`. Refresh читает Scene и меняет только UI document; все ссылки валидируются до применения набора обновлений.
- Панель позволяет создать/удалить элемент, редактировать текст/layout/binding и посмотреть canvas preview. Она добавлена в существующую docking layout.

Новая внешняя зависимость не добавлялась. UI model использует Scene API; ImGui применяется только в существующей Windows Editor панели.

## Проверки

Окружение: Windows 11 x64, Visual Studio 2022 Build Tools/MSVC 19.44, CMake 3.31.6, Ninja 1.12.1. Команды выполнялись из x64 Developer Command Prompt/PowerShell:

```powershell
cmake --build build/stack-spike --parallel 4
ctest --test-dir build/stack-spike --output-on-failure
cmake --build build/05.3-headless --parallel 4
ctest --test-dir build/05.3-headless --output-on-failure
```

Результат после реализации: Editor build успешно; CTest **30/30**. Headless build успешно; CTest **25/25**. В CTest входят `ui.document.unit`, `ui.binding.integration` и регрессионный `editor.smoke`. Editor smoke создаёт пример документа, проверяет responsive bounds, обновление Scene binding и отрисовку панели. `ui.binding.integration` проверяет несовместимую пару, изменение Name, stale EntityId и отсутствие частичного обновления при ошибке.

Логи: `build/06.2-build.log`, `build/06.2-editor-ctest.log`, `build/06.2-headless-build.log`, `build/06.2-headless-ctest.log`. Baseline до изменений (после локальной фиксации 06.1): optional/editor 28/28, headless 23/23.

## Ограничения

- UI document и выбранная тема теряются при закрытии редактора: UI-file save/load, версии схем и Undo пока отсутствуют.
- Preview не подключён к игровому UI renderer и export; элементы не появляются в игре.
- Доступны только две односторонние привязки; нет numeric/health/inventory источников, событий/действий, двухсторонней записи или Command API integration.
- В панели создаются только root элементы. C++ model понимает parent-relative layout, но UI hierarchy/reparenting отсутствует.
- Нет пользовательских theme tokens, image assets, keyboard/gamepad navigation, localization, pixel-golden сравнения и ручного UX review.
- Лимиты модели: до 512 элементов, 4096 UTF-8 bytes текста, 120 bytes имени, offsets до 1,000,000 px и viewport до 65,536 px на ось.
