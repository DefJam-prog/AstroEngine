# 06.20 — Puzzle authored-level catalog

## Scope

Added a project catalog for authored Puzzle levels: browse/open, duplicate, and rename IDs. This slice does not add a campaign graph, delete UI, autosave, or a level-selection runtime.

## Implementation

- `PuzzleLevelFile::list` scans the non-recursive `Puzzle/Levels` directory, caps entries at 4096, sorts by ID, and returns per-entry diagnostics for invalid IDs, links/non-regular entries, mismatched file/document IDs, and malformed or unsupported documents. A single damaged level does not hide readable entries.
- `createNew` publishes a new level file without replacing an occupied destination. Existing `write` retains its explicit atomic update behavior for the currently opened same-ID draft.
- `duplicate` copies a saved definition to a caller-provided safe ID and name. It refuses a collision and leaves the source unchanged.
- `rename` validates the source, publishes the new definition to an unused ID, rereads the source to detect concurrent edits, then removes the old path. On a detected failure it attempts to remove the newly published file and returns a diagnostic. The Editor requires confirmation before this operation. Player progress under the old ID remains in its old user-data directory and is not copied or removed.
- Editor presents the project catalog, refresh/open, duplicate, and rename controls. Opening another level or resetting a modified draft prompts before discarding it. A new draft Save uses create-only publication; an opened level Save updates that same ID. Changing an opened level's ID through Save is refused; use Rename.
- No new dependency or file schema was introduced.

## Limits and risks

- Rename intentionally leaves the previous ID's progress slots untouched. There is no UI to migrate or purge those slots.
- If the original file changes while rename is publishing, the operation detects it and attempts rollback. A filesystem failure during rollback is reported; in that rare case both file paths may remain and should be inspected manually.
- Validation was performed on Windows x64/MSVC Debug only; other filesystem semantics/backends were not tested.
- There is no delete workflow, campaign/progression format, draft undo, or guarantee that an authored level has a valid move.
