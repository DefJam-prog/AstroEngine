# 06.22 — Strict Puzzle campaign parser and integration tests

## Scope

Implemented the v1 Puzzle campaign text format designed in 06.21. This substage adds parsing, serialization, semantic validation, project-file read/write, and integration tests. It does not add Editor campaign authoring or runtime progression.

## Implementation

- Added `PuzzleCampaignDefinition` and transition records, with limits of 256 levels, 4096 transitions, and 128 KiB per document.
- Added strict UTF-8 v1 parsing and deterministic serialization. Only quote and backslash escapes are accepted in quoted strings. The parser rejects malformed/truncated/trailing records, unsupported versions/conditions, invalid IDs, invalid ordering/counts, invalid thresholds/default rules, invalid reachability, and control bytes in names.
- Added structural rules: unique ordered level IDs; START must be listed; every level has exactly one final DEFAULT; score thresholds are positive and strictly descending per source; rule targets must be campaign members; all levels are reachable from START. Reachable cycles are permitted.
- Added `PuzzleCampaignFile` under `Puzzle/Campaigns/<ID>.astro-puzzle-campaign`. Read/write resolve every referenced ID through `PuzzleLevelFile`; read checks filename/document ID identity. The API checks path containment and rejects campaign symlinks. Writes use a unique sibling temporary and atomic replacement.
- Added `runtime.puzzle.campaign.integration` for UTF-8 round-trip, ordering, malformed syntax/data, validation boundaries, cycles, project references, path traversal, filename identity, and replacement. The test owns a unique temporary project and deletes only that test root.
- Updated campaign, file-format, architecture, roadmap, status, decision, testing, and README documentation.

## Known limitations

- No runtime API currently selects the next level from a score. The ordered rules are parsed and validated only.
- No Editor campaign authoring UI exists.
- v1 has no migration policy because only v1 has been defined.
- Level rename is not yet campaign-reference-aware. Do not rename a level referenced by a campaign until a separate change adds reference checks or an explicit update transaction.
- Atomic-replacement failure injection and symlink-specific tests were not run; successful Windows atomic replacement and path traversal rejection were exercised.

## Recommended next substage

Add a pure runtime transition resolver with tests for highest matching score, default fallback, terminal END, and one-edge-per-completion semantics. Keep Editor UI and automatic loading as separate later work.
