# 06.24 — Puzzle campaign runtime session and level loading

## Scope

Connected the campaign resolver to project-authored Puzzle levels through an explicit runtime session. Defined terminal END behavior. No Editor controls, engine Scene loading, or progress persistence were added.

## Runtime contract

Added `PuzzleCampaignSession` in `astro/runtime/PuzzleCampaignSession.hpp`:

- `start(projectRoot, campaignId)` reads/validates the campaign, loads its START `PuzzleLevelDefinition`, and creates an independent `PuzzleGame`.
- `swap` forwards gameplay input while Running and latches the authored level's `levelCompleted` event. Moves are rejected after completion is latched so the final score cannot change before transition selection.
- `completeCurrentLevel` is valid only after the current Puzzle target score is reached. It passes the active game score to `resolvePuzzleCampaignTransition`.
- For a nonterminal target, the session reads and constructs the next level/game in temporary values before replacing the current values. On load/validation failure, it preserves the completed board, score, level ID, and Running state so the caller can diagnose/repair the content and retry.
- For END, it enters `PuzzleCampaignSessionState::Ended`, retains the last level/game/score for a results screen, and rejects more moves and completion calls. Restart is explicit: starting a new session returns to START.

The Puzzle game state is separate from engine Scene state. The session does not save progress, load scenes, or implicitly restart.

## Integration coverage

`runtime.puzzle.campaign.integration` writes real campaign and Puzzle level files into a unique test-owned project. It checks START loading, early completion rejection, a score-threshold transition, DEFAULT transition, final END and result retention, rejected actions after END, explicit restart, and failed next-level read followed by asset restoration and retry. The temporary root is removed by the test.

## Limitations and recommended next substage

Campaign runtime uses only the Puzzle level/game model; it does not integrate with engine Scene loading, editor Play Mode, campaign saves, or Editor authoring. ID rename remains unsafe for levels referenced from campaigns. A next substage can connect this session to the Game View host or define explicit campaign progress persistence; keep those as separate changes.
