# 06.25 — Connect Puzzle campaign session to Game View

## Scope

Connected the existing `PuzzleCampaignSession` runtime to the Windows Editor Game View. This substage does not add campaign authoring UI, engine Scene loading, or campaign save/progress persistence.

## Behavior

- With a project open, enter a campaign ID in Game View and select **Play Campaign**. The campaign and its authored levels are loaded from that project through `PuzzleCampaignSession::start`.
- The campaign board is shown in Game View. Neighbor-tile clicks queue moves; the existing fixed-step `RuntimeSession` callback forwards them into the active campaign session.
- After the authored level target is reached, **Continue campaign** resolves and loads exactly one transition. Progression is explicit so the user can inspect the completed board and score.
- `DEFAULT END` shows a terminal campaign message and retains the final board/score. New moves are rejected by the ended session. **Restart campaign** starts a new session at START; **Stop** clears the current session.
- Campaign progress is not stored in the standalone Puzzle slot/profile UI. The view states this limitation explicitly. The standalone Puzzle preview, level authoring and per-level slots remain separate.

## Limitations and next recommendation

Only the Windows Editor host is connected. Campaign files still need to be created/edited outside the Editor. Campaign progress and campaign-level save slots are not implemented, ordinary Scene Play still has no Puzzle campaign binding, and level rename does not update campaign references. A reasonable next substage is a read-only campaign browser/diagnostics panel before adding campaign editing or persistence.
