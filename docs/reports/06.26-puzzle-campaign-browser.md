# 06.26 — Puzzle campaign browser and reference diagnostics

## Scope

Added a read-only project campaign browser to the Editor and a bounded campaign catalog API with per-level asset diagnostics. This does not add campaign editing or campaign progress persistence.

## Runtime file API

`PuzzleCampaignFile::list(projectRoot)` enumerates at most 4096 matching files directly under `Puzzle/Campaigns`; it does not recurse. It rejects an invalid project/catalog directory and skips following symlinked files. Results are sorted by campaign ID.

- Malformed files remain in the result with an ID and diagnostic, but without a parsed campaign definition.
- Structurally valid files retain their parsed definition even if level assets are missing or invalid.
- Each ordered level reports its ID, availability, and specific `PuzzleLevelFile::read` diagnostic.
- `referencesValid()` is true only when the document parsed and every level file is valid.
- Strict `PuzzleCampaignFile::read` and starting a campaign continue to reject broken links.

## Editor behavior

Open **View → Puzzle Campaign Browser**. Select a readable campaign to copy its ID into Game View. The browser displays the campaign ID/name, START level, ordered levels, transition conditions/targets, and a per-level OK or MISSING/INVALID status. Malformed campaign documents stay listed with their parse/validation diagnostic. Browsing is read-only and does not rewrite project assets.

## Limitations and next recommendation

The browser is read-only. It does not create, edit, or repair campaign files. A selected structurally valid campaign with bad references can be inspected, but Game View launch still fails strict reference validation until its project level files are repaired. Campaign progress is not persisted. A reasonable next substage is campaign authoring with safe reference-aware level rename behavior, designed before adding mutation controls.
