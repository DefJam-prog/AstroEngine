# 06.27 — Puzzle campaign authoring and safe level rename

## Scope

Added the requested campaign authoring flow and safe handling of campaign references when a Puzzle level ID is renamed. No user project levels/campaigns were edited, no files were deleted, and nothing was committed or pushed. Test assets were created only under a unique temporary project owned by the integration test.

## Implementation

- **Campaign Browser authoring:** create or load a campaign draft; edit ID/name, add readable project levels, reorder/remove levels, select START, add score threshold branches, and configure rule targets including DEFAULT/END.
- **Draft/write safety:** reset/open with unsaved edits asks for explicit discard. Save opens a confirmation dialog and goes through `PuzzleCampaignFile::write`, which validates the campaign and every referenced level before publishing. Saving with an ID that already exists replaces that file after confirmation. Changing ID writes a new campaign and keeps the previous ID's file.
- **Rename links:** `PuzzleLevelFile::rename` scans campaign files before changing the level ID. It blocks when a readable campaign contains the source ID, any campaign cannot be parsed, or catalog enumeration fails. The error identifies referencing/unreadable campaign IDs. Users must update/save those campaign references, rename the level, then add the new ID. There is no implicit multi-file rewrite or progress-slot migration.
- **Tests:** level integration verifies referenced rename refusal and campaign identification, unchanged source/no destination, successful rename after removing the test-owned reference, and conservative refusal when a campaign file is malformed. Editor smoke asserts the browser and authoring section render, while retaining campaign diagnostic/runtime progression checks.

## Limits

- Editor smoke is programmatic: it confirms the authoring section is drawn but does not click through ImGui controls or exercise the save modal end-to-end. Campaign writer/validator is independently covered by integration tests.
- Rename takes a conservative policy rather than updating multiple campaign files transactionally. Even unrelated malformed campaign files block rename because their references cannot be proven absent.
- Campaign progress saving, engine Scene loading, migration from a future campaign schema, and automatic ID/progress-slot migration are not implemented.
