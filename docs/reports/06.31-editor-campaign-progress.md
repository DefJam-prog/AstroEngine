# 06.31 — Ручное сохранение прогресса Puzzle-кампании в Editor Game View

Дата: 2026-11-15.

## Объём

Выполнена только интеграция ручных слотов прогресса уже выбранной Puzzle-кампании в Windows Editor Game View. Используются существующие `SaveStore` и `PuzzleCampaignSaveAdapter`; параллельный формат не добавлялся.

В профиле явно выбраны четыре пользовательских поля: ID кампании, ID текущего уровня, флаг конечного `END` и Puzzle snapshot. Свойства Scene и другие значения игры профиль не выбирает. В Game View доступны десять ручных слотов 0–9 и текущий каталог хранения.

Сохранения размещаются в SDL user data под настроенным для проекта относительным каталогом, затем `PuzzleCampaigns/<campaign-id>`. Файлы не записываются в каталог проекта или игровые ресурсы. При загрузке данные и совместимость с авторскими правилами проверяются до публикации новой campaign session; неудачная загрузка оставляет текущую сессию неизменной.

## Изменённые файлы

- `editor/main.cpp` — состояние инициализации хранилища кампании, слоты Game View, ручные Save/Load handlers и smoke-путь.
- `editor/Localization.cpp` — подписи панели и сообщения на русском языке.
- `tests/unit/editor/LocalizationTests.cpp` — проверки новых локализованных строк.
- `README.md`, `docs/ARCHITECTURE.md`, `docs/ROADMAP.md`, `docs/STATUS.md`, `docs/DECISIONS.md`, `docs/TESTING.md`, `docs/SAVE_SYSTEM.md` — описание поведения, границ и проверки.
- `docs/reports/06.31-editor-campaign-progress.md` — этот отчёт.

## Ограничения

- Проверка UI программно вызывает те же Game View handlers; реальные клики в ImGui окне не автоматизировались.
- Слоты ручные. Автосохранение, preview слотов, миграции схемы и восстановление произвольных игровых переменных отсутствуют.
- Профиль хранит только четыре указанных значения и не сохраняет Scene properties.
- Перенос сохранений при переименовании/смене ID кампании не реализован.
- Полный CTest в `build/stack-spike` Debug profile не использовался как подтверждение: эта существующая конфигурация ранее давала ошибки и не имела корректно настроенного .NET root. Релизные проверки выполняются на выделенном профиле `build/04.8-release-clean`.
