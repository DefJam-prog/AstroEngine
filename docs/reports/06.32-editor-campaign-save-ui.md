# 06.32 — Живая проверка Save/Load кампании в Editor Game View

Дата: 2026-11-15.

## Объём и обнаружение

Выполнена ручная проверка Editor Game View для сохранений Puzzle Campaign. Первый запуск показал, что небольшое first-use окно Game View слишком узкое для панели действий: поле слота вместе с двумя кнопками располагались в одной строке и обрезались; сам Game View сообщал о недостаточном размере для доски.

Исправлен только UX первого запуска: интерактивное окно получает размер 520×560, а Save/Load расположены строкой ниже селектора слота. Для режимов `--smoke` и `--benchmark` размер не меняется, чтобы сохранить существующую геометрию графического захвата. Формат SaveStore и правила выбора сохраняемых полей не менялись.

## Ручная проверка

Использован Release `astro_editor.exe` и отдельная копия `samples/ПазлКампания` в:

1. Открыт `project.astro`, в Game View введён campaign ID `starter` и запущена кампания.

3. В слот 0 сохранён стартовый `intro`, счёт 0.
4. Обмен соседних плиток изменил счёт с 0 на 180 и включил явное продолжение уровня.
5. Загрузка слота 0 вернула уровень `intro`, счёт 0 и исходную раскладку плиток.
6. Проверен файл `slot-0.astro-save` размером 7065 байт в `AppData/Roaming/AstroEngine/AstroEngine/Saves/Projects/6f72cc2f5e82e903/Puzzle/PuzzleCampaigns/starter`, вне тестового проекта.

## Автоматические проверки

До правок: target build был актуален; `editor.smoke`, `editor.localization.unit`, `runtime.puzzle.campaign.save.integration` прошли **3/3**, **3.46 s**.

После правок: Release target build прошёл; те же тесты прошли **3/3**, **3.48 s**. Первая попытка после безусловного изменения размера не прошла только `editor.smoke` с диагностикой `Scene/Game visual regression failed: screenshot lacks sprite colors`; после ограничения новой геометрии обычным запуском smoke снова прошёл. Полный Release build завершился успешно (`ninja: no work to do` после целевой пересборки), полный CTest прошёл **52/52**, **50.85 s**.
