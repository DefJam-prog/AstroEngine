# 06.38 — Campaign save copy transaction

Date: 2026-11-15
Scope: implement and test a confirmed, copy-only runtime API for same-ID campaign save artifacts. No Editor write action and no real user save data.

## Result

Added `copyPuzzleCampaignSaveTransfer`. It accepts the displayed preview and an `explicitlyConfirmed` caller flag. A false flag returns `ConfirmationRequired` without filesystem work. A true flag reruns the 06.37 read-only preflight before creating target directories. Only primary and `.bak` files for valid or backup-recovered same-ID slots are copied, byte-for-byte; invalid/mismatched/oversized slots and unexpected artifacts block the operation. Payloads are not rewritten.

Target artifacts are created exclusively: Windows uses `CreateFileW(CREATE_NEW)` and POSIX uses `open(O_CREAT|O_EXCL)`. A file or directory that appears at an expected target path during the batch is preserved, and the operation does not replace it. Existing unrelated files in the selected target directory remain untouched.

On detected I/O failure or progress cancellation, rollback removes only files created by the current attempt when the content still matches the expected output prefix. It then removes only empty directories created by that attempt. Results distinguish `CancelledRolledBack`, `FailedRolledBack` and `RollbackIncomplete`; the latter lists paths needing inspection. The optional progress callback can cancel after any successfully copied file.

This is not a crash-atomic multi-file transaction. Process termination or power loss while copying can leave partial files in the destination. `Ready` is still a point-in-time check; per-file exclusive creation protects target collisions after revalidation, while source files are opened without following reparse/symlink files on supported platforms and checked against the preview fingerprint before each write. FNV-1a is only the existing stale-change detector, not cryptographic integrity. No UI action calls this API; future UI must obtain explicit confirmation for each operation.

## Limits and next step

- No crash recovery journal exists for a process/power failure during a batch copy.
- No Editor user interface invokes the copy API, and no production save directory was used by the tests.
- FNV-1a is not cryptographic; successful preflight does not prevent source mutation after validation, though each artifact is read and fingerprint-checked before its target is created.
- Symlink fixture creation is not available in this environment; the earlier symlink path validation remains conditionally tested.

Next recommended substage: **06.39**, add an Editor confirmation flow that presents the exact same-ID preview, requires an explicit per-operation confirmation, then invokes the runtime copy API and displays completed/rollback-incomplete diagnostics. Do not run the operation against an actual user save path until its exact source and target have been reviewed and separately confirmed.
