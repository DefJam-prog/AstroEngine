# 06.39 — Editor confirmation for campaign save copying

## Result

Connected the 06.38 same-ID copy transaction to the Puzzle Save Settings UI. Once a read-only preview is available, **Copy campaign saves…** opens a separate confirmation dialog. It displays the canonical source and target paths, eligible slot count, byte total, no-overwrite behavior, and that source files stay unchanged. Only **Copy reviewed save files** invokes the runtime API with explicit confirmation; Cancel closes the dialog without copying.

The runtime API revalidates the displayed preview immediately before writing. The Editor reports copied/attempted files and bytes, stale inputs, conflicts, cancellation or rollback status, diagnostics, and each leftover path if rollback is incomplete. Changing the destination folder or refreshing preview clears the old copy result. New visible strings have Russian translations.

The Editor smoke opens the confirmation dialog, runs the same confirmation handler against its isolated temporary Unicode fixture, then confirms that the source slot remains and the copied bytes match. No real project save or AppData directory was transferred.

## Limits

- This copies same-ID recognized primary and backup files verbatim; it does not migrate IDs, merge, or overwrite.
- A process or power failure can leave a partial target because the multi-file operation has no crash-recovery journal.
- Tests verify the confirmation workflow through Editor smoke, but do not perform an interactive manual click-through using real user data.
- The repository already had 169 dirty status entries at the start of this substage. No user changes were staged, committed, pushed, or deleted.
