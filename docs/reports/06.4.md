# Подэтап 06.4 — Save System Editor

## Что сделано

- Добавлена optional backend-neutral `astro_save_editor` модель authoring: пустые профили с schema version, группы явных Entity ID, прямые поля и свойства группы.
- Перед передачей runtime модель разворачивает групповые правила в обычные `SaveProfile` поля; дубли прямого и группового выбора схлопываются. Проверяются существование Entity и наличие поддерживающего компонента. Неявного выбора всей сцены нет.
- В Editor добавлено `View → Save System`: авторинг профиля/групп, список эффективных свойств, checkpoint area, respawn XYZ, режим сохранения, slot, enabled/repeat mode и XY preview.
- Ручная кнопка запускает действующие `CheckpointSystem` и `SaveStore` на копии Scene с отдельным уникальным каталогом в temp. Тот же путь activation/save/mutate/restore проверяется editor smoke. Каталог удаляется после выхода из scope; каталог пользовательских сохранений не используется.
- Runtime контракт не менялся. Внешние библиотеки не добавлялись. `astro_runtime_save` и `astro_runtime_checkpoint` собираются с Editor даже при отключённом CTest.

## Проверка

Среда: Windows 11 x64, Visual Studio 2022 Build Tools 17.14, MSVC 19.44, CMake 3.31.6, Ninja 1.12.1. Команды выполнялись из Visual Studio 2022 Developer Command Prompt x64 в корне репозитория:

```powershell
cmake --build build/stack-spike --parallel 4
ctest --test-dir build/stack-spike --output-on-failure
cmake --build build/05.3-headless --parallel 4
ctest --test-dir build/05.3-headless --output-on-failure
```

Фактические результаты: editor build успешен; **33/33** editor CTest успешны. Headless build успешен; **28/28** headless CTest успешны. Unit тест покрывает группы, валидацию, схлопывание полей и неверные свойства. Integration тест реально активирует checkpoint, сохраняет выбранное свойство и восстанавливает его на runtime Scene копии из временного SaveStore. Editor smoke создаёт профиль/группу/checkpoint, выполняет restore preview и подтверждает отрисовку окна Save System. Дополнительно Release-конфигурация с `BUILD_TESTING=OFF` успешно собрала target `astro_save_editor` вместе с SaveStore/Checkpoint runtime. Сборка полного Release `astro_editor` не завершилась: в локальном dependency cache отсутствует `bgfxRelease.lib`; установка/скачивание зависимости не выполнялись.

Вывод сохранён: `build/06.4-editor-build-final.log`, `build/06.4-editor-ctest-final.log`, `build/06.4-headless-build-final.log`, `build/06.4-headless-ctest-final.log`.

## Известные ограничения

- Данные групп, профилей и checkpoint остаются в памяти и теряются при закрытии редактора.
- Сохраняются только `entity.name`, scalar Transform и `sprite_renderer.visible`; health, inventory, fuel, puzzle progress и остальные игровые компоненты отсутствуют.
- Группа — явный список entity ID. Теги, запросы/фильтры, исключения и шаблоны профилей не реализованы.
- XY карта — диагностический preview Transform coordinates, не пространственный Scene renderer.
- Для profile-backed ручной preview `entity.name` должен быть явно включён для первого тестового entity, отличного от checkpoint.
- Ручная мышиная UX-проверка и pixel-golden сравнение не выполнялись. Полная Release-сборка Editor ограничена отсутствующим `bgfxRelease.lib` в текущем локальном кэше.
