# 06.41 — Explicit resume for interrupted campaign save transfers

## Scope

Implemented only the next campaign-save transfer substage: resume a valid interrupted same-ID transfer. No save schema migration, cleanup workflow, or next substage was started.

## Behavior

- Added `resumePuzzleCampaignSaveTransfer`, a separate API requiring explicit confirmation. The existing copy API remains blocked while a pending journal exists.
- Before writing, runtime rereads the journal and checks its fingerprint/size, campaign ID, artifact inventory and target states against the displayed preview. It compares the current source preview with the reviewed inventory and requires every primary/backup source artifact to match the journal's slot, kind, byte count and content fingerprint.
- Complete target artifacts are preserved and skipped. Missing target artifacts are read with source fingerprint revalidation and created exclusively. A partial/changed/unsafe artifact, a changed source, a changed journal or a target changed after review blocks resume. Existing paths are never overwritten or repaired.
- When a write fails or is cancelled, only exact output files created by this resume attempt are rolled back; the journal and previously complete files remain. The unchanged journal is removed only after every planned target artifact inspects as complete.
- Editor shows a separate confirmation action for valid journals with only complete/missing artifacts. It reports copied/skipped/attempted counts and refreshes the preview after the action.
- Integration scenarios cover confirmation, successful resume, stale source and target changes after review. Editor smoke checks the recovery UI exposes the resume action. All fixtures are temporary and isolated.

## Limits

Journal v1 records content fingerprints and campaign identity, not an authenticated source path; matching content/inventory does not prove provenance. Fingerprints are for stale-change detection, not cryptographic integrity. There is no multi-process lock, power-loss atomicity for the whole set, or automatic repair/removal of partial or changed files. Such conflicts require manual review. No real project/user save data was read or changed.
