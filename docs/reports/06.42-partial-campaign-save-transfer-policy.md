# 06.42 — Non-destructive policy for partial campaign save targets

## Scope

Completed only the recommended 06.42 recovery-policy substage. No save-format migration, automatic file cleanup, or later substage was started.

## Decision and behavior

A `Partial` target artifact remains a conflict. Confirmed resume returns `DestinationConflict`, leaves the partial file byte-for-byte unchanged, does not create the missing companion artifact, and keeps the recovery journal. The Editor shows a clear manual-review warning and disables resume while any artifact is partial.

No append/delete/replace operation was introduced. Journal v1 stores the planned complete artifact size and content fingerprint, but does not bind an observed partial prefix to the process that created it. Even if the file bytes equal a prefix of the source, that alone does not prove provenance. This policy preserves the no-overwrite contract and avoids silently changing a target file of uncertain origin.

## Limits and next step

Partial files still require manual inspection; the engine does not infer ownership or remove them. Journal/source fingerprints detect ordinary changes but are not cryptographic authentication. Resume also lacks cross-process locking and power-loss atomicity across a batch. Next recommended work is 06.43: assess recovery for invalid/torn journal records without deleting or guessing at their associated save artifacts. Do not begin until explicitly confirmed.
