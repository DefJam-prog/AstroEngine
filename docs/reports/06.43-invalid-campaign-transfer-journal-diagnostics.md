# 06.43 — Diagnostics for invalid campaign transfer journals

## Scope

Implemented the next recovery substage only: classify invalid or unreadable transfer journals and preserve all other files. No journal repair, deletion, quarantine or later substage was started.

## Behavior

- Added `PuzzleCampaignSaveTransferRecoveryJournalState`: `Missing`, `Valid`, `Unreadable`, `Unsafe`, `Oversized`, and `Malformed`.
- Recovery inspection maps journal read failures and parser failures to those explicit states. Oversized journals are rejected by the existing 4096-byte cap before content is read into an unbounded buffer.
- An invalid journal produces no artifact list: the runtime does not guess target slots from malformed contents. It therefore blocks copy and resume; acknowledgement continues to reject invalid records.
- Editor shows the journal status and read/parser detail, says no save paths were inferred and no save files changed, and directs manual inspection. The invalid-record view exposes no copy/resume/acknowledgement action.
- Integration coverage includes unsupported version, truncated v1 content, oversized content and a directory occupying the journal path. Candidate slot files, journal bytes/path occupants and nested contents are asserted unchanged. Editor smoke repeats a malformed journal with a slot-looking candidate and verifies both are preserved.

## Limits and next step

An invalid journal cannot safely establish the intended artifact list. The engine leaves it and all slot-looking files untouched; manual inspection is required. No journal authenticity, repair or automatic cleanup is implemented. Next recommended substage: 06.44, design an explicitly confirmed way to retire/archive an invalid journal while preserving all save artifacts and rechecking the exact journal bytes before action. Do not begin without confirmation.
