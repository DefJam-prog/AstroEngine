# 06.46 — Handle-based acknowledgement of a valid campaign journal

## Scope

Reviewed and hardened the separately confirmed acknowledgement operation for a valid interrupted campaign transfer. The previous implementation re-read the journal by path and then called `std::filesystem::remove(path)`, leaving a replacement window between validation and deletion.

## Implementation

- Windows now opens the journal with `GENERIC_READ | DELETE` and `FILE_SHARE_READ`, using `FILE_FLAG_OPEN_REPARSE_POINT`. It checks the opened object is a disk file and neither a directory nor a reparse point, bounds the file to the supported 4096 bytes, reads the bytes from that handle and compares them exactly with the bytes re-read for the reviewed journal.
- The same handle is marked for deletion with `SetFileInformationByHandle(FileDispositionInfo)`. Existing incompatible handles, access errors, changed bytes, and filesystem refusal fail closed. There is no path-based remove fallback.
- Acknowledgement still requires explicit confirmation and compares the current journal and artifact inventory against the displayed review. It changes no campaign slot artifacts.
- No public recovery-struct layout was changed. Exact bytes are held in local variables for the final handle comparison.
- POSIX acknowledgement currently returns an unsupported-platform error without removing the journal. The documented future plan uses `open(O_NOFOLLOW)`, advisory `flock`, a held directory fd, `fstatat(..., AT_SYMLINK_NOFOLLOW)` identity comparison and `unlinkat`. Advisory locks only coordinate cooperating processes; this path remains disabled until a supported POSIX build and race tests exist.

## Tests and results

- Integration test verifies missing explicit confirmation leaves the journal; a changed journal after preview is rejected; a held competing writer handle causes Windows acknowledgement to fail and preserve journal bytes; after closing it, acknowledgement succeeds and preserves slot data and destination conflict state.
- Baseline Release build was current; full CTest passed **52/52 in 52.12 s**.
- A first focused run passed the campaign integration test but Editor smoke crashed. Investigation found the temporary public struct field had changed layout while the incremental Ninja build did not rebuild `editor/main.cpp.obj`. The field was removed; the public layout is unchanged, runtime and integration targets were rebuilt, and Editor smoke then passed.
- Final focused CTest passed **2/2 in 3.94 s**. Final Release build succeeded; full CTest passed **52/52 in 55.72 s**. `git diff --check` exited 0; Git printed working-copy line-ending notices.

## Limits

The Windows test uses a competing open writer handle in the same test process, not a multiprocess adversarial stress test. Network filesystems, ACL restrictions and filesystem-specific delete behavior can reject handle disposition; the code preserves the journal on failure. POSIX behavior was not run in this Windows environment and remains fail-closed. Other transfer/rollback cleanup paths are outside this acknowledgement API and are not made race-safe by this change.
