# 06.47 — Cross-platform campaign recovery journal acknowledgement

## Scope

Implemented and tested safe acknowledgement of a valid campaign-save transfer recovery journal on Windows and POSIX. Copy/resume now retain the journal lease while they are changing target artifacts. Acknowledgement validates the reviewed journal and artifact inventory, obtains that lease, rereads the exact journal bytes and removes only the same opened journal object/verified directory entry. Slot save files are not changed by acknowledgement.

## Platform behavior

- Windows opens the journal without following reparse points and takes an exclusive `LockFileEx` byte-range lock. It marks the same opened file object for deletion with `SetFileInformationByHandle`; closing the lease completes deletion. Other app operations that take the same range lock fail closed while a transfer or acknowledgement is active.
- POSIX opens the parent directory and journal with `O_NOFOLLOW`, takes non-blocking exclusive `flock`, reads from the held file descriptor, compares `fstat` with `fstatat(..., AT_SYMLINK_NOFOLLOW)`, then calls `unlinkat` relative to the held directory descriptor. This protects against cooperating processes that use the same lock protocol. POSIX advisory locks do not block arbitrary non-cooperating local writers; the check and unlink are not an atomic defense against a hostile local actor.
- Malformed-journal archival behavior is unchanged: archival creates an exact copy and retains the source journal for manual review.
- Neither platform guarantees crash-atomic multi-file copy or parent-directory durability after sudden power loss.

## Tests

The existing integration suite exercises interrupted copy/resume, exact/stale journal handling, slot preservation, cancellation rollback and Unicode temporary paths. New contention coverage verifies active copy lease behavior, acknowledgement refusal while a separate POSIX process holds `flock`, refusal while another Windows process holds the range lock, then successful acknowledgement after contention ends. POSIX tests use a real child process and isolated temporary paths.

## Reproduction commands

From an x64 Visual Studio Developer shell at the repository root:

```powershell
cmake --build build/04.8-release-clean --config Release
ctest --test-dir build/04.8-release-clean -C Release --output-on-failure
```

The configured `ASTRO_PWSH_EXECUTABLE` must point to an available PowerShell 7 executable.

From PowerShell with WSL Ubuntu 24.04 installed:

