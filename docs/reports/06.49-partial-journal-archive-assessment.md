# 06.49 — Assessment of interrupted malformed-journal archive writes

## Scope and result

Assessed the current malformed-journal archive path and added an isolated integration check for the residue an interrupted write can leave. Production archive code and the public API were not changed.

The archive is created directly under its final deterministic, fingerprint-derived name with exclusive creation. The source malformed journal remains present and locked through archive verification. If a process terminates before the archive write completes, a partial final-path archive may remain. A later archive request treats it like any existing non-identical occupant: it fails closed, does not overwrite or delete it, and leaves the source journal in place. The user must manually inspect the two files; the current Editor has no resume/cleanup action for archive residue.

This behavior protects the source recovery record and avoids automatic deletion of an archive-path occupant whose ownership cannot be proven. A fully written archive is idempotent on retry. File flush is attempted by the writer, but the parent directory is not explicitly flushed, so power-loss durability of the name is not guaranteed.

## Test

The integration fixture first creates a valid exact archive in an isolated temporary directory, truncates that archive to model a partial final-path residue, retries the archive operation, and verifies that the retry refuses while the partial bytes, original malformed journal, and candidate save remain unchanged. The fixture then restores the archive bytes and continues existing repeat/collision checks.

This is a state-based simulation of persisted partial output. It does **not** kill a process during the write, induce disk-full or I/O errors, or simulate sudden power loss.

Baseline focused campaign-save integration passed **1/1** on both platforms. After the test change, focused integration passed **1/1** on Windows x64 Release and WSL Ubuntu 24.04 Release. Full Release CTest passed **52/52 in 62.87 s** on Windows and **39/39 in 0.96 s** on WSL Ubuntu.

## Recommendation

Keep the current fail-closed behavior until a separate implementation stage defines a portable staged-write protocol: create a uniquely named temporary archive, write and flush it, verify exact bytes, then atomically publish to the deterministic final name without replacing an existing occupant. That stage must define temp residue ownership/cleanup, Windows/POSIX no-replace publication behavior, and parent-directory durability limits before code changes. No such protocol was implemented here.
