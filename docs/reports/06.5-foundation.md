# 2D Play foundation prerequisite for 06.5

## Scope

Implemented only the foundational slice explicitly authorized by the user to
unblock later 2D template work. The Puzzle, Platformer, and Top-Down templates
themselves are not started.

## Changes

- Added `astro_runtime_render2d`: backend-neutral filled rectangle commands,
  layer order, world-to-viewport projection, validation, and bounded command
  count.
- Added optional `astro_runtime_sdl_render2d`, which draws through the existing
  SDL3 software/renderer API without owning the host window or renderer.
- Added `astro_2d_playground`: a standalone preview with WASD/arrow movement,
  fixed-step `RuntimeSession`, pause/resume/restart, and an isolated runtime
  Scene copy.
- Added unit and SDL smoke coverage, updated build options and documentation.
- Committed the prior 06.4 work locally as recovery point `56619c6`. No push was
  performed.

## Limitations

The renderer draws filled rectangles, not image textures; it does not render
Scene entities or `SpriteRenderer` automatically. The preview is a
code-defined sample, not Editor Play UI, and has no physics/controller binding,
level serialization, or export integration. Windows/MSVC is the only backend
tested. This makes a visible 2D geometry and fixed-step input path available,
but does not by itself satisfy template requirements. See
[RENDERER_2D.md](../RENDERER_2D.md).

Next prerequisite before template authoring: connect scene assets/components
to the 2D view and define a serialized level/progress path. The user must
confirm before any further substage.
