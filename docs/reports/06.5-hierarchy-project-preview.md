# 2D hierarchy and project Scene preview prerequisite

## Scope

Implemented the next 2D-rendering prerequisite only. This does not start the
Puzzle, Platformer, or Top-Down template implementation and does not complete
stage 06.5.

## Changes

- Scene sprite collection now composes each entity's root-to-child XY transforms
  using affine `T * Rz * S` multiplication. It retains all four transformed
  corners so nested rotations with non-uniform scale render their shear
  correctly. The 2D view uses XY position/scale and Z rotation; X/Y rotation
  and Z depth are not applied.
- SDL3 draws affine sprites as textured geometry. The existing texture resolver
  and bounded Windows WIC cache remain at the adapter boundary.
- Added `astro_2d_playground --project <directory> --scene <relative-file>`.
  It loads Astro Scene v1–v4 and an existing AssetRegistry, rejects scene paths
  outside the canonical project root, and auto-fits visible sprite bounds.
- Project preview requires pre-existing `Assets`, `Library/Assets`, `.astro`,
  and `.astro/assets.index`; it does not initialize a missing project. CTest
  verifies scene, asset source, cache and index hashes remain unchanged during
  preview. Windows `wmain` preserves Unicode project paths.
- Expanded unit/integration/smoke tests and updated architecture, decisions,
  status, roadmap, user-facing render documentation and this report.

## Verification

Windows 11 x64, Visual Studio 2022 Build Tools/MSVC 19.44, CMake 3.31.6,
Ninja 1.12.1. CMake was invoked from `vcvars64.bat` because the regular
PowerShell PATH does not include it.

```powershell
cmake --build build/stack-spike --parallel 4
ctest --test-dir build/stack-spike --output-on-failure
cmake --build build/05.3-headless --parallel 4
ctest --test-dir build/05.3-headless --output-on-failure
cmake --build build/06.5-render2d-only --target astro_runtime_render2d astro_scene_render2d --parallel 4
```

Editor/optional Debug build succeeded; CTest **37/37**. Headless build
succeeded; CTest **30/30**. The project smoke passed using a Unicode temporary
project path and confirmed that scene, source image, decoded cache and index
were unchanged. It also confirmed traversal rejection. A Release configuration
with `ASTRO_BUILD_RENDER2D=ON` and `BUILD_TESTING=OFF` built both backend-neutral
targets without SDL.

## Limits and next work

The WIC decoder remains Windows-only. Project preview draws visible
SpriteRenderer components only; it does not display colliders, editor handles,
UI, or arbitrary scene components. It cannot repair missing cache entries,
modify/save the project, or control a gameplay entity in project mode. There is
no Editor-integrated Game View, physics controller, level/progress file, or
game template. The optional playground CMake option currently reuses the
stack-spike bootstrap and therefore still checks for local bgfx/ImGui cache
artifacts even though this sample only links SDL3/WIC. Next recommended work is
an Editor Scene/Game View integration plan or explicit level/progress format;
stop for user confirmation before that step.
