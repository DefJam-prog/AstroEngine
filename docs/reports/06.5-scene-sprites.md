# 2D Scene sprite rendering prerequisite follow-up

## Scope

Connected existing Scene `SpriteRenderer` data to the 2D Play preview. This is
still prerequisite work for stage 06.5; no game template, level format, or
Editor Play workflow was started.

## Changes

- Added backend-neutral sprite draw commands and a Scene-to-Canvas collector.
  Visible root sprites use AssetRegistry image dimensions and Transform XY
  position/scale/Z rotation. Negative XY scale is represented as texture flips.
- Added a caller-owned texture resolver boundary to the SDL3 renderer.
- Added an optional Windows WIC adapter that reads the registry's cached PNG or
  JPEG, limits decoded image size to 16 megapixels, and caches SDL textures.
- Updated the standalone Play sample to import a generated fixture into a
  uniquely named temporary sample project, then draw that real PNG through
  Scene/SpriteRenderer. The temporary project is removed on exit; no existing
  user asset is changed.
- Added unit and integration coverage and updated architecture, status,
  decisions, roadmap, testing, and rendering documentation.

## Verification

Windows 11 x64, Visual Studio 2022 Build Tools/MSVC 19.44, CMake 3.31.6,
Ninja 1.12.1. The regular PowerShell PATH did not expose CMake; builds were run
through `vcvars64.bat` and the installed Visual Studio CMake executable.

```powershell
cmake --build build/stack-spike --parallel 4
ctest --test-dir build/stack-spike --output-on-failure
cmake --build build/05.3-headless --parallel 4
ctest --test-dir build/05.3-headless --output-on-failure
```

Editor/optional profile built successfully and CTest passed **36/36**. The
headless profile built successfully and CTest passed **30/30**. The SDL smoke
decoded and rendered a PNG, read back its expected pixel, verified movement,
pause/manual-step and authoring Scene isolation. Scene integration verifies
that invalid/missing references do not partially append sprites.

Running both CTest profiles concurrently once caused the pre-existing

temporary-directory creation/cleanup in that older test; its precise cause was
not established and it is outside the new Scene Sprite code.

## Limits and next work

Only root entities render; parent transforms return a validation error instead
of being approximated. The WIC decoder is Windows-specific. There is no
renderer in the Editor, no scene/project loading in the sample, no camera
component, automatic texture cache invalidation after asset reimport,
texture streaming/batching, collision controller, level or progress
serialization, and no Puzzle/Platformer/Top-Down template. Next recommended
prerequisite is hierarchy/world-transform composition and a project-backed
Scene/asset preview. Stop here for manual confirmation before starting it.
