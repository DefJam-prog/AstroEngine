# 06.51 — Staged journal archive interruption tests

## Scope and implementation

Added subprocess integration tests for the 06.50 staged archive. The test starts the integration executable as a child and terminates it at three boundaries:

1. After writing the first half of the staging bytes.
2. After the complete staged file was flushed and verified, but before final-path publication.
3. After final-path publication, before normal staging-name cleanup.

The callback and entry point live in the private `PuzzleCampaignSaveAdapterTestHooks.hpp`; the normal archive API signature is unchanged and no environment-variable control was added. The parent test verifies each resulting staging/final state, retries archival, and checks that the malformed source journal and candidate slot remain byte-for-byte unchanged. CTest timeout for this integration target is 60 seconds; each child wait is bounded to ten seconds.

Expected outcomes verified by the test:

- Partial write: no final archive; partial staging bytes remain. Retry publishes the exact archive and leaves old residue untouched.
- Verified before publish: no final archive; complete staging bytes remain. Retry publishes the exact archive and leaves old residue untouched.
- Published before staging cleanup: the final archive already contains the exact bytes. Retry is idempotent. POSIX retains a staging hard link at this boundary; Windows has moved the staging file to the final name.
- In every case, the malformed journal and the slot-looking candidate file retain their original bytes.

These are real process terminations (`TerminateProcess` on Windows, `SIGKILL` on POSIX), not simulated errors returned by the archive code.

## Limitations

- Process termination does not model kernel crash, sudden power loss, storage-controller caches or filesystem corruption.
- The POSIX test passed on this WSL Ubuntu filesystem; other POSIX filesystems may have different durability guarantees. The implementation still fails closed if same-directory hard-link publication is unsupported.
- Windows full CTest covered the 40 tests registered by this Release configuration; optional SDL Editor, Game UI demo and C# host targets were disabled.
- This step does not repair a pre-existing partial archive at the deterministic final path; such an occupant remains a manual-review case.
