# 06.52 — Legacy final-archive conflict assessment

## Scope

This is a read-only policy assessment of an existing occupant at the deterministic final path used for malformed campaign-transfer journal archives. No runtime, Editor, test or CMake behavior changed. Only this report and project documentation were updated.

## Findings

- The final archive name is derived from a 64-bit FNV-1a fingerprint of the reviewed journal bytes. It is a bounded change-detection/name lookup value, not a cryptographic ownership proof. Distinct inputs can collide, and the filename does not establish which process created an occupant.
- A readable regular file whose bounded bytes exactly equal the reviewed source journal is safe to reuse under the existing checks.
- Any different occupant is ambiguous. It may be a partial file from the old 06.49 direct-to-final implementation, unrelated user data, a manually edited archive, or a fingerprint collision. A byte-prefix match increases no provenance guarantee: arbitrary user data can share a prefix.
- Directories, symlinks/reparse points, unreadable files, and oversized files are also not safe to open as an archive or replace. Current code fails closed and preserves them. Save slot files are not accessed by this archive operation.
- The Editor surfaces the runtime error text, but there is no dedicated conflict report with the expected archive path and no-follow file details.

## Recommended operator workflow

Keep exact-copy reuse and fail-closed behavior. For future Editor diagnostics, inspect without following links and report: expected path, file kind, byte size, whether it is readable within the existing bound, and a bounded comparison category (`exact match`, `different`, `prefix match`, or `unavailable`). Label every differing occupant as unknown; a prefix match describes bytes only and must not be called a verified interrupted archive. Show that no files were changed and keep the malformed source journal available for manual review.

Until such diagnostics exist, the operator must inspect an unknown occupant outside the engine. After independently deciding how to preserve/resolve it, the operator may clear the deterministic destination path and retry archival. The application must not delete, move, truncate, overwrite or auto-clean a differing occupant. The source journal and all save slots remain untouched.

## Decision

No safe automatic recovery or ownership classification can be made from a partial file's length, prefix or deterministic name. Preserve the unknown occupant and keep manual review. A future substage may implement read-only diagnostics with no-follow metadata and bounded comparison; any removal/move/replace workflow needs separate design, explicit user action and tests.
