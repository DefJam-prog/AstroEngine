## Code path reviewed

`PuzzleCampaignSaveAdapter.cpp` uses `openat`, `fstatat` with `AT_SYMLINK_NOFOLLOW`, `O_NOFOLLOW`, `O_DIRECTORY`, inode/device identity checks, `flock`, exclusive same-directory staging, `linkat` for no-replace publication, and `unlinkat` for staging cleanup/acknowledgement. It attempts `fsync` on staged file and directory. `SaveStore.cpp` also flushes its temporary save file with `fsync` before rename.

These calls are present in Apple's Darwin API documentation. `O_NOFOLLOW` rejects a symlink at the final component; descriptor-relative operations reduce races after a parent directory is opened. They do not by themselves establish safety for untrusted ancestor path components. `flock` is explicitly advisory: only cooperating processes honor it. Apple's `link(2)` documentation specifies atomic hard-link creation and requires source and destination on the same filesystem; this code stages and publishes in the same parent directory, but the actual volume/provider still matters.

## Durability finding

The implementation checks `fsync` return values but the result must not be presented as power-loss durability on macOS. Apple's `fsync(2)` documentation warns that writes may remain in device cache and may be reordered or lost after power failure. Apple documents `F_FULLFSYNC` as a stronger device flush request, but it is Apple-specific, can be slow, and may be ignored/unsupported by some filesystem/device combinations. Whether directory `fsync` succeeds and what it guarantees on the supported macOS/APFS target was not tested here. This is the main platform-specific acceptance question, not proof that the current behavior fails.

## Recommendation and required validation

Keep the current code/API unchanged until there is a macOS host/CI runner. On a supported macOS release and APFS, compile the existing POSIX path and run focused plus full Release CTest. Record separately: file `fsync`, directory `fsync` result/errno, collision-safe hard-link publication, Unicode path round trip, symlink rejection, active lease contention, and child-process interruption before and after publish. Repeat the directory flush observation on any additional officially supported filesystem/provider. Define product durability wording from observed results; do not claim power-loss safety from normal process termination tests. If any system lacks a required no-follow primitive, fail closed at configuration/runtime rather than silently compiling that safety check away.
