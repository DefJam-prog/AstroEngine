# Подэтап 06.7 — PuzzleSnapshot через выбранный SaveProfile

## Что сделано

- Добавлен optional `astro_runtime_puzzle_save`, который связывает Puzzle runtime с SaveStore, не добавляя зависимость файлового SaveStore в `astro_runtime_puzzle`.
- `selectPuzzleSnapshotField` явно добавляет строковый ключ `puzzle.snapshot` (или заданный пользователем key) в SaveProfile.
- `savePuzzleSnapshot` записывает состояние `PuzzleGame::snapshot()` в этот ключ; остальные выбранные custom values остаются явными аргументами вызывающего кода.
- `loadPuzzleSnapshot` загружает Scene-кандидат, декодирует versioned payload и восстанавливает PuzzleGame. Исходная Scene публикуется только после успеха всех стадий.
- Payload `ASTRO_PUZZLE_SNAPSHOT 1` содержит правила/размер, score/level, tile IDs в hex и RNG state. Payload ограничен 64 KiB, размеры и палитра валидируются; неизвестная версия и повреждённые данные отклоняются.
- Добавлен integration CTest с round-trip Scene + Puzzle + дополнительного custom значения, сравнением следующего хода/refill, отказом для невыбранного/нестрокового snapshot поля, неизвестной версии и повреждённых tile данных. Ошибки payload не меняют исходную Scene.

## Ограничения и известные проблемы

- Payload version 1 пока не имеет мигратора; неизвестная версия даёт `VersionMismatch`.
- Adapter предназначен для явного кода runtime/save. GUI-профили, Play integration, проектный шаблон Puzzle и process-restart/export smoke не добавлены.
- SaveStore ограничивает custom string 64 KiB; текущая Puzzle-модель ограничивает доску 4096 клетками.
- Профиль с дополнительными custom keys должен передавать все их значения при save; при load они возвращаются в `additionalCustomState`.
- Проверена локальная Windows/MSVC конфигурация. Другие платформы и компиляторы не проверялись.

Следующий рекомендуемый подэтап после ручного подтверждения: добавить минимальный playable Puzzle Game View workflow поверх существующего runtime/session и проверять его отдельным smoke-тестом; не смешивать это с текущим SaveStore adapter.
