# Editor Scene/Game View renderer integration

## Scope

Connected the current Canvas2D -> Scene sprites -> SDL3 renderer pipeline to both Windows Editor preview windows. Preserved the existing bgfx/ImGui renderer and the structural hierarchy map. No gameplay systems were added.

## Changes

- Scene View has a **Rendered** tab and keeps **Hierarchy map**.
- Game View renders the authoring Scene when stopped and the isolated `RuntimeSession` copy while playing. Buttons provide Play, Pause/Resume, single Step, and Stop.
- Each pane uses a bounded SDL software surface (maximum 1280x720), WIC-backed `SDLImageTextureCache`, and BGRA upload to a bgfx texture shown through ImGui.
- Editor builds now request the optional 2D renderer targets even when `BUILD_TESTING=OFF`.
- Updated `RENDERER_2D.md`, architecture, roadmap, status, decisions, testing notes and README.

## Verification

Baseline before edits: `cmake --build build/stack-spike --parallel 4` reported no work; CTest passed 37/37.

After edits:

```powershell
cmake --build build/stack-spike --target astro_editor --parallel 4
ctest --test-dir build/stack-spike --output-on-failure
```

The editor target linked successfully after adding the existing `astro_runtime_session` library. The first link attempt exposed that missing link dependency; it was corrected. Full Debug CTest passed 37/37. `editor.smoke` asserts successful rendered frames in both panes plus a separate runtime Scene copy. In the existing `BUILD_TESTING=OFF` Release tree, the new renderer dependencies built with no work after target generation. Logs: `build/06.8-editor-build.log`, `build/06.8-editor-ctest.log`, `build/06.8-production-renderer-targets.log`.

## Limits

- RuntimeSession's fixed-step callback is empty. Play controls currently exercise the isolated runtime lifecycle but do not execute physics, input, animation, interaction, or gameplay.
- Per-frame full-surface CPU upload to bgfx is an integration bridge and has not been performance-measured.
- Only SpriteRenderer assets appear; there are no selection/gizmo/collider/UI overlays or visual golden tests.
- WIC makes this decoder path Windows-only. A non-Windows decoder and final GPU rendering adapter remain future work.
- Production Release Editor executable was not linked; its dependency cache may not contain release bgfx binaries.

## Recommended next substep

Measure Scene/Game View frame time with representative scenes, then choose and validate a GPU-backed upload/render path before adding more editor overlays or gameplay connections.
