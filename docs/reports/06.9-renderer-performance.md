# Scene/Game View performance baseline and GPU path

Date: 2026-11-13

## Benchmark method

Added `astro_editor --benchmark`. It initializes the real Windows Editor D3D11/bgfx backend, creates a uniquely named temporary project and cached 1x1 PNG, then benchmarks synthetic scenes with 1, 100 and 1000 visible SpriteRenderer entities. Every entity uses the same asset; transforms form a simple grid. Both Scene and Game targets are rendered at 960x540. Each scenario runs 8 warm-up and 40 measured frames. The temporary project is removed after the run.

Measured separately: scene-to-Canvas preparation and auto-fit, SDL software rendering, and CPU time for bgfx upload submission (`bgfx::copy` and `bgfx::updateTexture2D`). The values do not include GPU transfer completion, ImGui composition, or the editor's vsync frame duration. They are one local MSVC Debug / Direct3D 11 run, not target budgets.

## Results

| Sprites | View | Prepare p50 | SDL software p50 | Upload submit p50 | Total p50 | Total p95 |
|---:|---|---:|---:|---:|---:|---:|
| 1 | Scene | 0.058 ms | 0.130 ms | 0.879 ms | 1.072 ms | 1.455 ms |
| 1 | Game | 0.032 ms | 0.114 ms | 0.888 ms | 1.046 ms | 1.381 ms |
| 100 | Scene | 0.840 ms | 0.306 ms | 0.757 ms | 1.974 ms | 2.337 ms |
| 100 | Game | 0.376 ms | 0.273 ms | 0.694 ms | 1.351 ms | 1.863 ms |
| 1000 | Scene | 5.338 ms | 1.974 ms | 0.690 ms | 7.995 ms | 9.122 ms |
| 1000 | Game | 4.312 ms | 2.162 ms | 0.734 ms | 7.378 ms | 9.148 ms |

At 1000 sprites the paired median is about 15.37 ms CPU, close to the 16.67 ms budget for 60 FPS before main UI work. Paired p95 is about 18.27 ms when summing each pane's p95; this is a conservative estimate, not a measured paired percentile.

The full-frame upload at 960x540 is 2,073,600 bytes per view. Two views upload 4,147,200 bytes per frame, about 237.3 MiB/s at 60 FPS. At the 1280x720 surface cap this would scale to about 421.9 MiB/s. The upload submission measurements include a CPU-side copy into bgfx memory; actual GPU copy time is unmeasured.

## Selected GPU route

Use direct bgfx rendering into one framebuffer attachment for Scene and one for Game. Convert the existing backend-neutral sprite corners to transient GPU vertex/index buffers, sample the Editor's existing bgfx asset textures, and draw those view IDs before ImGui. ImGui then displays each framebuffer attachment. This removes software rasterization and whole-frame CPU upload; it does not require GPU readback. Batch adjacent sprites by layer and texture when that preserves order.

Keep SDLCanvas2DRenderer for its standalone/runtime adapter use. The GPU route is an editor presentation adapter around the same Canvas2D/SceneSprite commands; it should not replace the renderer-neutral scene composition contract.

Before switching, compare p50/p95 on these same cases and verify texture orientation, alpha, nested affine transforms, resize/recreate, missing-asset diagnostics, and that Scene/Game attachments are isolated. Add a small visual golden test. This report selects the route but does not implement it.
