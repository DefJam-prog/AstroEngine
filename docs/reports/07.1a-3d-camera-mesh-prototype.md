# 07.1a — 3D camera, mesh data and bgfx smoke

## Scope

Added the first optional 3D data contract without changing Scene serialization or runtime/editor APIs. The core target remains independent of SDL/bgfx and imports no new dependency. The graphics sample reuses existing local SDL3/bgfx libraries and bgfx's cached D3D11 cube shader binaries.

## Changes

- `engine/render3d`: `astro_runtime_render3d`, a backend-neutral `Camera3D` and indexed `MeshData` API.
- Camera contract: right-handed view, +Y up, default look direction -Z; column-major matrices; configurable [0,1] or [-1,1] projection depth; finite and degenerate input validation.
- Mesh contract: bounded vertex/index counts; triangle-list shape; finite positions; index-range validation; deterministic colored cube fixture.
- `samples/3d_prototype`: optional SDL3/bgfx D3D11 rotating cube window. It reads official cached `vs_cubes.bin`/`fs_cubes.bin` and copies them only into the ignored build tree.
- Unit coverage checks camera matrix behavior, invalid pose/projection values, mesh bounds and malformed indices. CTest smoke creates GPU resources, requests a backbuffer readback, checks coarse foreground pixels/color diversity/bounds, and reports frame-interval percentiles.

## Verification

Windows x64 Release, VS 2022/MSVC:

```powershell
cmake -S . -B build/06.53-editor-release -DASTRO_BUILD_RENDER3D=ON -DASTRO_BUILD_RENDER3D_BGFX_SMOKE=ON
cmake --build build/06.53-editor-release --parallel 8
ctest --test-dir build/06.53-editor-release -R "runtime.render3d.(camera_mesh.unit|bgfx.smoke)" --output-on-failure
ctest --test-dir build/06.53-editor-release --output-on-failure
```

Results before the readback extension: configuration succeeded; Release build completed 161/161 Ninja actions; focused CTest 2/2 passed; full CTest 46/46 passed. Three pre-existing C4189 warnings remain in `editor/main.cpp`.

The readback extension was built as `astro_render3d_bgfx_smoke`; focused CTest passed 1/1. Three direct smoke runs produced identical pixel results: 85,155 foreground pixels, 169 color buckets and bounds 280,135–658,498. Their CPU frame-interval p50 values were 16.701/16.735/16.764 ms (median 16.735 ms); p95 values were 32.824/34.120/32.055 ms (median 32.824 ms). The smoke requires more than 500 pixels outside the known clear color, at least four coarse RGB buckets and an in-bounds region. It does not save an image or compare exact pixels against a golden image. The complete Windows Release rebuild after the readback change completed 161/161 Ninja actions and full CTest passed 46/46 in 13.94 s. These frame intervals are one rotating cube with VSync and are only a baseline, not complete scene frame time or a performance budget.

Existing compiler warnings in unrelated runtime sources remain outside this substage.

## Known limits

The readback is a coarse pixel-presence and region test, not a golden-image or exact color-layout test. The timing sample is one tiny rotating cube with VSync; it does not represent full frame time for a game scene and establishes no performance budget. The cube has vertex colors only; it does not validate normals, textures, materials, lighting, scene loading or editor display. The API has not been compiled on macOS or mobile targets. Scene format remains unchanged.
