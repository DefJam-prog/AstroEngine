# 07.1b — bounded glTF/GLB static geometry importer

Date: 2026-11-17  
Platform: Windows 11 x64, Visual Studio 2022 Build Tools 17.14.45, MSVC 19.44.35230.0, CMake 4.4.4, Ninja, Release.

## Scope

Implemented only the importer/cache slice of roadmap 07.1b. The feature is opt-in and returns backend-neutral mesh data. It does not change Scene, AssetRegistry, project asset-index or serialized scene formats. It does not add a 3D Editor viewport or physics system.

## Changes

- Added `astro_gltf`, gated by `ASTRO_BUILD_GLTF_IMPORTER` (default OFF).
- Added `astro::render3d::GltfImporter::importFile(projectRoot, sourceRelativePath)` and result types in `engine/render3d/include/astro/render3d/GltfImporter.hpp`.
- Added bounded `.gltf`/`.glb` parsing and geometry extraction. Supported primitives use float VEC3 `POSITION`, optional unsigned triangle indices, or non-indexed triangle positions. Geometry is validated through the existing `MeshData` contract.
- Accepted project model paths only beneath `Assets/`; external buffer URIs must be plain relative paths resolving to regular files beneath `Assets/`. URI traversal, absolute/remote paths, link/reparse components, unsupported required extensions and unsupported geometry are rejected. Source files are read only.
- Added bounded geometry cache under `Library/Derived/gltf`, with content-derived identity, schema marker, checksum, size validation and corrupt-entry rebuild. Cache writes stage a sibling temporary file and publish atomically on the tested Windows filesystem.
- Added `runtime.render3d.gltf.import.integration` with data URI and GLB fixtures, external Unicode/percent-encoded path handling, cache reuse/corruption, source preservation, malformed/unsupported inputs, path traversal and limits. Link-preservation checks run where the host can create a link.
- Staged fastgltf v1.0.1, simdjson 5.1.0 and simdutf 9.3.3 only under ignored `build/07.1b-deps`. CMake verifies the fastgltf Git commit and four SHA-256 values. Its automatic downloads and optional upstream examples/tests/docs/install are disabled. No system installation, tracked vendoring, push or commit occurred.

Explicit limits currently enforced by the adapter include 8 MiB source, 64 MiB per external buffer, 128 MiB total external buffers, 128 meshes, 256 primitives, 1,000,000 total vertices, 3,000,000 total indices and 64 MiB per cache file.

## Known limitations and risks

- This is not full glTF 2.0 support. Normals, UVs, tangents, colors, materials, textures/images, node transforms/hierarchy, animation, skinning, morph targets, Draco and physics are not imported. Unsupported required extensions fail explicitly.
- Meshes are not AssetRegistry records, do not enter the dependency graph/package builder, are not serialized in Scene and are not drawn by Editor/runtime views.
- Filesystem checks reject ordinary traversal and symlink/reparse escapes, but they inspect paths and then open them conventionally. A hostile concurrent local process may race path replacement; this is not a filesystem sandbox.
- No fuzzing, sanitizer, malformed corpus campaign, macOS, Linux, Android or iOS build was run. The fastgltf parser is not claimed vulnerability-free.
- The build emits warnings from fastgltf third-party headers under MSVC (`C4458`/`C4456`); they did not fail the build. No warning was presented as a project test failure.
- Atomic cache publication was validated on the tested Windows filesystem; durability under power loss and other filesystems is not established.
