# 07.1b — Bounded glTF/GLB importer dependency assessment

Date: 2026-11-16

## Scope and outcome

This is a dependency/security assessment for the next 07.1 importer slice. No production code, public API, Scene schema, tests, downloaded sources or project assets were changed. The 07.1a camera/mesh/bgfx prototype remains separate from the existing image/script AssetRegistry.

The local dependency cache contains `build/spike-deps/bgfx/3rdparty/cgltf/cgltf.h`, whose header identifies itself as cgltf 1.15. I do not recommend using that vendored copy as the parser for arbitrary project assets: upstream issue [#287](https://github.com/jkuhlmann/cgltf/issues/287) remains an open report of integer-overflow and out-of-bounds reads in sparse-accessor validation for v1.15. Related public reports [#288](https://github.com/jkuhlmann/cgltf/issues/288) and newer issue listings show additional parser/accessor concerns. These issue reports are risk evidence, not proof that every version or parser call is affected; the relevant point is that an untrusted asset parser should not be adopted without a version-specific security review and adversarial tests.

Recommended candidate for a bounded prototype: released [fastgltf v1.0.1](https://github.com/spnda/fastgltf/tree/v1.0.1), whose project describes C++20 support and MIT licensing. The release CMake declares automatic downloads ON by default for simdjson and simdutf. Its pinned dependency script selects simdjson 5.1.0 and simdutf 9.3.3 when those packages are not already found. This means configuring the candidate as-is can initiate network downloads; a project integration must explicitly prevent that behavior and stage or find the exact dependency sources under an approved policy. Keep optional upstream examples/tests disabled to avoid fetching extra glm/Catch2 dependencies. The reviewed library and parser-helper licenses are MIT.

This is a recommendation to prototype, not a claim that fastgltf is vulnerability-free or production-approved. The parser's own validators do not replace engine-level input budgets and path confinement.

## Existing asset-pipeline boundary

The current `AssetRegistry` registers bounded PNG/JPEG image sources and C# script references. Its image cache retains encoded bytes, and package building includes the supported image payloads. There is no model asset type, generic binary asset record, glTF URI resolver, mesh cache format or Scene mesh reference. Extending the image API to pretend it handles models would mix incompatible validation and derived-data contracts. The importer should therefore begin behind a distinct optional model-import adapter and avoid Scene serialization changes in the first slice.

## Proposed implementation guardrails

- Opt-in CMake target/module; default headless/editor/runtime configurations must not require the parser or dependencies.
- Initial scope: `.gltf` JSON and `.glb` container parsing, static triangle mesh primitives and a small explicit attribute set. Document unsupported animation, skinning, morph targets, compression and extensions; reject required unsupported extensions.
- Put hard limits on source bytes, JSON depth/tokens, buffers, buffer views, accessors, vertices, indices, primitive count and total decoded bytes before allocations.
- Do not let the parser open arbitrary external resources. Resolve each external buffer URI in engine code against the canonical project root; reject absolute paths, traversal, unsupported URI schemes, symlink/reparse escapes, oversized files and inconsistent declared/actual lengths. Ignore or reject image URI loading in the first slice.
- Preserve original source files. Hash source plus importer/cache schema version; publish generated mesh cache to a temporary sibling and atomically replace only the engine-owned cache entry. Verify integrity on reuse and do not delete old cache entries as part of first import.
- Tests must include valid minimal `.gltf` and `.glb`, malformed/truncated JSON/container, wrong magic/version/length, missing and oversized buffers, traversal/absolute/data URI policy, path separators and Unicode, integer/size overflow boundaries, empty/invalid accessors, unsupported required extension, corrupted/reused cache, reimport identity and source-byte preservation. Run sanitizer and bounded fuzz tests when the toolchain supports them.
- Keep outputs backend-neutral; add no bgfx handle to imported asset data. Renderer upload, Scene component/versioning and Editor viewport hookup remain later slices.

## Verification and remaining gate

No code changed in this assessment, so no new test was expected. The immediately preceding Windows x64 Release state rebuilt the 3D smoke successfully (161/161 Ninja actions) and full CTest passed 46/46 in 13.94 s. Three direct D3D11 smoke runs each reported 85,155 foreground pixels, 169 coarse color buckets and bounds 280,135–658,498. Median frame-interval p50 was 16.735 ms (range 16.701–16.764 ms); median p95 was 32.824 ms (range 32.055–34.120 ms). This is a single VSync cube baseline, not a representative workload. WSL Release CTest 40/40 in 0.77 s belongs to the source state before the Windows-only readback change; WSL was not rerun after that edit.

No dependency acquisition is included here. The next importer implementation requires permission to download/stage fastgltf v1.0.1, simdjson 5.1.0 and simdutf 9.3.3 in the ignored local `build/07.1b-deps` directory, or a decision to use already available verified local package sources. This does not imply changing system PATH/registry, vendoring third-party files into tracked source, or network activity during ordinary CMake builds.
