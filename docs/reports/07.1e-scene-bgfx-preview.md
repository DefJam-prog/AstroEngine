# 07.1e — Standalone Scene Mesh BGFX preview

## Scope

Consume one validated Scene `MeshRenderer` in the optional Windows D3D11/BGFX sample and verify that its selected static primitive appears in framebuffer readback. This does not integrate the 3D path into Editor Scene/Game View or gameplay runtime.

## Implementation

- Extended `astro_render3d_bgfx_smoke` with an opt-in `--scene-smoke --project-root <path>` mode when the glTF importer is enabled.
- The mode opens AssetRegistry, imports/registers the fixture glTF, loads the serialized Scene v6, verifies its single visible MeshRenderer references the resulting Model AssetId, resolves it through `resolveMeshRenderer`, uploads the selected geometry and renders it with BGFX/D3D11.
- Preserved the procedural cube smoke and verified it still builds and runs when `ASTRO_BUILD_GLTF_IMPORTER=OFF`.
- Added a glTF/Scene fixture and CTest wrapper. The wrapper makes a unique temporary project under the build tree, copies only fixture Assets/Scenes, checks the selected model/index report and pixel-readback metrics, then removes that test-owned directory.
- Added explicit preview limits: 65,536 vertices and 196,608 indices using 16-bit BGFX index data. The selected primitive draws without back-face culling and uses an identity model matrix; Scene transforms and hierarchy are not applied.

## Baseline and verification

Before changes, the importer Release build was up to date and full CTest passed **42/42 in 2.56 s**. The existing editor build completed; focused procedural BGFX and Editor smoke passed **2/2**.

Fresh opt-in Release configure succeeded using the existing ignored local dependency caches. The first compile caught an incorrect structured binding over `Scene::entities()` (a vector); this was corrected to iterate the entity vector directly. Retry completed the sample build. Focused Release graphics tests passed **2/2**; the new Scene smoke passed and reported:

## Limitations

- Visual verification is Windows x64/D3D11 only. No macOS, mobile or second graphics backend was built.
- Pixel thresholds are coarse and fixture-specific; this is not a golden-image test.
- No real project assets are rewritten; CTest runs on a temporary copy. This smoke does not exercise hostile filesystem races or production project loading UX.
- No Editor Scene/Game View, gameplay runtime, Scene Transform/hierarchy, multiple objects, materials/textures, normals/UVs, lighting or animation are implemented in this substage.
