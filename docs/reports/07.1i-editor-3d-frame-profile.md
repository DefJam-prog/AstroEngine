# 07.1i — Editor 3D frame profile

## Scope

Added an opt-in Windows Editor command, `astro_editor.exe --benchmark-3d`, and a CTest smoke for the optional glTF-backed Scene View renderer. This substage establishes measurements for the Stage 07.1 “editable 3D scene with measured performance” acceptance point. It does not optimize geometry or set a target hardware budget.

The benchmark copies the checked-in triangle glTF fixture into an owned temporary project and creates visible 3D mesh grids with 1, 100, 500, and 1000 MeshRenderer entities under hierarchy roots. It records model import and scene construction separately. For each scenario it renders 24 warm-up frames and measures 48 frames at a 617×376 Scene View target.

## Measurements

Windows x64 Release, BGFX D3D11, three direct runs on this host, no other workload intentionally started. The executable was 7,663,616 bytes. Import took 7.86–7.99 ms. Constructing the 1000-mesh scene took 0.87–0.91 ms. The 1000-mesh scenario used 73.8–74.1 MiB process working set and 113.7–114.0 MiB private bytes at the time sampled. These process memory values include the editor and its other systems; GPU memory is not included.

The per-frame report also exposes CPU mesh preparation vs submission, Scene 3D CPU phase, editor CPU before `bgfx::frame`, CPU duration inside `bgfx::frame`, BGFX GPU timer, draw calls, and exact mesh submissions. At 1000 meshes in run 3, prepare p50/p95 was 1.3752/1.9503 ms, submit was 0.0440/0.0919 ms, combined Scene 3D CPU was 1.4192/1.9935 ms, and total Editor wall frame was 16.6710/17.1247 ms.

The roughly 16.7 ms complete frame is VSync-limited on this setup. The BGFX GPU timer spans the complete window frame and tracks the same VSync cadence; it is not a measurement of the isolated 3D GPU pass. FPS is derived from wall-time p50 and does not establish uncapped throughput. The result is a local baseline, not a cross-platform claim or acceptance budget.

## Known limitations

- Validated only on this Windows x64 Release / D3D11 environment; no macOS, Linux, mobile, alternate GPU backend, or headless profile validation was performed.
- VSync caps the observed complete frame near 60 Hz, so the measurements do not show maximum rendering throughput.
- BGFX's timer in this path covers the full window frame, not only the 3D pass; GPU work and wait time cannot be isolated with this report.
- The test geometry repeats one tiny triangle fixture and is a controlled draw/CPU scaling probe, not representative production art, materials, overdraw, shader cost, or a real game scene.
- No budget is approved, and the smoke deliberately checks report completeness rather than timing thresholds.
- Static geometry/color path remains limited: no materials, normals, lighting, picking, or Game View/runtime integration.
