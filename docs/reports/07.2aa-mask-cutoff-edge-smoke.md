# 07.2aa — MASK cutoff-edge UNORM8 mip smoke

## Scope

Test the cutoff boundary for actual 8-bit texture samples through the Windows Editor Scene View mipmapped MASK path. Keep all generated test PNGs inside disposable smoke projects. Do not change renderer policy, material schema, runtime API or user assets.

## Implementation

Added six CTest cases for constant magenta RGBA textures with alpha byte 127, 128 or 129, each at UV scales 2 and 4. They use the existing MASK material, cutoff 0.5, Repeat sampling and `LinearMipmapLinear` filtering. Every case asserts at least one mipmapped MASK submission. Alpha 127 must be discarded (under 8 diagnostic-magenta pixels and visible blend-through); bytes 128 and 129 must remain visible (at least 32 magenta pixels). Editor smoke output reports the tested alpha byte and cutoff.

An 8-bit UNORM channel cannot encode exactly 0.5: 127/255 is below, 128/255 is the first representable value above it, and 129/255 is the next. Existing factor-only cutoff tests continue to exercise the shader's below/equal/above float comparison separately.

## Limits

These are broad pixel assertions for the current D3D11 adapter, not image goldens or exact hardware-LOD inspection. Constant-alpha images confirm cutoff behavior after mip generation/upload but do not prove visual behavior for arbitrary alpha patterns, other GPU drivers, graphics backends or platforms. Exact 0.5 cannot be represented in UNORM8 texture data.
