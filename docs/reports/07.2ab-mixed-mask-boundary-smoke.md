# 07.2ab — mixed MASK cutoff boundary stripes

## Scope

Check simultaneous below-cutoff discard and passing MASK coverage within one spatially mixed mip-filtered texture in the existing Windows Editor Scene View path. The generated PNG exists only inside the disposable smoke project. No runtime API, renderer policy, material schema, dependency or user asset is changed.

## Implementation

Added two CTest cases using a generated 64×64 magenta RGBA texture with four vertical alpha bands: 127, 128, 129 and 127. They use MASK cutoff 0.5, Repeat sampling, `LinearMipmapLinear`, and UV scales 2 and 4. Each test requires one mipmapped MASK submission, a broad visible MASK pixel range and visible blend-through pixels from the underlying mesh.

## Results

| UV scale | MASK magenta pixels | Blend-through pixels | Mipmapped MASK submissions | Result |
| ---: | ---: | ---: | ---: | --- |
| 2 | 358 | 303 | 1 | pass |
| 4 | 378 | 252 | 1 | pass |

Both types of output coexist in each captured Scene View region. This is a broad pixel-count smoke; it does not correlate output pixels with specific source stripe coordinates.

## Limits

The test runs on the current Windows D3D11 adapter. It does not inspect the selected hardware mip LOD, compare exact pixels to a golden image, prove which output pixels came from a particular alpha band, or establish other driver/backend/platform behavior. UNORM8 values 127/255 are below 0.5 while 128/255 and 129/255 are above it; exact 0.5 is not representable as an alpha byte.
