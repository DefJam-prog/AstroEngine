# 07.2ae — spatial MASK smoke across window sizes

## Scope

Extended the 07.2ad alpha-ramp Scene View smoke matrix to cover three logical window sizes and reworked its spatial assertions to use coverage ratios per sampled bin. No runtime rendering API, material format, or renderer policy changed.

The six smoke cases exercise near/far UV scale at 1100×720 (default), 900×650 (compact), and 1440×900 (large, requesting `SDL_WINDOW_HIGH_PIXEL_DENSITY`). The Editor reports logical window size, BGFX pixel size, SDL pixel density, and whether high-density mode was requested.

The 64 vertical bins count crop sample pixels and MASK/blend-through pixels. A bin is mask-rich or blend-rich based on its normalized coverage and 2:1 dominance over the other class. The assertion requires at least two bins in each class and at least three transitions. It does not require the first rich bin to be blend-through: observed far-scale patterns can start with a mask-rich bin while still containing the expected alternating regions.

## Validation

Environment: Windows x64, MSVC 14.44, CMake/Ninja Release tree `build/07.2d-release-clean`, SDL 3.5.0, BGFX D3D11.

Focused command:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release -V -R '^editor\.scene_view_mask_mips\.cutoff_transition\.'
```

Result: **6/6 passed in 17.36 s**. The initial focused run found the over-specific “must start blend-rich” assertion in both far-scale cases. The assertion was corrected to require alternating spatial categories without fixing their first category; all six then passed.

Full regression command:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure
```

Result: **84/84 passed in 90.51 s**. The Release editor rebuild completed successfully. Existing compiler warnings in `editor/main.cpp` (C4456 and C4189) remain; this substage did not address them.

Observed SDL-reported window states:

| Profile | Logical window | Pixel size | Density | High-density requested |
|---|---:|---:|---:|---|
| Default | 1100×720 | 1100×720 | 1.0 | no |
| Compact | 900×650 | 900×650 | 1.0 | no |
| Large | 1440×900 | 1440×900 | 1.0 | yes |

The host display did not provide a framebuffer density above 1.0, so this verifies differing window/framebuffer dimensions and the requested SDL mode, but does not validate physical high-DPI scaling. It is a count-based Windows D3D11 smoke, not a golden-image, exact LOD, alternate-GPU, or cross-platform test.
