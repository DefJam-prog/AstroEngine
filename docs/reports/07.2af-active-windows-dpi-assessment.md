# 07.2af — active Windows DPI assessment

## Goal

Run the 07.2ae Scene View MASK alpha-ramp smoke on a real Windows display above 100% scaling and compare SDL-reported window pixel density to the logical window size. The user explicitly authorized temporary display scaling changes for this test.

## Procedure and observation

Both active displays were temporarily changed from 100% to 125% in Windows Settings. Windows logical desktop bounds changed from **1080×1920** and **2560×1440** to **864×1536** and **2048×1152**, consistent with 125% display scaling. The primary display was selected so that the smoke windows opened on a scaled monitor.

The six near/far ramp smoke cases then ran successfully. However, all six reported `pixelDensity=1.0`, with `windowPixels` equal to `windowLogical`; the profile requesting `SDL_WINDOW_HIGH_PIXEL_DENSITY` did the same. The smoke validated rendering while Windows scaling was set to 125%, but it did **not** demonstrate a high-density SDL/BGFX framebuffer. This result points to a DPI-awareness or window/backbuffer sizing issue that needs a separate technical step. No renderer changes were made in this test-only substage.

After the run, both changed display settings were returned to **100%**. During restoration, a UI selection briefly set the primary to 150%; it was immediately corrected to 100% and no test ran at 150%. `Screen.AllScreens` then again reported **1080×1920** for the primary and **2560×1440** for the secondary display. The secondary screen origin differs by one logical pixel from the earlier query due to Windows display-layout rounding; its resolution, scale, and visible arrangement are restored.

## Verification

Release build tree: `build/07.2d-release-clean`; `cmake --build build/07.2d-release-clean --config Release --parallel 8` reported `ninja: no work to do`.

Focused command at Windows 125% scaling:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release -V -R '^editor\.scene_view_mask_mips\.cutoff_transition\.'
```

Result: **6/6 passed in 17.94 s**. This is a successful functional smoke run, but high pixel density was not observed.

Full regression at the restored 100% scaling:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure
```

Result: **84/84 passed in 90.79 s**.

Logs: `build/07.2af-125dpi-focused-ctest.log` and `build/07.2af-final-ctest.log`.

## Remaining work

Investigate the Editor process DPI-awareness context and SDL/BGFX backbuffer sizing under Windows per-monitor scaling. Add a measured assertion that distinguishes a 1.25 pixel/logical ratio from Windows bitmap scaling, then repeat these six smokes. This implementation work is outside the current test-only substage.
