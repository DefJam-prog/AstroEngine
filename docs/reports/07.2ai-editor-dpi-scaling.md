# 07.2ai — DPI-масштабирование Editor UI

## Изменения

- Добавлен `EditorUiScalePolicy`: хранит копию исходного Dear ImGui style и при изменении SDL display scale восстанавливает базу, затем масштабирует style через `ScaleAllSizes()` и шрифт через `FontScaleMain`.
- Editor опрашивает `SDL_GetWindowDisplayScale()` перед каждым ImGui кадром. Изменение масштаба применяется к следующему кадру без накопительных коэффициентов и без перезапуска; переход логируется как `uiScaleChanged`.
- Editor smoke проверяет совпадение SDL display scale с применённым font scale/style padding и печатает наблюдаемые значения.
- Добавлен unit-тест для 100%, 125%, 150%, повторного scale, возврата к базе, некорректного значения и верхней границы.

`SDL_GetWindowPixelDensity()` и размеры BGFX swapchain не используются как UI scale. Ни SDL, ни Dear ImGui dependencies не менялись.

## Проверка

Окружение: Windows 11 x64, Visual Studio 2022 Build Tools 17.14.45, MSVC 14.44, SDL 3.5.0, Dear ImGui 1.93.1 WIP, Release Ninja tree `build/07.2d-release-clean`.

Build/reconfigure:

```powershell
cmd.exe /d /s /c 'call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\Tools\VsDevCmd.bat" -arch=x64 && cmake -S . -B build\07.2d-release-clean && cmake --build build\07.2d-release-clean --config Release --parallel 8'
```

Успешно. В первой компиляции Editor сохранились существующие предупреждения C4456/C4189; новый C4530 от iostream в тесте устранён заменой вывода на C stdio, финальная пересборка target завершилась без warning/error в сохранённом build log.

Фокусированные тесты:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release -V -R '^editor\.(ui_scale_policy\.unit|smoke)$'
```

- При восстановленных 100%: **2/2 passed**; smoke: `displayScale=1`, `uiScale=1`, `fontScale=1`, `windowPaddingX=8`.
- При временных реальных 125% на основном дисплее: **2/2 passed**; smoke: `displayScale=1.25`, `uiScale=1.25`, `fontScale=1.25`, `windowPaddingX=10`. HWND подтвердил DPI 120.
- До переключения живой Editor был открыт при 100%; после изменения системного scale его интерфейс обновился на 125% без перезапуска. После возврата 100% Win32 DPI снова 96 и live окно вернулось к исходному UI размеру. Второй активный дисплей оставался на 100%.
- Финальный полный тест после сборки на 100%: **85/85 passed за 109,00 с**. Лог `build/07.2ai-final-ctest-100dpi.log`; build log `build/07.2ai-build.log`.

Скриншот живого окна визуально просмотрен при 100% и 125%, но golden image не добавлялся. Системная настройка изменялась только временно после подтверждения; primary и secondary восстановлены на 100%.

## Ограничения

Scale ограничен диапазоном 1.0–4.0: invalid/нулевой scale fallback на 1.0, значения выше 4.0 clamp к 4.0, scale ниже 1.0 clamp к 1.0. App фиксирует базовый theme style во время инициализации; будущая runtime смена темы должна обновлять базовую копию. Узкая логическая рабочая область может обрезать фиксированные editor panels; adaptive workspace/layout не реализован. Отдельный перенос окна между двумя одновременно настроенными на разных scale мониторами, 150%/200%, другие ОС и многомониторные backend не проверялись.
