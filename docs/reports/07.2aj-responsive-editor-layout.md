# 07.2aj — адаптивная раскладка Editor

## Что изменено

- Добавлены `EditorWorkspaceLayoutPolicy.hpp/.cpp`: ограничение стартового окна запрошенным размером и usable work area; выбор compact режима при ширине меньше 1000 логических пикселей; bounded размер первой Game View.
- При создании окна SDL Editor запрашивает usable bounds основного дисплея, ограничивает размер окна и центрирует его на этом дисплее.
- SDL события `DISPLAY_CHANGED`, `DISPLAY_SCALE_CHANGED`, `RESIZED` обновляют рабочие границы. Окно, выходящее за новую usable area, уменьшается и возвращается внутрь; слишком большая существующая Game View уменьшается после события.
- При ширине окна меньше 1000 логических пикселей dock split становится compact: 20% Hierarchy, 27.78% правой группы от оставшейся ширины и 28% нижней Visual Logic области. Правая группа немного шире, а центральная область остаётся близкой к прежней ширине. `View → Reset layout` использует dock split текущей ширины. Обычный пользовательский dock layout при переносе окна автоматически не перестраивается.
- Unit-тест покрывает wide 1100×720, compact 864×720, границу 420×300 и некорректные размеры work area.

## Проверки

Среда: Windows 11 x64, MSVC 14.44, SDL 3.5, Dear ImGui 1.93.1 WIP, Release Ninja `build/07.2d-release-clean`.

```powershell
cmd.exe /d /s /c 'call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\Tools\VsDevCmd.bat" -arch=x64 -host_arch=x64 && cmake --build build\07.2d-release-clean --config Release --parallel 8'
ctest --test-dir build/07.2d-release-clean -C Release -V -R '^(editor\.workspace_layout_policy\.unit|editor\.smoke)$'
ctest --test-dir build/07.2d-release-clean -C Release -V -R '^editor\.smoke$'
ctest --test-dir build/07.2d-release-clean -C Release --output-on-failure
```

- Release build: прошёл. Первый вызов без `VsDevCmd.bat` не имел переменной `INCLUDE` и не находил стандартные заголовки; сборка прошла повторно в Developer environment без установки/изменения инструментов.
- Focused unit + Editor smoke при исходном 100%: **2/2 passed**. Editor сообщил окно 1080×720 и work area 1080×1872.
- Editor smoke при временных Windows 125%: **1/1 passed**, `displayScale=1.25`, `uiScale=1.25`, `fontScale=1.25`, paddingX=10; окно 1080×720, work area 1080×1860.
- После пересборки полный Release CTest при 125%: **84/86 passed за 103.89 s**. Компактные `cutoff_transition.compact.near/far` завершились сообщением `Scene/Game visual regression failed: screenshot lacks sprite colors`; повторные focused прогоны дали то же сообщение. Финальные TGA 900×650 содержали 171 ожидаемый зелёный пиксель и 0 красных/синих; причина отсутствия двух маркеров не установлена.
- Живое окно визуально перенесено на соседний экран Windows. Скриншот показал окно в пределах захваченной рабочей области, но фактические `SDL_GetWindowPosition`, display scale и usable bounds после переноса отдельно не логировались.

Логи лежат в игнорируемом `build/`: `07.2aj-release-build.log`, `07.2aj-focused-ctest-100dpi.log`, `07.2aj-editor-smoke-125dpi.log`, `07.2aj-compact-ctest-125dpi.log`, `07.2aj-final-ctest-125dpi.log`.

## Ограничения и открытые проблемы

- Два compact visual smoke падают на 125%; нельзя утверждать, что изменение раскладки прошло полный регресс. До изменений предыдущий подэтап имел полный прогон 85/85 на 100%, но после 07.2aj полный CTest при подтверждённых 100% пока не выполнялся.
- Windows Settings после 125%-ного прогона показывал пустое поле Scale; щелчок открывал Custom scaling. Глобальный custom scale не применялся, чтобы не менять нецелевые мониторы. Возврат системы к 100% не подтверждён; проверьте Settings → System → Display → Scale и установите 100% для исходного дисплея.
- Live-перенос не автоматизирован, разные DPI на активных мониторах отдельно не измерены. `SDL_GetDisplayUsableBounds` и логические пиксели — SDL backend-данные; macOS/POSIX не проверены.
- Dock ratios применяется при Reset layout/startup; автоматический dock rebuild при переносе намеренно отсутствует, чтобы не уничтожать созданную пользователем раскладку.
