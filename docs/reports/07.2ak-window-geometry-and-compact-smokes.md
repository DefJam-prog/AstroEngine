# 07.2ak — compact visual smoke и SDL геометрия окна

## Цель

Разобрать два компактных spatial MASK smoke, которые в 07.2aj падали на общей проверке красного/синего цвета, покрыть фактическое ограничение SDL окна по рабочей области и повторить полный Windows Release регресс.

## Изменения

- Добавлен `EditorWorkspaceLayoutPolicy::constrainWindow`: чистая функция ограничивает размер окна рабочей областью и прижимает координаты окна к её границам. Обработка SDL display/display-scale/resize events применяет её к текущему окну.
- Unit-тест геометрии дополнил случаи отрицательного начала координат дисплея, окна за левым/верхним и правым/нижним краем, размера больше рабочей области.
- Добавлен CTest `editor.window_geometry.sdl.smoke`. Он запускает настоящий SDL Editor, переносит окно за правую границу usable area, помещает в SDL очередь display-change event и проверяет, что обработчик вернул фактические координаты и размер в рабочую область. Это event smoke, а не hot-plug физического монитора.
- По исходному TGA 900×650 в обоих compact случаях обнаружено 0 красных, 0 синих, 171 blend-green пиксель. Визуальное исследование показало 3D mesh поверх 2D sprites. Компактные ramp smoke проверяют назначенные mesh/base-color/MASK/spatial-band критерии ниже по тесту, поэтому общий whole-window RGB assertion там не применим. Assertion оставлен в обычном `editor.smoke`; 2D композиция дополнительно проверяется `runtime.scene.render2d.integration`.
- Обновлены README, architecture, roadmap, status, testing и журнал решений D170.

## Сборка и проверки

Среда: Windows 11 x64, MSVC 14.44, CMake 4.4.4, Ninja 1.13.2, SDL 3.5.0, BGFX D3D11, Release, build tree `build/07.2d-release-clean`. SDL фактически сообщил `displayScale=1.25` и `pixelDensity=1.0`; обе величины различны. Компилятор использовался из Visual Studio 2022 x64 Developer Command Prompt.

Сборка:

```powershell
cmd.exe /d /s /c 'call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\Tools\VsDevCmd.bat" -arch=x64 -host_arch=x64 && cmake --build build\07.2d-release-clean --config Release --parallel 8'
```

Результат: Release build успешно завершился. MSVC сообщил существующие предупреждения о локальном `diagnostics` и неиспользуемых C# metadata UI переменных; ошибок компиляции/линковки нет.

Профильный прогон:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --output-on-failure -V -R '^(editor\.workspace_layout_policy\.unit|editor\.window_geometry\.sdl\.smoke|editor\.scene_view_mask_mips\.cutoff_transition\.compact\.(near|far)\.smoke)$'
```

Результат: **4/4 passed за 9,92 с**. Geometry smoke подтвердил `windowGeometryEvent=passed`. Compact near/far оба прошли все собственные 3D alpha/spatial assertions.

Полный регресс:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure
```

Результат: **87/87 passed за 108,06 с**. Логи лежат в игнорируемом `build/`: `07.2ak-release-build.log`, `07.2ak-focused-ctest.log`, `07.2ak-final-ctest-125dpi.log`.

## Системный масштаб и границы проверки

По ранее данному разрешению была сделана попытка возврата к 100% через Windows Settings. Страница Scale показывала пустое поле и переходила в Custom scaling. Настраиваемое глобальное значение не вводилось и не применялось; после попытки Settings оставлено на обычной странице System → Display. SDL по последующим smoke всё ещё сообщил `displayScale=1.25`. Поэтому системный масштаб не объявляется восстановленным, и полный тест при подтверждённых 100% после изменений не проведён.

Не проверялись реальный hot-plug/перенос между мониторами с разными DPI, macOS/POSIX, оконные декорации за границей usable area, сохранённые пользовательские dock-layouts. Автоматический smoke синтезирует SDL display-change event в текущем Windows процессе.
