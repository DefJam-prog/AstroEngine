# 07.2am — Scene Camera3D component и надёжная MSVC/Ninja пересборка

## Цель

Добавить персистентную перспективную камеру как типизированный компонент Scene и проверить безопасную миграцию формата. Одновременно расследовать CTest segfaults, появившиеся при инкрементальной пересборке изменённого Scene header.

## План и границы

Зависимости: существующие Entity/Transform, Scene serializer, stable ComponentId, unit/integration инфраструктура и backend-neutral camera math. Новый внешний пакет не требуется.

Решение: хранить FOV и clipping planes в `Camera3DComponent`, а позу считать частью Entity Transform; не выводить из этого готовое рендер-поведение. Обновлять Astro Scene до v8, сохраняя чтение v1–v7; старые сцены не получают отсутствующий компонент автоматически. Game View, активный camera resolver, transform-to-view matrix и Inspector отложены.

## Изменения

- `Camera3DComponent`: стабильный ID, schema v1, `verticalFovDegrees`, `nearPlane`, `farPlane`.
- `Scene::setCamera3D` отклоняет неfinite значения, FOV вне открытого диапазона (0,180) и clip plane values вне `0 < near < far`; отказ сохраняет старое состояние. Добавлен `removeCamera3D`.
- `restoreScene` проверяет schema, numeric ranges и uniqueness ComponentId вместе с прочими компонентами.
- `ASTRO_SCENE 8` сериализует/читает Camera3D; файлы v1–v7 остаются читаемыми. Сохранение загруженного v7 явно записывает v8, не добавляя камеру.
- Integration test проверяет camera lens/component-ID round-trip, отказ на invalid FOV без mutation, сохранение после повторной atomic замены и явное v7→v8 upgrade.
- Добавлена cache option `ASTRO_MSVC_SHOWINCLUDES_PREFIX`. Для текущей русской локали она указывает prefix `Примечание: включение файла:` и позволяет Ninja записывать include dependencies из MSVC `/showIncludes`.

## Найденная проблема инкрементальной сборки

Первый полный CTest после смены layout `Entity` упал на наборе разрозненных `SEGFAULT` и `0xc0000409`, включая старые unit и Editor smoke. Причина была в старых объектных файлах: Ninja metadata для `astro_scene_tests.obj` содержала `#deps 0`; object был собран до нового `Scene.hpp`, тогда как `astro_scene.lib` уже пересобрался. Русский `/showIncludes` prefix был неправильно сохранён CMake/Ninja при автоматическом определении, и header dependency не записывалась. После явного prefix metadata содержала 8 header dependencies, включая `Scene.hpp`. Clean Release build заново собрал все потребители.

- `ninja -t deps tests/CMakeFiles/astro_scene_tests.dir/unit/scene/SceneTests.cpp.obj`: 8 dependencies, включая `Scene.hpp`.
- `git diff --check` выполняется после обновления документации; работа ведётся поверх существующих пользовательских изменений без коммита и push.

## Ограничения и продолжение

Camera3D здесь — только сохраняемая настройка перспективной оптики. Не реализованы active camera selection, transform-to-view conversion, Inspector controls, runtime camera behavior и Game View draw path. Следующий отдельный подэтап должен определить правило выбора камеры и добавить camera Inspector, прежде чем подключать её к runtime Game View. Этот шаг не начат.
