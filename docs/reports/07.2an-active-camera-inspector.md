# 07.2an — активная Camera3D и Inspector

Дата: 2026-11-18. Платформа проверки: Windows 11 x64, MSVC 14.44.35207, CMake 4.4.4, Ninja 1.13.2, Release.

## Результат

- `Camera3DComponent` schema v2 хранит флаг `active`; модель Scene и `restoreScene` отклоняют несколько активных камер.
- Добавлены typed transactional команды `camera3d.add`, `camera3d.remove`, `camera3d.set_lens` и `camera3d.set_active`. Dry-run проверяет наличие сущности/компонента и диапазоны FOV/clip planes; Undo/Redo восстанавливают стабильный ComponentId, параметры и предыдущую активную камеру.
- Command field metadata получил аддитивный тип `Number` для `double` payload-полей.
- Inspector умеет добавить и удалить Camera3D, отредактировать вертикальный FOV и near/far plane с явным Apply, а также выбрать или снять активную камеру. Все изменения проходят через общий CommandRegistry. Ключи интерфейса добавлены в русский каталог.
- Scene v9 сериализует schema v2 и `active` как 0/1. Scene v8 Camera3D v1 загружается неактивной; старые сцены переписываются в v9 только при явном сохранении.
- Integration-тесты покрывают dry-run, запрет дубликата и конфликт ComponentId, single-active invariant, lens/selection/remove Undo/Redo, Scene v9 round-trip и v8 migration. Editor smoke проверяет typed lens/selection commands и наличие Inspector контролов.

## Ограничения и следующее направление

Active camera сейчас является сохраняемым выбором редактора. View matrix из иерархического Transform не строится, камера не управляет Game View/Runtime и её lens-поля не влияют на рендер. Это оставлено отдельной последующей работой.

Из-за локализованного `/showIncludes` в конфигурации используется существующий `ASTRO_MSVC_SHOWINCLUDES_PREFIX=Примечание: включение файла:`; этот подэтап не меняет настройки сборки. Никаких файлов не отправляли в GitHub и коммиты не создавали. Рабочее дерево уже было dirty до начала этого подэтапа.
