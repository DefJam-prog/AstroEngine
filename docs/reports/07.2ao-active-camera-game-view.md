# 07.2ao — активная Camera3D в Game View

## Результат

Game View Editor теперь отрисовывает видимые `MeshRenderer` через явно выбранную активную `Camera3DComponent`. Поза строится из полной иерархии Transform сущности камеры, локальные `-Z`/`+Y` задают направление и up, lens-поля преобразуются в `Camera3D`, а perspective aspect вычисляется из размеров BGFX target. Game View получил depth attachment. Scene View по-прежнему использует независимую orbit-камеру; существующий 2D SpriteRenderer в Game View продолжает рисоваться собственным ортографическим путём после 3D.

Иерархическое преобразование сцены вынесено в общий helper и используется для pose камеры и mesh world matrices. Ошибки отсутствующего Transform/родителя, цикла, нулевого масштаба, неfinite значений и отсутствующей/неактивной камеры не выдают некорректную матрицу. Если Game View не может получить активную камеру, 3D pass пропускается, 2D остаётся доступным; сообщение записывается в diagnostic string target, но пока не отображается отдельной строкой в панели Game View.

## Изменённые файлы

- `editor/SceneCameraPose.hpp`, `editor/SceneCameraPose.cpp` — общий resolver иерархической world matrix и pose активной камеры.
- `editor/main.cpp` — Game View BGFX pass, depth target, camera-driven view/projection; Scene View сохраняет orbit camera. Обновлён порядок проходов: Scene 2D, Scene 3D, Game 3D, Game 2D, ImGui.
- `editor/CMakeLists.txt` — подключение helper и unit target `astro_editor_scene_camera_pose_tests`.
- `tests/unit/editor/SceneCameraPoseTests.cpp` — родительская и дочерняя трансформации, pose/оси, lens и матрицы, отказ для inactive/missing camera и нулевого масштаба предка.
- `README.md`, `docs/ARCHITECTURE.md`, `docs/ROADMAP.md`, `docs/STATUS.md`, `docs/DECISIONS.md`, `docs/TESTING.md`, `docs/3D_RENDERING.md` — текущий контракт, ограничения и проверки.
- `docs/reports/07.2ao-active-camera-game-view.md` — этот отчёт.

## Проверки

Среда: Windows 11 x64, MSVC 2022 Build Tools 14.44, CMake 4.4.4, Ninja 1.13.2, локальная optional BGFX/D3D11 сборка с glTF renderer. Для корректного MSVC/Ninja header dependency scan использовался уже настроенный `ASTRO_MSVC_SHOWINCLUDES_PREFIX=Примечание: включение файла:`.

Release build выполнен успешно:

```powershell
cmd.exe /d /s /c 'call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\Tools\VsDevCmd.bat" -arch=x64 -host_arch=x64 && cmake --build build\07.2d-release-clean --config Release --parallel 8'
```

До изменения сфокусированный набор прошёл **5/5**. После изменения focused CTest прошёл **6/6 за 3,92 с**:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure -R '^(editor\.scene_camera_pose\.unit|editor\.scene_view_camera3d\.unit|scene\.unit|scene\.command\.integration|scene\.file\.integration|editor\.smoke)$'
```

Editor smoke подтвердил активную Camera3D и ненулевое число 3D mesh submissions в Game View, одновременно сохранив существующие Scene View проверки. Полный Release регресс прошёл **89/89 за 116,02 с**:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure --output-log build/07.2ao-full-ctest.log
```

Лог полного прогона находится в игнорируемом каталоге `build/07.2ao-full-ctest.log`.

## Ограничения

- Проверен только Editor Game View на Windows x64/BGFX D3D11 с включённым optional glTF renderer. Этот шаг не подключает камеру к standalone Runtime или Play Mode.
- Game View использует существующий плоский/vertex-color mesh path; Game View материалы, alpha policy, освещение и тени не подключены.
- 2D спрайты остаются отдельным ортографическим overlay и не участвуют в общем 2D/3D depth ordering.
- Диагностики отсутствующей или невалидной камеры собираются target, но не показаны в отдельной панели Game View.
- Smoke подтверждает прохождение draw path и submissions, но не добавляет cross-driver golden image или проверку визуального framing для нескольких камер/соотношений сторон.
