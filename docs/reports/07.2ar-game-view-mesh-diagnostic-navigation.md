# 07.2ar — переход из Game View diagnostics к сущности MeshRenderer

## Что сделано

- `SceneViewTarget` хранит сообщения текущего кадра отдельными записями: текст и необязательный related EntityId. Совместимый агрегированный текст для viewport diagnostics сохранён.
- Ошибки, возникшие при разрешении модели, подготовке геометрии/material, upload и проверке Transform/bounds, связываются с текущей Scene entity. Ошибка invalid active Camera3D связывается с камерой. Общие ошибки без надёжной сущности остаются без ссылки.
- Diagnostics показывает строки отдельно. Если EntityId ещё существует в открытой Scene, доступно действие выбора; общий Editor selection раскрывает родительскую цепочку и прокручивает Hierarchy к строке. Удалённая/неизвестная сущность не создаёт action.
- Новая локализованная подпись `Related entity` покрыта unit assertion.
- Добавлен Editor smoke для вложенной сущности с unresolved model AssetId. Он проверяет link/selection, раскрытие родителя и прокрутку, а также сохранение camera-driven draw для остальных валидных meshes.
- Scene/API/Asset formats, runtime, зависимости и исходные ресурсы не изменялись.

## Ограничения

- Проверен Windows x64 Editor с BGFX D3D11; другие ОС и renderer backends не проверялись.
- Smoke вызывает тот же обработчик выбора через тестовый harness; физический ввод мыши и ручная визуальная оценка UX не автоматизированы.
- Действие ведёт к сущности в Hierarchy, но не открывает asset-файл и не выбирает прямую ссылку из недоверенного текста importer/resolver.
- Диагностики остаются снимком текущего кадра, а не историческим журналом.
- В рабочем дереве до этапа уже имелось множество несохранённых изменений. Они не удалялись; commit/push не делались.

## Следующий рекомендуемый подэтап

После ручной проверки UI можно отдельно оценить переход к зарегистрированным mesh/material ресурсам через безопасный AssetId -> AssetRegistry mapping. Не извлекать пути из текста ошибок и не менять эту функциональность без отдельного подэтапа.
