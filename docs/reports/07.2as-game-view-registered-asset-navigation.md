# 07.2as — безопасный переход к зарегистрированному ресурсу

## Результат

Game View renderer diagnostics теперь могут ссылаться на зарегистрированный model или project material через типизированный `AssetId`. В Diagnostics действие выбора в Project доступно только после повторного разрешения ID текущим `AssetRegistry` и проверки, что корень проекта, для которого сформирован snapshot, совпадает с текущим корнем реестра. В Project отображаются тип ресурса, ID и относительный source path из записи реестра.

Для отсутствующей модели сохраняется Entity-навигация, но Asset action не появляется. Запись о материале без project override ссылается на зарегистрированную модель, поскольку source material является частью импортированной модели; зарегистрированный material override связывается со своим ID. Camera и глобальные диагностические записи не получают недостоверные asset-ссылки. Изменение не открывает файлы, не изменяет игровые ресурсы, не вызывает import/reimport и не пишет в cache или registry.

Это выбор из диагностики и карточка сведений Project, а не полный Asset Browser: каталог ресурсов, поиск, фильтры, drag-and-drop и открытие ресурса не входят в подэтап.

## Проверки

Среда: Windows x64, MSVC 2022, Release, BGFX D3D11. Существующая Release-конфигурация использовалась без установки новых зависимостей.

До изменений чистая сборка уже была актуальна (`ninja: no work to do`), а полный baseline CTest прошёл **92/92 за 115,40 с**.

Конфигурация:

```powershell
cmake -S . -B build/07.2d-release-clean '-DASTRO_MSVC_SHOWINCLUDES_PREFIX=Примечание: включение файла:'
```

Сборка:

```powershell
cmd.exe /d /s /c 'call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\Tools\VsDevCmd.bat" -arch=x64 -host_arch=x64 && cmake --build build\07.2d-release-clean --config Release --parallel 8'
```

Фокусированный набор после реализации прошёл **6/6 за 15,54 с**:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure --output-log build/07.2as-focused-ctest.log -R "^(editor\.localization\.unit|editor\.smoke|editor\.game_view_camera_no_active\.smoke|editor\.game_view_camera_invalid\.smoke|editor\.game_view_mesh_diagnostic_entity\.smoke|editor\.game_view_registered_asset_diagnostic\.smoke)$"
```

Полный Release CTest прошёл **93/93 за 127,16 с**:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure --output-log build/07.2as-full-ctest.log
```

Результаты сохранены в `build/07.2as-prechange-ctest.log`, `build/07.2as-focused-ctest.log` и `build/07.2as-full-ctest.log`.

## Ограничения

- Проверен только Windows D3D11 Editor-путь; другие BGFX backends и standalone runtime не проверялись.
- Smoke harness вызывает действие UI программно, а не физическим вводом мыши.
- Project показывает запись выбранного ресурса, но не является полноценным Asset Browser.
- В этом подэтапе не проверялись визуальные golden images: изменения касаются диагностики и выбора ресурса.
- В компиляции остаются предупреждения MSVC `C4530` и существующие `C4189` в C# metadata code; сборку они не блокировали.

## Следующий рекомендуемый подэтап

После ручной проверки UX можно отдельно спланировать read-only Asset Browser с каталогом только из AssetRegistry, поиском и фильтрами. Его контракт, безопасность путей и критерии тестирования следует определить до реализации. Этот следующий подэтап здесь не начинался.
