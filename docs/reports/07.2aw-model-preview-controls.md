# 07.2aw — automated Project model preview controls

## Scope

The substage strengthens the existing registered-model preview smoke. It verifies a model with multiple glTF primitives and checks the preview camera control methods used by the GUI handlers. It does not simulate physical mouse events or begin another roadmap substage.

## Changes

- In the Editor smoke project only, the copied glTF model receives a second primitive. The tracked fixture and user project assets are untouched.
- The test requires geometry counts of 1 mesh, 2 primitives, 6 vertices and 6 indices, exactly 2 BGFX draw submissions, applied Frame All and zero mesh diagnostics.
- After Frame All, the smoke harness invokes the same `SceneViewTarget` orbit, pan and zoom methods used by right-drag, middle-drag and wheel UI callbacks. It requires yaw, focus and distance to change.
- The real window screenshot crop must contain at least 32 foreground pixels; this run measured **2,202**.
- Documentation/status/decision records describe the scope and limits.

## Limits

Validated on Windows x64, MSVC 2022, BGFX D3D11. The smoke calls the control methods directly; it does not synthesize OS mouse input. The second primitive reuses the same triangle geometry, so this checks multiple submissions and preview composition, not non-overlapping object layout. No other graphics backend/OS and no image golden comparison were tested.
