# 07.2ax — manual Project model preview review

## Scope and environment

Reviewed the selected registered glTF model in the running Windows Editor. The repository and the inspected user asset folders did not contain a multi-primitive glTF project. The user-side examples found were `C:\Users\zheka\Desktop\gpt\models\SC.fbx` and `C:\Users\zheka\Desktop\gpt\Scenes\level_1.obj`; the current importer only accepts glTF/GLB. These user files were read only and left unchanged.

To keep the review isolated, a copy of the existing generated smoke project was placed under `build/07.2ax-manual-project`. Only that ignored copy received a review glTF: two spatially separated triangle primitives, one shared source image/material, and UV transform/sampler metadata. The already-built local importer registered it as AssetId 4, 1 mesh and 2 primitives. The copied project and temporary registration helper remain under ignored `build/`; no tracked source or user resource was changed.

## Observations

- Editor opened the isolated project, Asset Browser selected `Models/triangle.gltf`, and Project preview showed both non-overlapping triangles. Geometry summary: 1 mesh, 2 primitives, 12 aggregate primitive vertices, 6 indices.
- Scrolling the pointer over the preview changed the visible model scale in both directions, confirming actual wheel input reaches preview zoom.
- The rendered triangles appeared blue/cyan against the dark preview background. The source material and texture were present, but there is no visual golden or pixel color assertion for this manual review; exact color correctness is therefore not claimed.
- The current Project viewport uses a 4:3 size rule (160×120 logical minimum at this narrow dock width). On the restored 864×608 window, the lower part of the Project preview was below the visible panel area; on the maximized portrait display it was fully visible. A second freely resizable preview aspect ratio could not be exercised in this dock layout.
- The Windows Computer Use API available in this environment supports left-button drag only. The editor maps orbit to right-button drag and pan to middle-button drag, so physical orbit and pan could not be invoked through this automation session. The prior 07.2aw smoke still verifies their shared camera methods programmatically; that is not evidence of actual OS right/middle mouse events.

## Limits and follow-up

Validated the Project preview and wheel zoom on Windows x64, MSVC 2022, BGFX D3D11. Real user FBX/OBJ files remain unsupported by the current importer. Actual right/middle mouse orbit/pan and comparative non-4:3 preview behavior remain unverified. Have a human drag inside the model viewport with the right and middle buttons to close the input gap; if the 864×608 layout is a target, assess making the Project content scroll/resize without clipping the viewport.
