# 07.2az — Project model preview mouse event path

## Scope

Close part of the orbit/pan validation gap by driving the selected Project model viewport through the regular SDL3 → ImGui backend → Editor handler path. The available Computer Use `drag` action has no mouse-button argument, so it cannot hold right or middle while moving. This substage therefore exercises queued SDL events; it does not claim physical mouse validation.

## Implementation

The isolated asset-model-preview smoke waits until the 864×608 compact layout is active and the target preview is visible. It then queues one SDL event sequence per frame into its own window: cursor motion to the viewport, right down/motion/up, then middle down/motion/up. Motion carries the matching SDL button-state mask. Events are consumed by the existing `SDL_PollEvent` loop and `ImGui_ImplSDL3_ProcessEvent`; the existing hover-and-button GUI handlers perform the camera changes.

Smoke success requires the right drag to change camera yaw, the middle drag to change camera focus, all input phases to complete with releases, and the existing viewport visibility / image pixel assertions to pass.

## Limits and next recommended step

SDL events are synthetic. This test covers the actual app event queue, ImGui SDL backend, hit testing, and GUI camera handlers, but does not exercise Windows `SendInput` or a physical mouse. It has only been run on Windows x64 Release with BGFX D3D11 at display scale 1.25. A human right-drag/middle-drag check remains the next useful validation; no later roadmap substage was started here.
