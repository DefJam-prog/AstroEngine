# 07.2b — Versioned material asset and AssetRegistry

## Scope

Implemented the reusable material data layer and project registration only. This is a bounded slice of 07.2, not a Material Editor or PBR renderer.

## What changed

- Added strict UTF-8 text format `ASTRO_MATERIAL 1` with bounded parsing/serialization and finite/range checks.
- Added backend-neutral values: base color RGBA, metallic/roughness, emissive RGB, alpha mode/cutoff, double-sided, normal scale and occlusion strength.
- Added optional texture bindings for base color, metallic-roughness, normal, occlusion and emissive; each stores a registered image AssetId and `texCoord` selector.
- Added material registration and resolution under `Assets/Materials/*.astro-material`. Registration reads source bytes but does not modify the material file. Re-registering the same relative path keeps its stable AssetId and updates source metadata.
- Extended the shared AssetRegistry manifest to v4 with material records and a shared monotonic ID space. Existing v1–v3 indexes remain readable and are upgraded only when a registry write occurs.
- Added unit and integration coverage, including legacy index migration and preservation of corrupt indexes.
- Updated architecture, format, asset pipeline, tech stack, roadmap, status, testing, README and decision records. No external dependency was added.

## Format and validation

`ASTRO_MATERIAL 1` has ordered scalar/vector rows followed by up to five typed `TEXTURE` rows and `END`. Files are capped at 64 KiB. Unknown/duplicate roles, unsupported schema, malformed values, non-finite numbers, invalid ranges, extra records, zero image IDs and malformed structure fail with an error. AssetRegistry resolve also checks source size/hash and confirms texture IDs exist in the image registry. It does not check whether the registered image's own source bytes have changed during material resolve.

Base-color/emissive factors are linear values. Base-color/emissive samples are intended for sRGB decode; metallic-roughness uses G=roughness/B=metallic; normal and occlusion are linear, with occlusion in R. These are documented data semantics. No image decoding, color conversion or GPU upload is implemented.

## Limits

- No Material Inspector, command API/Undo integration, Scene material slots or project/entity overrides.
- No glTF material extraction, material assignment per primitive, texture decode/upload, PBR shader, lighting, shadows or Game View/runtime material rendering.
- Current image reference validation checks registry membership, not current image source freshness.
- No macOS, Android, iOS, sanitizer, fuzzing or performance validation was run.

## Recommended next substage

After explicit approval, add bounded glTF material metadata extraction: retain supported PBR factors, source texture/image references and per-primitive material-slot indices, with validation and regression tests. Preserve unknown/unsupported source mappings as diagnostics; do not add Scene overrides or Editor controls in that slice.
