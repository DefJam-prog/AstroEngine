# 07.2bd — Creating built-in primitives in a 3D scene

## Scope and implementation

Added a localized Hierarchy menu `+ 3D Primitive` with Cube, Plane, Sphere and Cylinder. Choosing an entry creates a Scene entity with the ordinary Transform plus a persistent `PrimitiveRendererComponent`. The meshes are generated in memory by `MeshData::makePrimitive`, uploaded into the existing BGFX cache, and submitted through the same Editor Scene/Game View path used for imported meshes. No image, model or other user Asset was written.

Scene serialization is now v10. The component stores its stable ComponentId, primitive kind and visibility; the loader still accepts v1–v9 and only rewrites them to v10 on explicit save. Imported `MeshRenderer` and built-in `PrimitiveRenderer` are mutually exclusive on one entity. New menu strings have Russian translations.

- Full Release build: `cmake --build build/07.2d-release-clean --config Release --parallel 8` — succeeded when run after importing the Visual Studio x64 developer environment using `VsDevCmd.bat -arch=x64`.
- Focused tests: `ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure -R "^(scene\.unit|scene\.file\.integration|runtime\.render3d\.camera_mesh\.unit|editor\.smoke)$"` — **4/4 passed in 7.45 s**.
- Full regression: `ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure` — **95 passed, 1 failed, 1 skipped out of 97** in 282.03 s.
- The new geometry tests verify that every primitive generates finite position/normal/UV values, non-empty triangle geometry, and in-range indices; invalid primitive values fail. Scene integration verifies sphere kind, visibility and stable component ID across save/load. Legacy v1, v7 and v8 migration checks passed.
- The full run's failed test is `editor.asset_model_preview.smoke`, where synthetic Scene View mouse events were not observed (`scene-view-hover=0`, `scene-view-right-drag=0`, `scene-view-middle-drag=0`). This matches the already known environment-sensitive failure from before this feature. `editor.window_mixed_dpi.sdl.smoke` returned its configured skip code because the machine did not expose the required mixed-scale monitor pair. The ordinary `editor.smoke` passed.

The first direct build from ordinary PowerShell failed before compiling project code because MSVC's environment lacked standard C++ include paths. Re-running from the installed Visual Studio x64 developer environment resolved it; no tool installation or system setting was changed.

## Limits and next work

This is an Editor Scene/Game View prototype. It does not add a standalone runtime renderer, physics colliders, per-primitive material/color authoring, or an explicit rendering smoke/pixel golden for each kind. The Hierarchy currently creates entities directly, consistent with the existing `+ Entity` action; it clears Undo/Redo history. A later step should add transactional create/delete with stable IDs and a focused BGFX primitive smoke before claiming those aspects complete.
