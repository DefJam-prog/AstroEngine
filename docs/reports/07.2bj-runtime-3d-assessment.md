# 07.2bj — оценка готовности Runtime/Play к 3D PrimitiveRenderer

## Краткий вывод

В проекте пока нет standalone 3D scene renderer для игрового Runtime/Play. Материализованные `PrimitiveRenderer` работают в Editor Scene/Game View, а существующий BGFX sample проверяет ограниченный 3D prototype для `MeshRenderer`. Считать этот sample готовым игровым runtime было бы неверно.

## Проверенные границы

- `engine/runtime/include/astro/runtime/SDLCanvas2DRenderer.hpp` и SDL adapter реализуют 2D `Canvas2D`; 3D Scene submission API в `engine/runtime` не найден.
- Renderer `SceneViewTarget` в `editor/main.cpp` приватен для Editor и использует его BGFX lifecycle/cache. Прямая зависимость Runtime от этого класса привязала бы Runtime к Editor.
- `engine/render3d` предоставляет backend-neutral `Camera3D`, `MeshData::makePrimitive`, glTF import и `resolveMeshRenderer`. Scene хранит `MeshRenderer` и `PrimitiveRenderer` с persisted material AssetId.
- `samples/3d_prototype/main.cpp` под условной компиляцией открывает `AssetRegistry`, ищет ровно один видимый `MeshRenderer`, вручную разрешает material и отправляет mesh в sample BGFX window. Sample не строит render items из всей сцены и не учитывает Scene hierarchy/active Camera3D.
- BGFX sample ограничен Windows x64/MSVC. Текстурный путь использует Windows WIC. Его baseColor smoke — диагностическая плоская tint-проверка, а не renderer с полным материалом.

## Рекомендуемая последовательность реализации

1. Сначала добавить backend-neutral Scene render-item builder в подходящий слой engine/render3d или runtime: разрешить ровно одну активную 3D camera, вычислить world transforms по hierarchy, получить geometry из `resolveMeshRenderer` либо `MeshData::makePrimitive` и связать optional registered material override. Не копировать Editor-owned `SceneViewTarget`.
2. Возвращать ограниченные ошибки/diagnostics с EntityId и AssetId при цикле родителей, невалидном Transform/camera, отсутствующем mesh/material или неподдерживаемой geometry. Не удалять неизвестные scene data.
3. Покрыть builder unit-тестами и сериализованный Scene integration round-trip до появления GPU backend.
4. Отдельным следующим шагом подключить необязательный BGFX Runtime backend, использовать кэш ресурсов и сохранить возможность собрать/запустить Runtime без Editor.
5. Добавить Runtime/Play smoke для видимых primitive и MeshRenderer material, камеры, hierarchy и отсутствующих ресурсов; затем отдельно проверить export path.

До первых тестов нужно решить владение render caches и texture decoder, thread/lifecycle границу, и повторное использование Editor material implementation без переноса Editor зависимостей. Эти вопросы остаются рисками следующего implementation substage; 07.2bj не выбирает новую библиотеку и не меняет API.
