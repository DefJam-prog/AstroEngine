# 07.2bm — RuntimeSession Play → BGFX sample smoke

## Scope

Connected the existing opt-in BGFX packet sample to the engine's `RuntimeSession`. The smoke starts Play from an authoring `Scene`, mutates only a runtime entity during fixed updates, rebuilds a render packet from the runtime copy every frame, and submits it through `astro_runtime_bgfx_scene3d`. No editor renderer or public runtime API was changed.

## Files changed

- `samples/3d_prototype/main.cpp` — runtime Scene fixture, Play setup/ticking, per-frame packet building, invariants and clean stop.
- `samples/3d_prototype/CMakeLists.txt` — links the optional sample to `astro_runtime_session`; strengthens the smoke output assertions.
- `README.md`, `samples/3d_prototype/README.md`, `docs/3D_RENDERING.md` — describe the verified scope and limits.
- `docs/ROADMAP.md`, `docs/STATUS.md`, `docs/DECISIONS.md`, `docs/TESTING.md` — record substage, decision and validation.

## Verification

Configuration: existing Windows x64 MSVC Release build `build/07.2d-release-clean`, local SDL3/BGFX dependencies, D3D11. Build command:

Pixel capture measured 29,511 foreground pixels, 15 color buckets, bounds `(326,256)-(627,377)`; frame timing was 16.642 ms p50 / 16.993 ms p95 under VSync and is not a performance claim. Full Release CTest passed **100/101** in 124.02 s; 1 test was skipped (`editor.window_mixed_dpi.sdl.smoke`) because the environment did not provide two suitable displays. No CTest failures.

## Limits

This proves the sample-host handoff through the disposable Play Scene only. The SDL window, BGFX initialization, shaders and program remain in the sample; `editor/main.cpp` Scene/Game View is not connected to this adapter. Windows x64/MSVC/D3D11 only. Current adapter scope remains vertex colors plus opaque `baseColorFactor`; texture/alpha/PBR and alternate backends are not covered. Existing unrelated working-tree changes were preserved; no user resources were deleted or rewritten by this substage.
