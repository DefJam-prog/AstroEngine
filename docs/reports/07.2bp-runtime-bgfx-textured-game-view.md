# 07.2bp — Opaque base-color texture in Runtime BGFX Game View

## Scope

Added a bounded Runtime BGFX path for registered project-material base-color images and verified the actual Game View output pixels. Also corrected BGFX view order: each Scene/Game render target's 2D color clear now runs before its corresponding 3D pass, so the later clear no longer erases 3D output before ImGui samples the target.

## Implementation

- `BgfxSceneRenderer` keeps its original one-program constructor and gains an overload with host-provided textured program/uniforms. `render` accepts optional host image decode and hash resolvers.
- The Editor resolves image IDs only through `AssetRegistry`, gets the current source SHA-256, and decodes the derived image with the existing WIC helper. The Runtime adapter does not open project paths itself.
- Supported material subset: opaque project `baseColorTexture`, registered image AssetId, mesh UV0, identity UV transform, nearest/linear non-mip min filter, nearest/linear mag filter, and repeat/mirrored/clamp wrapping. Texture data is converted from sRGB BGRA8 to linear BGRA8 and multiplied by `baseColorFactor` before upload.
- GPU texture cache is bounded to 256 MiB and keyed by image AssetId, current AssetRegistry SHA-256 and linear factor. `clearCache()` and renderer destruction release texture handles while BGFX is alive.
- Unsupported alpha modes, other PBR maps, missing UV0, UV1, non-identity transform and mip filters reject the adapter pass, allowing the pre-existing Editor renderer to draw the whole scene.
- The texture smoke uses a separate Play copy with a test MeshRenderer and project material. It verifies one adapter mesh, one texture submission/cache entry and at least 64 base-color pixels in the Game View image. Current captured result: **4050 pixels**.

## Limits

This is a Windows x64/D3D11 prototype. Source glTF image references without a project-material override still use the Editor fallback. Runtime BGFX does not yet support alpha mask/blend, mipmapped sampling, UV transforms/UV1, metallic-roughness/normal/occlusion/emissive maps, sampler extensions or other rendering backends. The screenshot threshold is a bounded color-region smoke, not a strict pixel-golden comparison.
