# 07.2br — оценка mip-фильтрации Runtime BGFX

## Вывод

Добавлять mip-фильтрацию можно отдельным ограниченным шагом, переиспользовав уже существующий CPU mip-chain policy, а не вводя новый алгоритм или зависимость. Сейчас Runtime BGFX намеренно загружает только `levels.front()` как одноуровневую BGRA8 texture и ставит `hasMips=false`; проектные и source glTF mip-фильтры явно отклоняются, поэтому весь кадр сохраняет Editor fallback.

У Editor Scene View уже есть полный генератор `prepareLinearBaseColorMipChainBgra8`, тесты выбора всех четырёх mip-фильтров, проверки OPAQUE/BLEND/MASK alpha policy и ограничение результата 96 MiB. Генератор строит цепочку в linear space; для MASK корректирует покрытие cutoff, для BLEND обрабатывает alpha согласованно с текущей политикой. Runtime texture cache сейчас ограничен 256 MiB, но при расширении необходимо учитывать **все mip levels** в cache budget и освободить частично созданную GPU texture при неудаче загрузки уровня.

BGFX API предусматривает создание текстуры с mip chain и обновление отдельных уровней. Это подтверждает техническую возможность, но не заменяет smoke на фактически выбранном backend: после реализации следует проверить размер/число mip levels, per-level upload, отсутствие неполной texture в кеше при ошибке и фактический mip выбор на D3D11. Точные функции/сигнатуры сверить с локально зафиксированной версией BGFX в build dependencies до начала кода.

## Предлагаемые границы следующего шага

- Поддержать только четырe glTF/project min filters с mip (`NearestMipmapNearest`, `LinearMipmapNearest`, `NearestMipmapLinear`, `LinearMipmapLinear`) для существующего opaque base-color subset.
- Сохранить текущие nearest/linear no-mip режимы и texture/material API.
- Не включать alpha MASK/BLEND, остальные PBR maps, UV1 и UV transforms: для них оставить полный Editor fallback.
- Использовать общий CPU mip generator; учитывать полный chain byte size в 256 MiB Runtime cache budget.
- Разнести adapter validation/upload так, чтобы любая ошибка любого item происходила до draw submissions; не оставлять частично принятую сцену или незавершённые GPU handles.

## Риски

1. GPU backend может отклонить BGRA8 mip uploads или sampler flags; требуется capability validation/clean fallback.
2. Ошибочная mip offset, уровень или размер может вызвать неверные текстуры или чтение за пределами буфера; нужен per-level unit/integration проверяемый план размеров и байтов.
3. MASK/BLEND требуют сохранения уже проверенной alpha-aware mip политики, но пока не проходят Runtime alpha passes — объединять их в этом шаге рискованно.
4. Пороговый screenshot недостаточен для доказательства корректной фильтрации; smoke должен сравнить minified region для всех четырёх sampler modes и проверить различие между mip/non-mip выбором на фиксированной тестовой геометрии.
5. Проверка доступна только на текущем Windows x64 D3D11 host; другие BGFX backends не подтверждены.
