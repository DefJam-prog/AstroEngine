# 07.2bs — mipmapped opaque base-color в Runtime BGFX

## Изменения

Runtime BGFX adapter теперь использует общий `selectBaseColorMinFilter` для всех четырёх sampler modes с mip. Для mip-enabled texture он строит bounded linear-space mip chain общим `prepareLinearBaseColorMipChainBgra8`, создаёт BGRA8 texture с mip levels, задаёт `BGFX_SAMPLER_MIP_POINT`/`MIN_POINT` согласно filter selection и отправляет уровни 1..N через `bgfx::updateTexture2D`. Уровень 0 передаётся при создании texture. Размер **всех** уровней учитывается в 256 MiB cache budget. Cache key отличает mip chain от одноуровневого upload, при этом совместимые фильтры переиспользуют mip texture.

Существующий Editor Game View smoke сохранён: temporary Scene содержит project-material texture и source glTF texture. Source primitive использует `LINEAR_MIPMAP_LINEAR`; Play проверяет 2 mesh submissions, 2 texture cache entries, ровно 1 mipmapped entry, не менее 64 красных и 64 голубых pixels. Project override, source-image WIC path validation и прежний full-pass fallback сохранены.

## Ограничения и известные проблемы

Поддерживаются только opaque base-color, UV0, identity UV transform, ранее допустимые wrap/mag modes и четыре min filters с mip. Smoke фактически прогоняет один режим `LINEAR_MIPMAP_LINEAR`; unit проверяет общую таблицу выбора всех четырёх mode, но отдельные adapter screenshot сравнения пока отсутствуют. MASK/BLEND, прочие PBR карты, UV1/transform и другие graphics backends остаются fallback.

BGFX `updateTexture2D` возвращает `void`, поэтому renderer не может получить поздний per-level backend upload failure. Все размеры и byte bounds проверяются до аллокации; cache запись добавляется только после постановки всех уровней в очередь. Это ограничение API, не гарантия успешного исполнения GPU команд.
