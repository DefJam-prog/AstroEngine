# 07.2bt — сравнение четырёх mip min-фильтров Runtime BGFX

## Результат

Добавлены четыре раздельных Editor Play/Game View smoke для glTF min-filter enum 9984–9987. Каждый smoke использует checker PNG 64×64, glTF mip chain и уменьшенный треугольник в disposable проекте; основной project-material треугольник остаётся в кадре как контрольный цвет. Проверки подтверждают mip cache entry, передачи draw через Runtime BGFX, фактический sampler enum и попадание числа цветных source pixels в диапазон соответствующего режима.

Фильтры glTF: 9984 `NEAREST_MIPMAP_NEAREST`, 9985 `LINEAR_MIPMAP_NEAREST`, 9986 `NEAREST_MIPMAP_LINEAR`, 9987 `LINEAR_MIPMAP_LINEAR`. На текущем Windows x64 / BGFX D3D11 host crop измерил соответственно **256, 512, 256, 512** пикселей checker-текстуры; project texture дала **4050** пикселей. Результат показывает, что sampler выбран и minified source texture видна, но эти значения не являются универсальным визуальным golden для других GPU, драйверов или backend.

Во время smoke был найден defect загрузки mip chain: initial memory block BGFX принимал только один mip и давал чёрную source texture. Renderer теперь создаёт mip texture без initial data и ставит каждый уровень, включая level 0, отдельным `bgfx::updateTexture2D`. Checker снова виден, все четыре варианта проходят. Сам API BGFX по-прежнему не возвращает результат исполнения каждого upload на GPU.

## Изменённые файлы этого подэтапа

- `editor/main.cpp` — тестовая checker-картинка, выбор одного из четырёх фильтров через smoke environment и проверка видимого результата.
- `editor/CMakeLists.txt` — четыре serial CTest smoke с отдельными временными рабочими каталогами.
- `tests/smoke/editor_runtime_bgfx_game_view_texture.cmake` — фильтр, enum и диапазоны видимых пикселей.
- `engine/runtime/adapters/bgfx/BgfxSceneRenderer.cpp` — upload всех mip уровней, включая base level, через отдельные update calls.
- `README.md`, `docs/ARCHITECTURE.md`, `docs/3D_RENDERING.md`, `docs/ROADMAP.md`, `docs/STATUS.md`, `docs/DECISIONS.md`, `docs/TESTING.md`.

## Проверки

Сборка:

```powershell
cmake --build build/07.2d-release-clean --config Release --parallel 8
```

Результат: `ninja: no work to do` (текущая Release конфигурация уже собрана).

Новые smoke:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --output-on-failure -R "^editor\.runtime_bgfx_game_view_mipmap\.(9984|9985|9986|9987)\.smoke$"
```

Результат: **4/4 passed за 12,90 с**.

Полная регрессия:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --output-on-failure --output-log build/07.2bt-full-ctest.log
```

Первый прогон дал **106 passed, 1 failed, 1 skipped из 108 за 155,95 с**. Единственный failure — существующий `editor.asset_model_preview.smoke`: геометрия viewport, submissions, layout и selection прошли, но synthetic right/middle SDL drag assertions были `0`. Следующий отдельный запуск прошёл 1/1; `ctest --repeat until-fail:10` прошёл **10/10** за 30,08 с. Повторный полный Release CTest без изменения кода завершился **107 passed, 1 skipped из 108 за 171,24 с**, включая успешный asset preview. Первый отказ не воспроизведён; transient window/input timing остаётся лишь гипотезой, установленной причины нет. Исправлять runtime path или ослаблять assertions оснований нет. Mixed-DPI smoke штатно skipped из-за отсутствия подходящей пары дисплеев. Оба лога: `build/07.2bt-full-ctest.log`, `build/07.2bt-diagnosis-full-ctest.log`.

`git diff --check` проверен после обновления документации; существующие пользовательские изменения не откатывались. Коммит и отправка в GitHub не выполнялись.

## Ограничения

- Проверен только Windows x64, MSVC Release, BGFX Direct3D 11.
- Pixel count limits защищают текущий smoke от чёрной или неверно выбранной texture/filter path, но не являются переносимым способом сравнивать качество фильтрации.
- Asset model preview smoke прошёл десять последовательных повторов и полный CTest; единичный отказ не доказывает постоянную проблему. Если он повторится, до правки кода следует записать SDL focus, viewport rectangle и принятые motion/button координаты.

## Следующий рекомендуемый подэтап

Наблюдать повторяемость `editor.asset_model_preview.smoke` в последующих полных прогонах. При повторном сбое собрать window/focus/input diagnostics и не ослаблять assertions. Новый подэтап сейчас не требуется; следующую реализацию начинать только после подтверждения.
