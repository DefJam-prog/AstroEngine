# 07.2bv — оценка первого вертикального среза 3D-освещения

## Итог

База для освещения частично подготовлена: glTF importer распознаёт только bounded FLOAT VEC3 `NORMAL`, проверяет конечные ненулевые векторы, `MeshData` явно помечает наличие normal channel, а встроенные Cube/Plane/Sphere/Cylinder создают face normals. `SceneRenderPacket` уже вычисляет world transform для геометрии и разрешает материалы.

Само освещение отсутствует. Scene формата v11 не имеет Light component; render packet содержит камеру/items/diagnostics, но не lights и normal matrix. Runtime BGFX vertex cache использует position/color/UV и игнорирует `MeshVertex::normal`. Editor `scene_color.sc` и `scene_textured.sc` не читают normal attributes и не вычисляют освещение. Материал имеет base-color/metallic/roughness metadata, но текущие draw shaders остаются flat/unlit.

## Рекомендуемый ограниченный первый контракт

1. Добавить версионированный `DirectionalLight3D` Scene component с ComponentId и явными ограниченными полями: enabled, linear RGB color и finite intensity. Не вводить point/spot, environment map, shadows или PBR material response в этом срезе.
2. Использовать направление локальной оси `-Z` владельца как направление распространения света; вычислять world direction из rotation-only части иерархического Transform. Translation и scale не должны менять направление. Проверить математику в том же row/column convention, что и существующий `Mat4`/BGFX.
3. Расширить Scene file до v12. Файлы v11 продолжать читать с отсутствующим optional light без автоматического переписывания; неизвестные компоненты/поля диагностировать, не терять.
4. Добавить typed Scene commands для добавления/изменения/удаления компонента и тестировать validation + Undo/Redo. GUI Inspector добавлять только если команда и schema готовы, чтобы GUI и Command API имели один контракт.
5. Передавать light data в immutable backend-neutral render packet. Для mesh без normals packet/render diagnostic должен явно указывать, что освещённый путь невозможен; прежняя unlit rendering остаётся доступной. Не подменять normals фиктивным значением.
6. До этого data-contract slice не менять BGFX shader и не объявлять освещение работающим.

### Последовательность acceptance тестов

- Unit: finite/range validation, normalized world direction, hierarchy rotation, non-uniform/negative scale invariance, deterministic ordering, disabled/no-light state, missing-normal policy.
- Integration: typed add/set/remove command, invalid payload, Undo/Redo, packet light snapshot and no-light compatibility.
- Serialization: Scene v11 read remains valid and byte/data state is preserved until explicit save; v12 round-trip, missing/unknown component diagnostics and malformed numeric values.
- Следующий GPU visual slice: controlled plane/primitive with opposite normals under one directional light; verify expected lit/unlit pixel regions and unchanged OPAQUE/MASK alpha, texture and fallback tests. Scene with no light must retain current flat appearance.

## Риски и зависимости

- Нормаль должна трансформироваться inverse-transpose при non-uniform scale; использовать world matrix напрямую даст неверный результат.
- У glTF NORMAL есть valid optional state; для отсутствующего канала не придумывать uniform normal и не показывать объект как корректно освещённый.
- Потребуется согласовать linear-light color/intensity с уже существующими linear base-color factors, sRGB image preparation и backbuffer output. Перемножение гамма-кодированных цветов даст неверное освещение.
- Добавление component меняет Scene schema и typed command API; необходима explicit v11 compatibility, round-trip и undo test coverage.
- Первый slice будет только Lambert/directional foundation, не full PBR, физический lumen model или shadows. Целевые visual/brightness budgets надо определить отдельно.
- Новые внешние зависимости не нужны; проверки текущего прототипа ограничены Windows x64/MSVC/BGFX D3D11.

## Изменения и baseline

Code, public API, Scene format и зависимости не менялись. Release baseline: `cmake --build build/07.2d-release-clean --config Release --parallel 8` из подготовленного MSVC Developer environment — **ninja: no work to do**. Последняя полная проверка 07.2bu: **108 passed, 1 skipped из 109 за 156,52 с**. Архитектурных изменений не было, поэтому повторный CTest для assessment не нужен. `git diff --check` проверен; Git показывает только line-ending warnings для текущего dirty tree.
