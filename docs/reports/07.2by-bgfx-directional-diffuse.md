# 07.2by — BGFX directional diffuse in Runtime Game View

## Scope

Implemented the bounded visual slice selected by 07.2bx: normals and an inverse-transpose world normal transform, project-owned BGFX shaders, up to four directional lights, visible unlit behavior for scenes without lights or meshes without normals, and a Game View pixel smoke. No dependency was added. Scope is the optional Windows x64 BGFX/D3D11 Runtime/Game View adapter; Editor Scene View and Project model preview continue using their existing unlit render path.

## Implementation

- Added `NormalMatrix3` and `inverseTransposeNormalMatrix`. The function reads the column-major world matrix's linear 3x3 part and rejects singular, non-finite, or non-finite-result transforms.
- Extended Runtime BGFX vertex upload with the optional mesh NORMAL channel. Geometry without normals uploads zero normals but sets the shader light count to zero, preserving visible unlit output. The Editor surfaces a per-entity diagnostic for this fallback.
- Added project-owned color and textured vertex/fragment shaders. Lit texture RGB is decoded from sRGB; mesh vertex colors and `baseColorFactor` are treated as linear; Lambert diffuse is applied in linear space and lit RGB is encoded to sRGB. Alpha OPAQUE/MASK policy remains in place.
- The renderer consumes at most four directional lights. Scene packet order is stable by EntityId; excess lights are omitted and reported by the Editor.
- Added a D3D11 Game View smoke scene with a red directional light and a screenshot assertion that detects lit red pixels. Existing no-light, fallback, project/source texture, OPAQUE/MASK, and four mip min-filter smoke cases remain enabled.

## Limits and follow-up

- The pixel smoke proves red-lit output exists; it does not compare exact output values or explicitly compare front- and back-facing regions.
- No-light output is kept in the shader's unlit branch and the no-light Game View regression passes, but no saved-image equivalence metric is asserted.
- Scene View and Project model preview do not yet consume light packets. PBR, specular, ambient/environment lighting, shadows, other GPU APIs, and non-Windows platforms are out of scope.
- Before extending lighting, add explicit no-light image-equivalence and opposite-facing pixel comparisons. The recommended next bounded step is Scene View wiring after those checks are in place.
