# 07.2bz — Directional diffuse in Scene View

## Scope

Connected the existing `DirectionalLight3D` contract to the Editor Scene View's BGFX mesh renderer. The project model preview is unchanged. Lighting remains a limited Windows x64/D3D11 prototype.

## Implementation

- Extended the Scene View vertex layout and cached mesh vertices with authored normals from imported and built-in meshes.
- Resolved enabled light directions through the existing hierarchy-aware direction resolver, sorted by EntityId and capped at four. More lights are omitted with a diagnostic.
- Reused the project-owned Lambert shader programs and inverse-transpose normal-matrix helper. Meshes without normals or with singular world normal transforms remain on the unlit renderer path and report a diagnostic.
- Kept Scene View's existing per-material texture preparation and OPAQUE/MASK/BLEND/fallback handling. Scene View chooses the original unlit shader programs when no enabled directional light exists. Project model preview remains unlit.
- Extended the directional-light Editor smoke with a normal-bearing Scene View cube. Game View is placed in a separate right-side window so it cannot overlap the Scene View screenshot crop. The smoke captures both view rectangles and requires at least 16 red pixels in each. It observed **2,740 red pixels in Scene View** and **2,304 in Game View**.

## Known limits

- The smoke detects red pixels in each view; it does not compare exact rendered pixel values between no-light and pre-light shader output.
- It does not isolate a known front-facing and opposite-facing surface pair into separate pixel regions. No explicit per-face lighting ratio is claimed.
- Scene View's existing mip preparation bakes material factors into its texture path; its shader lighting is not a shared cross-backend color-space policy.
- PBR/specular, environment or ambient light, shadows, Project model-preview lighting, other GPU backends and non-Windows platforms are not implemented or validated.
- The repository was already dirty with unrelated and prior-stage modifications before this substage. No files were reset, staged, committed or pushed.
