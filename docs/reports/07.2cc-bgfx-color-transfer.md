# 07.2cc — BGFX base-color transfer and GPU screenshot checks

## Result

Reconciled the base-color texture and shader transfer path without changing the Renderer API, Scene schema, `.astro-material` schema, external dependencies or authored assets. The CPU helper decodes source sRGB RGB, applies the linear factor once, preserves alpha as linear coverage and builds mips in linear values. The BGFX shader paths no longer decode those already-linear bytes. Unlit texture and vertex-color RGB are output-encoded; lit shaders perform Lambert multiplication in linear space and encode once afterward. Runtime BGFX uses a white shader factor for a texture whose factor is already present in the CPU-prepared image, avoiding the former duplicate multiplication. Vertex-color material factors remain shader-side for lit draws.

The glTF role semantics follow the [Khronos glTF 2.0 material specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#reference-material-pbrmetallicroughness): base-color factor is linear; base-color texture RGB is sRGB and alpha is linear; `COLOR_0` is a linear multiplier. No generic serialized color-space tag was added.

## GPU acceptance

New `runtime.render3d.color_contract.bgfx.smoke` compiles and executes the production Scene View fragment shaders with BGFX D3D11. One screenshot contains four panels; the test reads the GPU capture and compares panel pixels with ±3 byte tolerance:

| Path | Input | Expected and measured RGB | Matching pixels |
|---|---|---:|---:|
| Unlit texture | sRGB 128, linear factor 0.5; CPU upload 28 | 93 | 14,336 |
| Lit texture | same sample, full-diffuse 0.5; shader factor white | 66 | 14,336 |
| Unlit vertex color | linear byte 55 | 128 | 14,336 |
| Lit vertex color | linear byte 55 × factor 0.5 × diffuse 0.5 | 66 | 14,336 |

The screenshot is `build/07.2d-release-clean/samples/3d_prototype/color-contract.tga` (build-local/ignored). CPU unit coverage also asserts sRGB 128 × linear factor 0.5 produces linear BGRA8 byte 28. Existing directional-light, mask, alpha, mip-filter and Runtime Game View regressions were retained. Their cyan/teal screen classifiers were adjusted to the measured encoded output ranges; this preserves visual/coverage checks but does not claim an alpha-blend colorimetric golden.

## Known limits and next step

Scene/Game View attachments and main output remain ordinary BGRA8. Fragment RGB is encoded before reaching that target. Fixed-function alpha blending therefore blends encoded RGB values in the ordinary target; the smoke verifies that the translucent overlap and mask/mip coverage remain visible, not that the blend is linear-light correct. The four-panel color contract also targets the production fragment shaders directly; a numeric reference for the complete Editor offscreen-to-ImGui composition and a second GPU backend are not included. A follow-up should assess linear-light blend targets and final composition, without changing saved material semantics.
