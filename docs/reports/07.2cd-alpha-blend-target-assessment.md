# 07.2cd — BGFX alpha blending and Scene/Game composition assessment

**Status:** assessment complete; no renderer/runtime code changed.
**Environment:** Windows 11 x64, MSVC Release, BGFX Direct3D 11.

## Findings

The 3D Scene View shader outputs RGB after `linearToSrgb`. The material draw state then applies straight-alpha RGB factors (`SRC_ALPHA`, `INV_SRC_ALPHA`) to an ordinary `BGRA8` render target. For a representative sRGB 128 sample with alpha 0.5 over black, that blends encoded values and yields about byte 64; linear-light blending followed by sRGB encoding yields about byte 92. This is a color error, not an alpha-coverage or depth-order failure. Current visual smokes check broad color/coverage ranges and do not measure this value.

The Scene/Game targets are created as ordinary `BGRA8`; the editor swap chain resets with `BGFX_RESET_VSYNC`, without `BGFX_RESET_SRGB_BACKBUFFER`. Scene/Game views clear alpha to 255. Their rendered image is then sampled by the ordinary ImGui image shader with output mode 0 (pass-through) and drawn over the opaque editor background. Since the viewport attachment is opaque, this presentation is effectively a byte-preserving image copy; it is not the source of the 3D overlap error. No numeric assertion currently compares attachment pixels to the viewport region of the final editor screenshot.

SceneTarget also renders 2D sprites before 3D geometry. Sprite images are uploaded as ordinary BGRA8 from WIC and the shared ImGui shader currently passes sampled RGB through. Therefore, changing the entire target to sRGB without updating the 2D sprite texture/tint path would encode those already-encoded values a second time. The fix must cover every draw path feeding an sRGB target, while keeping the final ImGui presentation in the editor's existing output mode.

## Candidate implementation boundary

The cached BGFX API exposes `BGFX_TEXTURE_SRGB_MUTABLE` for textures whose encoding is selected on each bind/attachment, and `BGFX_ATTACHMENT_SRGB` for sRGB rendering to such attachments (`build/spike-deps/bgfx/include/bgfx/defines.h`). The BGRA8 D3D11 backend contains mutable-sRGB format/view selection. This is a viable prototype path, not yet a verified capability on the active adapter or on other backends. At runtime, check both 2D sRGB texture and framebuffer-format support; do not assume the flag succeeded.

Recommended bounded prototype:

1. Create Scene/Game color attachments as mutable-sRGB BGRA8 and explicitly request sRGB attachment views. Keep the existing byte size and depth target.
2. Make all Scene/Game producers output linear RGB before blending: owned 3D shaders already receive linear base-color data after 07.2cc; the 2D sprite shader must decode its sRGB source image and tint according to a documented color role. Keep alpha linear and retain separate straight-alpha RGB/alpha blend factors.
3. Do not enable sRGB globally on the Editor swap chain. Keep the viewport ImGui sample in raw/pass-through mode so the sRGB-encoded attachment bytes display unchanged over the existing opaque editor background.
4. If the backend lacks the required sRGB render-target capability, retain the current path with a diagnostic until a separately assessed linear floating-point/ping-pong fallback is approved. Do not silently label that fallback colorimetrically correct.

An RGBA16F linear target plus an explicit output-encoding pass is a portable alternative candidate, but costs 8 bytes per color pixel rather than 4 and adds a composition pass. It would also need coordinated handling of the 2D sprite producer and final Editor presentation. It is not selected for this bounded D3D11 prototype.

## Acceptance tests for the implementation substage

- GPU readback with known linear/sRGB inputs: sRGB 128, alpha 0.5 over black should be about RGB 92 after an sRGB attachment blend, within a small byte tolerance; the current ordinary target should reproduce the gamma-space value around 64 as a negative/control case.
- Two transparent layers verify order and separate alpha accumulation; opaque and MASK depth occlusion remain unchanged.
- An sRGB 2D sprite and linear tint fixture verifies the full producer path, preventing accidental double encoding.
- Compare the Scene/Game attachment crop with the same viewport rectangle in the final Editor screenshot; because the view alpha is opaque and the ImGui path is pass-through, the interior should match within the capture/readback tolerance.
- Gate the feature on runtime BGFX caps, report the selected path, and run existing BLEND/MASK, directional-light, mip, Game View and full Release CTest regressions.

No material schema, scene format, renderer API, assets, dependencies, or engine behavior changed in 07.2cd. The current workspace was already dirty; all pre-existing user changes were preserved. Baseline logs: `build/07.2cd-prechange-build.log`, `build/07.2cd-prechange-focused-ctest.log`.
