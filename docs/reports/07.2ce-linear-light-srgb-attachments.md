# 07.2ce — BGFX mutable-sRGB attachments and linear-light blend prototype

**Status:** implemented prototype with a full-suite intermittent test failure recorded.  
**Host:** Windows 11 x64, Visual Studio 2022 MSVC Release, BGFX Direct3D 11.

## Change

Scene/Game `BGRA8` targets for BGFX view IDs 1 and 2 now request a mutable sRGB color attachment only when the active BGFX renderer advertises both `BGFX_CAPS_FORMAT_TEXTURE_2D_SRGB` and `BGFX_CAPS_FORMAT_TEXTURE_FRAMEBUFFER`. The attachment is explicitly initialized with `BGFX_ATTACHMENT_SRGB`; its storage remains four bytes per pixel and the existing depth target is retained. If capabilities are absent, the target and shader output use the previous ordinary-BGRA8 path and a warning is emitted once.

The target producers now agree on a linear RGB contract: SpriteRenderer tint bytes are converted from sRGB for sRGB targets; WIC sprite textures are created mutable and bound with sRGB sampling on those targets; 3D Scene and Runtime BGFX shaders skip manual output encoding when writing to an sRGB attachment. Sprite output uniform now suppresses the previous shader-side encoding in this mode. Alpha continues to use linear coverage and the existing straight-alpha factors. The Editor swapchain and project model-preview target are unchanged. ImGui uses non-sRGB sampling for the already encoded target so it can present its stored bytes.

`BgfxSceneRenderer::render` gained a final optional `outputIsSrgbAttachment` argument with a default of `false`, preserving existing callers. No Scene/material serialization format, user asset, or external dependency was changed.

## GPU verification

`runtime.render3d.color_contract.bgfx.smoke` now:

1. Checks the active BGFX BGRA8 sRGB texture/framebuffer caps.
2. Draws the four existing production shader cases to the D3D11 backbuffer.
3. Renders a half-alpha linear vertex color into an explicit mutable-sRGB offscreen BGRA8 attachment.
4. Samples that attachment without sRGB decode into the final test panel and requests a backbuffer screenshot.
5. Reads panel interiors from the TGA and requires at least 1,000 matching pixels per case with ±3 byte tolerance.

| Path | Expected RGB | Measured RGB | Matching pixels |
|---|---:|---:|---:|
| Unlit base-color texture | 93 | 93 | 14,336 |
| Lit base-color texture | 66 | 66 | 14,336 |
| Unlit vertex color | 128 | 128 | 14,336 |
| Lit vertex color | 66 | 66 | 14,336 |
| Half-alpha blend into sRGB attachment | 92 | 92 | 14,336 |

The saved smoke image is build-local: `build/07.2d-release-clean/samples/3d_prototype/color-contract.tga`. Existing Sprite, alpha/MASK/mipmap and transition screenshot classifiers were recalibrated to measured D3D11 sRGB-target colors. Scene/Game view smoke tests passed after the updates.

## Limits and next work

This implementation has been exercised only on the active Windows D3D11 adapter. It does not establish Vulkan, Metal, macOS, Android or iOS behavior. The numeric framebuffer test verifies sRGB attachment blending and a raw BGFX sample to a test backbuffer panel, not pixel-exact equality between the actual Editor Scene/Game attachment crop and its final ImGui window crop. No PBR, color-managed editor chrome or cross-backend guarantee is claimed.

Recommended next bounded work: diagnose the intermittent asset-preview drag smoke and add the explicitly separate Scene/Game-to-ImGui crop comparison if the current Editor capture hooks can expose both images without changing runtime behavior.
