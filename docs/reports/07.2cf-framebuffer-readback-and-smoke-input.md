# 07.2cf — framebuffer readback and Editor smoke input

## Goal

Measure whether the Scene View and Game View BGFX framebuffer attachments arrive in the final Editor window unchanged on the available Windows D3D11 backend, and remove the observed intermittent Asset Browser drag-smoke failure.

## Changes

- Added a smoke-only BGFX readback path: blit each BGRA8 sRGB Scene/Game framebuffer into a separate `BGFX_TEXTURE_READ_BACK` texture, then call asynchronous `bgfx::read`.
- Compared 768 interior RGB samples per viewport against the corresponding region in the final Editor TGA. Acceptance is 99.5% of samples with per-channel tolerance 8/255. Legacy unlit and zero-light Lambert variants both produced **Scene 768/768, maxDelta 0; Game 768/768, maxDelta 0**.
- The readback resources are destroyed before `bgfx::shutdown`; the path runs only for directional-light no-light smoke cases and does not enter the interactive render loop.
- Reworked the Asset Browser model-preview smoke to enqueue ImGui input after SDL backend polling and before `ImGui::NewFrame`. This prevents `ImGui_ImplSDL3_NewFrame` from replacing the synthetic mouse position. The normal application event path is unchanged.
- Updated the directional-light CTest script to print readback metrics and require both capture variants to report them.

## Verification

Windows x64, Visual Studio 2022, Release, BGFX D3D11.

- Build: `cmake --build build/07.2d-release-clean --config Release --target astro_editor --parallel 8` — passed.
- Focused CTest: `ctest --test-dir build/07.2d-release-clean -C Release -V -R "^editor\.runtime_bgfx_directional_light\.smoke$"` — **1/1 passed**. Both variants printed Scene/Game **768/768, maxDelta=0**; existing directional face checks reported Scene 6,724 pixels, Game 2,304, front 6,724, back 0. Legacy and zero-light crop hashes matched (`e9fa020911384770320feb5c310cdb48e8ab3238371b5faca53d6a975b7e8657`).
- Drag stability: `ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --repeat until-fail:5 --output-on-failure -R "^editor\.asset_model_preview\.smoke$"` — **5/5 passed**. The first attempt before moving event injection to after SDL polling failed with no observed hover or drag; this was retained as diagnostic evidence, not hidden.
- Full Release regression: `ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure` — **110 passed, 0 failed, 1 skipped of 111**, 308.63 s. `editor.window_mixed_dpi.sdl.smoke` skipped because this host has no suitable display pair with different content scales.
- `git diff --check` is run after documentation updates.

## Limits and next work

Evidence is limited to the current Windows D3D11 driver and the two no-light fixtures; the point-grid check is not a general golden-image test and other backends, OSes, or alpha/color scenarios are unverified. No Scene/runtime/API or asset format changes were made. Recommended next bounded step: extend the framebuffer comparison matrix to representative material and alpha cases, preserving backend-specific expected tolerances; do not infer cross-platform parity from this result.
