# 07.2ci — opt-in BGFX Vulkan startup smoke

## Scope

Add a diagnostic-only way to verify whether the linked BGFX Editor can initialize Vulkan and load the Editor's shader programs. The normal Editor continues to use Direct3D 11. This is a Windows x64 smoke stage; it does not promise backend parity or enable Vulkan as a normal user setting.

## Changes

- Added `--smoke-bgfx-backend` to verify the default renderer is still D3D11 and `--smoke-bgfx-vulkan` to explicitly request Vulkan with BGFX fallback disabled.
- The Vulkan smoke checks whether the linked BGFX library enumerates Vulkan. It returns CTest's skip code 77 only if that renderer is absent; if Vulkan is listed but initialization/program creation fails, the test fails.
- Added locally generated SPIR-V shader artifacts for BGFX ImGui, Scene View color/textured/lit programs and model-preview vertex stages. Existing D3D11 shader artifacts and embedded ImGui DXBC remain the default path.
- Added two serial CTest smoke cases. The short smoke submits the normal ImGui surface and checks the actual BGFX renderer plus nonzero draw calls.

No dependency was installed, no network was used, and no system display settings were changed. Before edits, a local recovery snapshot of the entire current working tree was created at `refs/codex-recovery/07.2ci` using a temporary Git index; the user's actual index and working tree were left in place.

## Validation

Windows 11 x64, Visual Studio 2022 Build Tools, Release, existing project-local dependency cache:

```powershell
& 'C:/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools/Common7/Tools/Launch-VsDevShell.ps1' -Arch amd64 -HostArch amd64 -SkipAutomaticLocation
cmake --build build/07.2d-release-clean --config Release --target astro_editor --parallel 8
ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure -V -R "^editor\.bgfx\.backend\.(default|vulkan)\.smoke$"
ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure
git diff --check
```

`shadercRelease.exe --help` confirmed a `spirv` profile. A disposable shader probe compiled the Scene lit-color vertex shader and both ImGui shaders to SPIR-V successfully. The full Editor build generated all ten Vulkan artifacts and completed successfully. The final repeated build reported `ninja: no work to do`.

Focused CTest passed **2/2**. Verbose output:

- default mode: `actual=Direct3D 11`, `drawCalls=14`;
- Vulkan mode: `actual=Vulkan`, `drawCalls=14`.

The full Release CTest passed **112 tests, 0 failed, 1 skipped of 113** in **309.65 s**. `editor.window_mixed_dpi.sdl.smoke` was skipped because the host has no suitable display pair with different content scales. The pre-change baseline focused render tests also passed **3/3**.

## Limits

The Vulkan smoke validates renderer initialization, BGFX program creation and the ImGui draw path on this AMD Radeon/Vulkan driver. It does not render a 3D fixture through Scene View/Game View, compare Vulkan framebuffer output with D3D11, profile frame time, or cover another driver, OS or device. Existing material/alpha visual thresholds remain D3D11-specific. Vulkan should not yet be described as a generally supported shipping backend.

## Recommended next substage

Add a small deterministic 3D Scene View fixture for Vulkan, capture its framebuffer, and compare bounded geometry/color evidence against a backend-specific baseline. Keep parity thresholds independent until both renderers are measured. This follow-up is not started.
