# 07.2cj — Vulkan Scene View material smoke

## Цель

Проверить, что opt-in Vulkan backend не только запускает ImGui Editor, но и рисует существующую 3D-сцену с тестовым материалом в Scene View. Сопоставить локальный screenshot-derived признак с обычным D3D11 baseline, не требуя совпадения всего окна.

## Изменения

- `editor/main.cpp`: выбор BGFX depth attachment по реальным render-target capabilities с предпочтением D24S8, D32F, D24, D16; отдельный Vulkan Scene View smoke использует существующую сцену и тестовый материал. В вывод добавлены имя renderer и измерение жёлтой области.
- `editor/CMakeLists.txt`: opt-in CTest сравнения; если исполняемый файл сообщает, что связанная BGFX библиотека вообще не предоставляет Vulkan (код 77), wrapper помечает тест специальной строкой, а CTest классифицирует его как skipped.
- `tests/smoke/editor_bgfx_backend_material_compare.cmake`: два backend smoke сохраняют TGA и сверяют пиксели диагностического материала. Допуск равен `max(8, floor(D3D11_pixels × 0.05))`; это сравнение локальной маски/покрытия, не полнокадровый golden.
- `tests/smoke/editor_primitive_material.cmake`: D3D11 baseline явно подтверждает backend и сообщает цветовую метрику.
- Обновлены `README.md`, `docs/3D_RENDERING.md`, `docs/ROADMAP.md`, `docs/STATUS.md`, `docs/DECISIONS.md`, `docs/TESTING.md`.

## Найденная причина Vulkan framebuffer отказа

На текущей системе BGFX Vulkan сообщает: `BGRA8=982747`, `D24S8=0`, `D32F=946753`, `D24=0`, `D16=946753`, `srgbTarget=1`. Старый Scene/Game target жёстко запрашивал D24S8 и потому не создавался. Теперь выбирается первый поддерживаемый формат; Vulkan использовал D32F, а D3D11 сохраняет D24S8, если он поддерживается.

## Фактические результаты

Среда: Windows x64, VS 2022 Release, локальный AMD GPU/драйвер с BGFX Vulkan. Сборка `astro_editor` прошла; после повторной генерации CMake Ninja сообщил `no work to do`.

Focused backend/material CTest после финальной настройки CTest: **3/3 passed за 22,89 с** (`editor.bgfx.backend.default.smoke`, `editor.bgfx.backend.vulkan.smoke`, `editor.bgfx.vulkan.scene_view.material.smoke`). Более ранний focused набор включал также независимый D3D11 `editor.primitive_material.smoke`: **4/4 passed за 31,09 с**.

Сравнение TGA: D3D11 — **402** жёлтых пикселя, Vulkan — **402**, delta **0**, разрешённый предел **20**. Vulkan Scene View smoke наблюдал viewport, 139 кадров, 7 mesh submissions в последнем кадре и ноль mesh diagnostics в проверяемом primitive pass. Оба backend отрисовали тестовый материал; штатный renderer остаётся D3D11.

Полный Release CTest после функциональных изменений: **113 passed, 0 failed, 1 skipped из 114 за 409,73 с**. Пропущен `editor.window_mixed_dpi.sdl.smoke`, потому что система не имеет требуемой пары дисплеев с разным масштабом. В первом полном прогоне два других smoke нестабильно завершились ошибками (directional-light readback и model-preview visible-pixel classifier); оба прошли отдельный повтор, затем повторный полный Release CTest завершился успешно. Directional-light повтор подтвердил 768/768 Scene и Game samples, model-preview — 2 499 видимых пикселей. После последнего полного прогона внесено только изменение CTest skip-классификации для отсутствующего Vulkan; сборка перегенерирована, backend focused CTest прошёл 3/3.

## Ограничения и риски

- Scene View проверен только на текущем Windows x64/AMD Vulkan устройстве и драйвере. Другие GPU/драйверы, Vulkan на macOS/Linux, mobile и D3D backend variation не проверялись.
- Этот тест намеренно отключает Game View-specific assertions. Нельзя считать Vulkan Game View валидированным этим результатом.
- Сравнивается число пикселей цветового маркера, а не весь кадр; это не измеряет полную цветовую parity и не защищает от одинаковой ошибки обоих путей.
- Наблюдаемый Vulkan путь выбирает D32F; глубина D32F имеет другой формат/точность, чем D24S8. Отдельная проверка depth/stencil behavior на сложных сценах ещё нужна.
- В раннем полном прогоне два визуальных smoke дали временные сбои до успешного focused и полного повторов; это стоит считать признаком нестабильности захвата/окна и исследовать отдельно, если повторится.
- `git diff --check` завершился без whitespace errors. Общая рабочая копия содержит большое количество предварительно изменённых файлов; эти изменения не коммитились и не отправлялись.
