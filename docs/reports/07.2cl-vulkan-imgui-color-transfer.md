# 07.2cl — Vulkan Game View color-path investigation

## Scope

Investigate the unresolved BGFX Game framebuffer → ImGui → Vulkan window readback mismatch from 07.2ck. Keep D3D11 as the unchanged control, preserve the 99.5% acceptance threshold, and change no public API, Scene data, assets, or dependencies.

## Baseline before experiments

- Release `astro_editor` build was initially up to date.
- The repo had 196 dirty paths before this substage; none were cleaned or staged.
- The focused Vulkan Game View CTest recognized the existing readback mismatch and skipped it. D3D11 passed its exact control.
- No `AGENTS.md`/`AGENT.md` repository instructions were present.

## Controlled experiments

1. **Explicit `BGFX_SAMPLER_SRGB` for mutable Scene/Game framebuffer textures.** BGFX documents that a mutable sRGB texture selects its sampling encoding at each bind. The experiment caused both backends to report `0/768` readback matches. It was reverted.
2. **BGFX ImGui output mode 1 on Vulkan.** The BGFX ImGui example defaults to sRGB output mode; the custom renderer currently uses mode 0. Applying mode 1 only for Vulkan also produced `0/768` matches. It was reverted.

The experiments show that these isolated changes are not valid fixes for this application's current swapchain/attachment path. They do not identify the swapchain format or prove which GPU transfer stage differs.

## Final verified state

Restored baseline Release focused CTest command:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure -V -R "^(editor\.runtime_bgfx_game_view_texture\.smoke|editor\.runtime_bgfx_vulkan_game_view\.texture\.smoke)$"
```

Result: **1 passed, 1 skipped, 0 failed**.

- D3D11 Game framebuffer/final-window comparison: **768/768**, `maxDelta=0`, passed.
- Vulkan explicitly selects Vulkan, uses the runtime camera/adapter and submits 2 meshes with textures. Readback: **563/768**, `maxDelta=145`; opposite vertical orientation: **564/768**, `maxDelta=185`. Required: at least **764/768**. The known mismatch is reported as a CTest skip, not a pass.
- `cmake --build build/07.2d-release-clean --config Release --target astro_editor --parallel 8` passed from VS 2022 x64 Developer environment. Three unrelated C4189 warnings remain for unused C# metadata smoke locals.
- Full `ctest --test-dir build/07.2d-release-clean -C Release --parallel 1 --output-on-failure`: **113 passed, 2 skipped, 0 failed of 115 in 263.39 s**. The skips are the known Vulkan Game View mismatch and mixed-DPI smoke, which requires two displays with different scales.
- No production behavior change is retained from the experiments. Only documentation records this investigation.

## Limits and next diagnostic

The actual selected Vulkan swapchain format was not observed, and a color chart was not read back independently at the render attachment, sampled texture, and final window. Next, add a narrowly scoped diagnostic for those three stages and record the BGFX/Vulkan swapchain format before attempting another transfer change. Keep the 99.5% threshold. Vulkan Game View remains visually unverified on this and other systems.
