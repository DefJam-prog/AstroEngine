# 07.2cm — Vulkan surface format and known-color chart

## Scope

This diagnostic substage measured the Vulkan Win32 surface format selected by BGFX and compared a known BGRA8 chart after ImGui texture sampling with the final-window screenshot. It did not change the regular renderer selection, relax the 99.5% Game View parity threshold, or introduce dependencies.

## Findings

- The selected AMD Radeon Graphics surface format is `VK_FORMAT_B8G8R8A8_UNORM` (native format 44), color space `VK_COLOR_SPACE_SRGB_NONLINEAR_KHR` (enum value 0). BGFX requested `BGRA8` with `srgbBackbuffer=0`; the surface offers both UNORM and SRGB variants.
- A test-only `BGRA8` texture marked `BGFX_TEXTURE_SRGB_MUTABLE` is sampled by the existing ImGui BGFX path and rendered to the final window. The chart has four source RGB values: `(0,0,0)`, `(192,128,64)`, `(30,100,200)`, `(255,255,255)`.
- Captured values were `(3,3,3)`, `(190,126,63)`, `(32,100,198)`, `(252,253,254)`: all **4/4** samples are within **8/255** per-channel tolerance; maximum channel delta is **3**.
- This narrows the failure: a simple BGRA8 texture through ImGui to the Vulkan window matches. The separate Game View framebuffer-to-window comparison remains **563/768**, maximum delta **145**, below the existing 99.5% threshold. Its CTest remains an explicit skip for this recognized mismatch; no Vulkan Game View parity claim is made.

## Implementation and checks

- Added a test-only Vulkan surface-format probe using the installed SDL Vulkan loader and existing Khronos headers; it matches the BGFX-selected physical device and mirrors BGFX's current BGRA8 non-sRGB preference. No vendored dependency was modified.
- Added an opt-in `ASTRO_VULKAN_COLOR_CHART_SMOKE` mode to the existing Vulkan textured Game View fixture and a dedicated CTest. The chart checks the final screenshot using four known color samples; normal D3D11 UI/rendering is unchanged.
- Release build: `cmake --build build/07.2d-release-clean --config Release --parallel 8` (VS 2022 x64 Developer environment) — passed.
- Focused tests: localization, D3D11 default, Vulkan startup, Vulkan Game View baseline and chart — **4 passed, 1 skipped, 0 failed**. Vulkan baseline skip is the existing 563/768 mismatch.
- Full Release CTest: `ctest --test-dir build/07.2d-release-clean -C Release --output-on-failure --parallel 1` — **114 passed, 2 skipped, 0 failed of 116** in 207.75 s. Skips: Vulkan Game View composition mismatch and unavailable mixed-DPI display setup.

## Limitations and next step

The chart proves only this GPU/driver, BGRA8 mutable texture, ImGui sampling shader, and window surface path. It does not capture an intermediate shader output or establish cross-driver behavior. The Game View mismatch is still unresolved; the next substage should instrument the Game View texture contents and its sampled result at stable points, then compare UV orientation, viewport/scissor, and source target dimensions without changing acceptance thresholds.
