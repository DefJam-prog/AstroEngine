# 07.2co — Vulkan Game View capture coordinate scaling

## Scope

Run the existing Vulkan Game View fixture at two requested client sizes and record the window/backbuffer dimensions at the exact frame where BGFX screenshot capture is requested. Compare the resulting TGA dimensions and viewport rectangle to the offscreen Game View target. No production renderer code, API, asset format, or dependency changed.

## Results on this Windows x64 AMD/Vulkan host

| Requested client | SDL pixels at capture | BGFX stats at capture | TGA/screenshot | Game View target | Screenshot viewport | readback comparison |
|---|---:|---:|---:|---:|---:|---:|
| 1100×720 | 1100×720 | 1100×720 | 1280×800 | 624×416 | `(288,217)+726×462` | 563/768, max delta 145; alternate Y 564/768, max delta 185 |
| 1280×800 | 1280×800 | 1280×800 | 1280×800 | 624×416 | `(248,196)+624×416` | 768/768, max delta 0 |

At 1280×800, the screenshot viewport rectangle has the same dimensions as the Game View target. All 24 rows report 32/32 matches, and each of the five fixed BGRA probe pairs matches exactly (`102,86,75`). At 1100×720, the capture TGA remains 1280×800 while SDL and BGFX stats report 1100×720; the screenshot viewport is larger than the 624×416 target. The two right/bottom probe locations land on the captured background `(38,38,38)` instead of target `(102,86,75)`.

These measurements strongly associate the existing mismatch with a size/capture-coordinate discrepancy on this host. They do not identify whether Vulkan surface extent, screenshot callback behavior, UI layout, or the coordinate transform is responsible. BGFX `getStats()` dimensions are not treated as proof of Vulkan swapchain image extent; the TGA header is direct capture evidence. The 99.5% requirement remains unchanged, and the 1100×720 Vulkan parity path remains unverified.

## Reproduction

```powershell
$vsDevCmd='C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\Tools\VsDevCmd.bat'
& cmd.exe /d /s /c "call `"$vsDevCmd`" -arch=x64 -host_arch=x64 >nul && cmake --build build/07.2d-release-clean --config Release --target astro_editor --parallel 8"
ctest --test-dir build/07.2d-release-clean -C Release --output-on-failure --parallel 1 -R "^(editor\.runtime_bgfx_vulkan_game_view\.tap(\.1280x800)?\.smoke|editor\.runtime_bgfx_game_view_texture\.smoke)$"
ctest --test-dir build/07.2d-release-clean -C Release --output-on-failure --parallel 1
```

For direct captures, set `ASTRO_VULKAN_GAME_VIEW_TAP_SMOKE=1` and `ASTRO_VULKAN_GAME_VIEW_TAP_SIZE` to `1100x720` or `1280x800`; this override applies only to the explicit Vulkan Game View tap smoke.
