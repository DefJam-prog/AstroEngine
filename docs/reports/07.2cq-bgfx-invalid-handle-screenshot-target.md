# 07.2cq — BGFX invalid-handle screenshot target

## Scope

Resolve which framebuffer BGFX captures for `bgfx::requestScreenShot(BGFX_INVALID_HANDLE)` after the fixed-size Vulkan resize runs. This was a source-trace/diagnostic substage; it intentionally does not change the renderer or vendor BGFX.

## Findings

The BGFX API accepts an invalid handle for screenshots. In the Vulkan backend, `getFrameBuffer(handle)` returns `m_backBuffer` when the handle is invalid. `requestScreenShot` reads that framebuffer's `m_swapChain`; `readSwapChain` copies the selected swapchain image and reports width/height from `m_sci.imageExtent`. Therefore this API captures the main BGFX window backbuffer, not the Scene/Game View offscreen framebuffer.

On the prior 1100×720 controlled run, SDL drawable, `bgfx::reset` size, BGFX stats, and Vulkan surface `currentExtent` for the Editor HWND all measured 1100×720; the TGA measured 1280×800. In the 1280×800 run, those extents agreed and the 768-sample comparison was exact. This proves which BGFX framebuffer the request selects and narrows the stale-size observation to its backbuffer/swapchain path. It does not prove whether resize timing, retained BGFX state, or capture scheduling causes the stored extent mismatch.
