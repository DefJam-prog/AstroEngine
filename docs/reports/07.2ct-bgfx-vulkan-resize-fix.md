# 07.2ct — BGFX Vulkan fixed-surface resize fix

## Scope

Fix the diagnosed Vulkan swapchain extent mismatch for the locally staged BGFX revision and verify stable size, growth, shrink-back, and the existing Game View readback threshold. This substage does not change AstroEngine's public renderer API, default backend, assets, or scene formats.

- Required project docs were reviewed; no `AGENTS.md` exists.
- Git already contained extensive user/project modifications and untracked artifacts. They were left untouched.
- Release build directory: `build/07.2d-release-clean`; CMake/CTest 4.4.4; MSVC 14.44 and Visual Studio 2022 Build Tools available through `VsDevCmd.bat`.
- Before edits, focused CTest: **2 passed, 1 recognized skip, 0 failed**. The 1100×720 tap captured 1280×800 images after shrink and measured 563/768 Game View matches; stable 1280×800 passed exactly.

- Local BGFX was clean before this stage at `eebf5686a8c5f1c77e1af2dad17b5746ba17da8f`.

## Implementation

The pinned BGFX Vulkan `SwapChainVK::update` path now queries surface capabilities when no existing recreation condition applies. If `currentExtent` is fixed and differs from the currently selected swapchain image extent, the usual recreation path runs, rebuilding swapchain attachments as well. Variable extents (`UINT32_MAX`) preserve the pre-existing descriptor-driven path.

The unified diff is tracked at `third_party/patches/bgfx/07.2ct-vulkan-fixed-surface-extent.patch`. `scripts/build_bgfx_07_2ct.ps1` validates the exact BGFX revision, applies the patch once, refuses unrelated dirty BGFX worktrees, and builds the BGFX Release library. This keeps the ignored dependency cache reproducible without mutating it at ordinary CMake configure time.

The resize smoke now asserts all nine image extents instead of only checking for non-zero dimensions: initial 1100×720, four post-grow captures at 1280×800, and four post-shrink captures at 1100×720.

## Limitations

This fix is verified only on Windows x64, the pinned BGFX commit, and one AMD Vulkan driver. Other drivers, devices, BGFX revisions, and variable-extent surfaces are not independently verified. D3D11 remains the default. The Vulkan probe performs a surface-capabilities query when BGFX evaluates a swapchain update; overhead was not benchmarked separately.
