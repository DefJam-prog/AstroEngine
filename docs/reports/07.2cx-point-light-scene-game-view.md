# 07.2cx — PointLight3D in Scene and Game View

## Scope

Add a bounded, optional point-light path to the existing directional diffuse lighting. This substage does not add PBR, shadows, spotlights, a light Inspector, a new dependency, or cross-driver claims.

## Implementation

- Added optional `PointLight3DComponent` with stable component ID, enabled flag, linear RGB `[0,1]`, intensity `[0,64]`, and scene-unit range `[0.1,10000]`.
- Added transactional typed `light3d.add_point`, `light3d.set_point`, and `light3d.remove_point` commands. Dry-run, validation, Undo/Redo, stable component identity, and command-catalog ordering are covered.
- Scene writer now emits v13 and adds `astro.PointLight3D`; v1–v12 remain readable. A v12 file does not acquire an inferred point light and is not rewritten on load; explicit save upgrades it.
- The backend-neutral packet resolves the owning Transform origin through the hierarchy, sorts enabled point lights by EntityId, includes stable component identity and range, caps the list at four, and records a diagnostic for excess lights.
- Project-owned BGFX color and textured shaders interpolate world position and evaluate direct Lambert point diffuse. Attenuation is `max(1 - distance/range, 0)^2 / max(distance^2, 0.01)`; all direct diffuse is summed and clamped to `[0,1]`. Scene View and Runtime Game View use the same uniforms. With zero enabled lights, the earlier unlit path remains selected.
- Added a D3D11 point-light Editor smoke which requires blue-lit pixels in Scene View and active Runtime Game View; the existing directional smoke remains in the focused regression.

## Limitations

Point-light authoring is currently available through Scene APIs/typed commands and test fixture code, not an Editor Inspector control. Lighting is bounded direct Lambert in the current BGFX D3D11 path; the chosen unitless intensity/attenuation is a prototype contract, not physically calibrated output. Shadows, spots, PBR/specular response, mobile/macOS, and another GPU/driver remain unverified.
