# 07.2cy — PointLight3D Inspector authoring

## Scope

Expose the existing optional `PointLight3D` component in the selected-entity Inspector without changing the Scene schema, renderer contract, or public Scene API.

## Baseline

- The project already had a large dirty worktree from earlier stages; all pre-existing tracked and untracked files were preserved.
- The Release build at `build/07.2d-release-clean` reported `ninja: no work to do` before edits.
- Baseline localization, primitive material, and directional-light tests passed; a separate baseline point-light smoke passed **1/1**.
- CMake and CTest were available at version **4.4.4**.

## Implementation

- Added a localized `PointLight3D` Inspector section with Add/Remove, enabled state, linear RGB, intensity `[0,64]`, and range `[0.1,10000]` controls.
- The Inspector keeps an edit draft keyed by Scene/entity/component identity. Apply executes `light3d.set_point`; component creation and removal execute `light3d.add_point` and `light3d.remove_point`. Scene command validation remains authoritative, and invalid values are reported rather than silently clamped.
- Existing transactional commands preserve Undo/Redo. The point-light Editor smoke checks all controls are present and exercises typed Add/Set/Remove plus Set Undo/Redo and Remove Undo. Existing Scene/Game blue-pixel checks remain in the same test.
- Added Russian labels and explicit localization assertions. No file-format, schema, dependency, or public API changes.

## Limitations

The UI smoke confirms controls render and the command transactions pass, but does not automate pointer-driven edits of the Inspector widgets. Rendering evidence is from the current Windows x64 D3D11 host; another GPU/driver remains unverified. Shadow, spot, and PBR controls are outside this substage.
