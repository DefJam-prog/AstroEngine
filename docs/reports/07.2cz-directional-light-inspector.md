# 07.2cz — DirectionalLight3D Inspector authoring

## Scope

Expose the existing `DirectionalLight3D` component in the selected-entity Inspector without changing Scene schema, command contracts, or renderer behavior.

## Baseline

- The Release build at `build/07.2d-release-clean` reported `ninja: no work to do` before edits.
- The worktree already contained many unrelated tracked and untracked edits from prior stages; none were reverted.
- Before changes, the related localization, Scene, Scene-command, directional-light render, and point-light regression tests passed **5/5**.
- CMake and CTest 4.4.4; x64 Visual Studio 2022 Build Tools available through `VsDevCmd.bat`.

## Implementation

- Added a localized Inspector section with Add/Remove, enabled state, linear RGB, and intensity `[0,64]` controls.
- Apply/add/remove use the existing `light3d.set_directional`, `light3d.add_directional`, and `light3d.remove_directional` transactional commands. The edit draft is keyed by Scene/entity/component identity; invalid values remain subject to Scene command validation.
- Direction is not authored as a duplicate field. The Inspector displays the resolved world direction and explains that it follows local `-Z` through parent rotations; the entity Transform remains the authoring control.
- Extended the existing directional-light Editor smoke with controls and command-history assertions using a separate hidden fixture entity. Existing Scene/Game lit pixels and Scene View front/back orientation assertions remain intact.
- Added Russian translations and localization assertions. No schema, public API, dependency, or render-path changes.

## Limitations

The smoke verifies that Inspector controls render and that the corresponding typed transactions retain Undo/Redo. It does not automate pointer-driven UI edits. Render evidence uses the current Windows x64 D3D11 adapter; a second GPU/driver was not available in this substage. Shadows, PBR/specular lighting, other backends, and platforms are outside scope.
