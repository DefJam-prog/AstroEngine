# 07.2d2 — Light Inspector RGB pointer input

## Scope

Extended the existing point and directional light Inspector smoke scenarios so they independently pointer-drag the red, green, and blue slider controls. Each drag is checked in the draft before Apply. The existing typed command then applies the complete color to the Scene component, and Undo must restore the original color. The smoke also retains the prior Enabled and intensity pointer interactions.

The harness derives each track from the rendered `SliderFloat3` geometry, including ImGui's per-item width and inner spacing. It uses the existing SDL/ImGui input queue and typed light commands. No public API, scene schema, renderer behavior, dependency, or user asset changed.

## Verification

Release build:

```powershell
cmake --build build/07.2d-release-clean --config Release --target astro_editor astro_editor_localization_tests --parallel 4
```

Result: successful. MSVC reported three existing C4189 warnings for unused variables in C# metadata smoke code.

Focused regression:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --output-on-failure --parallel 1 -R "editor\.(localization\.unit|runtime_bgfx_directional_light\.smoke|runtime_bgfx_point_light\.smoke)$"
```

Result: **3/3 passed in 13.70 s**. Point and directional light smokes independently moved all three RGB channels, verified their draft changes, applied them through typed commands, and restored the initial state with Undo.

Full regression:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --output-on-failure --parallel 1
```

Result: **119 passed, 0 failed, 1 skipped of 120 in 475.32 s**. `editor.window_mixed_dpi.sdl.smoke` was skipped because the host does not provide two displays with distinct scaling.

## Limits

Verified on one Windows x64/MSVC Release host with the available D3D11 adapter. macOS, Linux, additional GPU drivers, keyboard navigation and gamepad input remain untested. This verifies Inspector input and the existing command transaction; it does not establish color-space or cross-backend rendering parity.

## Recommended next substage

Assess keyboard/gamepad accessibility of the light Inspector controls and define a separate focused acceptance test before changing input behavior. Stop here until the user confirms the next substage.
