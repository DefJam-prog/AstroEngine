# 07.2d3 — Editor Inspector keyboard and gamepad accessibility assessment

## Scope

Assess the existing point/directional light Inspector path for keyboard and gamepad navigation. This is an assessment only: no runtime code, SDL lifecycle, project settings, scene data, dependencies, or user assets were changed.

## Findings

- `editor/main.cpp` enables `ImGuiConfigFlags_NavEnableKeyboard` and forwards polled SDL events to `ImGui_ImplSDL3_ProcessEvent`. Keyboard navigation is configured, but current Editor tests do not prove focus traversal through Inspector controls, keyboard editing of the Enabled/intensity/RGB fields, or keyboard activation of Apply and Undo.
- The bundled ImGui SDL3 backend can enumerate and poll a connected gamepad, including button and analog input, and observes add/remove events.
- AstroEngine initializes SDL with `SDL_INIT_VIDEO` only and does not set `ImGuiConfigFlags_NavEnableGamepad`. The backend capability is not sufficient by itself, so Editor gamepad navigation is not currently active/configured.
- `SDLInputAdapterTests.cpp` covers keyboard and gamepad-to-action mapping for Runtime. It does not exercise ImGui navigation in the Editor. The light Inspector smoke tests cover pointer interaction only.

## Risks and proposed acceptance for implementation

Keyboard navigation may be enabled globally while individual widgets, focus transitions, or Apply/Undo remain unusable without a pointer; this needs behavior-level smoke assertions. SDL gamepad enumeration requires explicit gamepad subsystem initialization. Add it with clear lifecycle ownership, then use an SDL virtual gamepad in tests so CI does not depend on physical hardware. Test connect/disconnect cleanup and verify the app's configured gamepad actions do not unexpectedly affect other SDL consumers. Real hardware, macOS/Linux, and alternative backends require separate platform checks.

Proposed checks: keyboard focus reaches Enabled, intensity, each RGB channel and Apply; arrow keys change focused values; activation applies the draft; Undo restores the original values. A virtual gamepad should navigate focus, adjust a slider, activate Apply, and disconnect without leaving stuck input state.

## Recommended next substage

Implement and smoke-test Inspector keyboard navigation first. Keep gamepad subsystem initialization and virtual-controller support as a separately reviewable implementation unless both are explicitly scoped together. Stop here until the user confirms the implementation stage.
