# 07.2d5 — SDL keyboard route in light Inspector

## Scope

Replace direct ImGuiIO test injection with SDL keyboard events for the point and directional light Inspector smokes. This remains test-harness work; it does not add product keyboard shortcuts, commands, scene schema, dependencies, or physical-device coverage.

## Verified

- Smoke events carry the Editor SDL window ID and enter via `SDL_PushEvent`.
- The ordinary `SDL_PollEvent` loop forwards them through `ImGui_ImplSDL3_ProcessEvent`.
- Tab navigation reaches Enabled and intensity controls.
- Enter toggles the Enabled draft.
- The Scene light component remains unchanged until Apply.
- Point and directional rendering and existing pointer command/Undo checks still pass.

These are synthetic SDL events using the production application route. They do not prove OS-level delivery or behavior with a physical keyboard.

## Not verified

- Numeric keyboard editing of RGB/intensity.
- Keyboard activation of Apply or Undo.
- Physical keyboard input, another platform, or another graphics backend.
- Editor gamepad navigation.

Numeric field activation and keyboard Apply were attempted in the smoke but did not produce the requested draft/command changes. Those assertions were removed instead of being replaced with pointer input, and the gap remains open.

## Build and tests

Build from an x64 Visual Studio Developer environment:

```powershell
cmake --build build/07.2d-release-clean --config Release --target astro_editor astro_editor_localization_tests --parallel 4
```

Build succeeded. MSVC emitted three existing C4189 warnings in the C# metadata smoke code.
