# 07.2d6 — Light Inspector keyboard edit diagnostic

## Scope

Determine why the SDL-backed Point/Directional Light intensity slider does not accept numeric keyboard input. This increment adds diagnostics to the existing Editor smoke only. It does not change Inspector behavior, command APIs, Scene data, or dependencies.

## Findings

- Tab reaches the intensity slider and ImGui reports `IsItemFocused()`.
- `ImGui::GetIO().NavVisible` is true during the probe.
- Enter does not activate the slider: `IsItemActive()` remains false.
- ImGui reports `WantTextInput=1`; the queued `SDL_EVENT_TEXT_INPUT` with the Editor's window ID is accepted by `ImGui_ImplSDL3_ProcessEvent`.
- The tested text does not change the draft: Point remains **4.0**, Directional remains **3.5**.
- The existing Enabled/Scene draft check and pointer-driven Apply/Undo coverage still pass.
- A trial global `ConfigNavCursorVisibleAlways` setting caused the existing pointer smoke to fail. It was removed and is not part of the final change.
- Keyboard Apply/Undo was not attempted because the numeric draft did not change. Physical keyboard behavior was not tested.

Interactive follow-up in the normal Release Editor window reproduced the same outcome outside the smoke harness. A temporary project was created under ignored `build/07.2d6-manual-keyboard/KeyboardProbe`; an unsaved Entity with PointLight3D was added. Tab moved through Enabled and the position fields to Intensity. Windows UI keyboard input (`Enter`, `Right`, then text `5.25`) left the displayed intensity at **1.00** and did not enable Apply. No scene was saved. This is OS-injected keyboard input through the interactive Editor, not a test `SDL_PushEvent`; it still does not prove behavior with a physical keyboard device.

The same failure in the regular interactive Editor rules out the smoke window as the only cause and establishes a user-facing keyboard-edit gap on this Windows build. The exact responsible layer (focus/activation, ImGui, or Inspector behavior) remains unlocalized. No fix is claimed.

## Build and tests

Environment: Windows 11 x64, MSVC Release, BGFX D3D11, build tree `build/07.2d-release-clean`. Build from an x64 Visual Studio Developer environment:

```powershell
cmake --build build/07.2d-release-clean --config Release --target astro_editor --parallel 4
```

Build succeeded with three existing C4189 warnings in C# metadata smoke code.

Focused diagnostic:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --output-on-failure --parallel 1 -V -R "editor\.(runtime_bgfx_directional_light|runtime_bgfx_point_light)\.smoke$"
```

Result: **2/2 passed in 7.62 s**. Both captured outputs show `sliderActiveAfterEnter=0`, `navCursorVisible=1`, `textInput=1`, `sdlTextAccepted=1`, and `numericDraftEdited=0`.

Full regression:

```powershell
ctest --test-dir build/07.2d-release-clean -C Release --output-on-failure --parallel 1
```

Result: **119 passed, 0 failed, 1 skipped of 120 in 172.04 s**. `editor.window_mixed_dpi.sdl.smoke` was skipped because this host has no suitable pair of differently scaled displays.
