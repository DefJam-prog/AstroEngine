# 07.2g — normals and UV0 in bounded mesh import

## Implemented

- Added `Vec2`, `MeshVertex::normal`, and `MeshVertex::texCoord0`.
- `MeshData::create(vertices, indices)` remains source-compatible and reports optional channels absent. Callers can mark present normals/UV0; finite-value validation applies to present channels.
- glTF still requires bounded, non-sparse FLOAT VEC3 POSITION. Optional NORMAL must be a matching, bounded, non-sparse FLOAT VEC3 with finite, non-zero values. Optional TEXCOORD_0 must be a matching, bounded, non-sparse FLOAT VEC2 or normalized UNSIGNED_BYTE/UNSIGNED_SHORT VEC2. Normalized integer UV values are converted to floats.
- Unknown/duplicate attributes, TEXCOORD_1+, mismatched counts, sparse accessors, invalid formats and buffer-view violations fail import. Source files remain read-only.
- Derived geometry cache advances to ASTROMSH v2 and stores channel flags/data. New entries use `.v2.astro-mesh-cache`; existing v1 files are left untouched and ignored.

## Limits

This adds validated data only. The current Editor/BGFX passes do not upload or consume normals/UV. No texture decoding/sampling, normal maps, PBR, lights, shadows, performance budget, macOS/mobile build, or fuzz/sanitizer run is included. TEXCOORD_1+ and every unsupported vertex attribute remain rejected.
