# 07.2i — base-color color space and linear factor

## Scope

Define and test the operation order for one sRGB base-color image combined with its linear material factor. Keep the work in the isolated Windows BGFX sample. Preserve the 07.2h white-factor image sampling smoke and do not integrate Editor/Game View or other PBR roles.

## Contract and implementation

- Source RGB channels are interpreted as sRGB-encoded values; alpha is linear.
- Decode RGB using the IEC 61966-2-1 piecewise transfer: `c / 12.92` at and below `0.04045`, otherwise `((c + 0.055) / 1.055) ^ 2.4`.
- Multiply the decoded linear RGB by the linear `baseColorFactor` RGB. Multiply alpha directly by the linear factor alpha.
- Round the result into a temporary linear BGRA8 UNORM buffer. The input bytes remain read-only; the source PNG and AssetRegistry content-addressed cache are not modified.
- The D3D11 sample uploads the prepared buffer as a linear BGRA8 texture and enables `BGFX_RESET_SRGB_BACKBUFFER` for output encoding. This avoids claiming or requiring hardware sRGB texture view support in this prototype.
- The factor fixture uses `(0.65, 0.60, 0.80, 1)`. Full-coverage primary-color texels should encode to approximately `(212, 203, 232)` for display. BGFX screenshot readback checks four expected fixture color families within fixed channel ranges.
- Added unit tests for sRGB mid-gray conversion, per-channel multiplication, linear alpha, zero factors, partial/empty pixel buffers, non-finite factors and factor range.

This is CPU preparation rather than the likely final renderer path. It has per-image CPU cost and quantizes intermediate linear values to 8 bits before sampling.

## Limits

- Verified only on Windows x64/MSVC and BGFX Direct3D 11.
- CPU sRGB conversion and 8-bit linear intermediate; no native BGFX sRGB texture sampling test.
- No mipmaps, sampler filtering/addressing authoring, texture transforms, alpha blending, other material roles, Editor/Game View, PBR, lighting, or shadows.
- Screenshot tolerance verifies coarse encoded-color regions, not exact framebuffer equality or display calibration.
