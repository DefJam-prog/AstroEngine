# 07.2k — Scene View source material and project override policy

## Result

The Editor Scene View now selects a material for each imported glTF primitive using this order:

1. A registered project material override on the `MeshRenderer`.
2. The source glTF material assigned to that primitive.
3. Imported vertex colors when no material is assigned.

An explicit override that cannot be resolved is treated as an error and reported. Geometry remains visible through the vertex-color shader; Scene View does not hide the error by selecting the source material instead. If the override value changes, the preview cache resolves and prepares the new selection again.

`ResolvedSceneMesh` now carries the optional source material index, a separate project override ID, the imported base-color factors and texture coordinate, and a checked local external image path where applicable. This keeps importer provenance separate from authoring overrides. Scene View uses only `baseColorFactor` and `baseColorTexture` on UV0. It reads local source image bytes under project `Assets` through bounded WIC decoding without registering/importing or rewriting them. Embedded/data-URI and remote images are not decoded/fetched. Unsupported/missing images, non-UV0 bindings, decode/factor/upload errors and invalid explicit overrides keep the mesh on vertex-color fallback with diagnostics.

The Editor smoke now draws five cases: a valid project texture override, a source glTF texture with no override, a project material requiring unsupported UV1, a nonexistent explicit material override, and an unresolved model AssetId. It checks the two textured submissions, fallback/diagnostic counts, hierarchy/Frame All behavior and broad screenshot pixel coverage. A glTF integration test checks source material index/factors, UV0 and confined external path resolution, and verifies that source metadata remains available alongside a project override.

## Limits and next step

This is not a general material system. Only base color and UV0 are previewed, only for Windows D3D11 Scene View. Material inspector mouse interaction was not automated. There is no Game View integration, alpha/sampler/texture-transform handling, other PBR roles, lighting, shadows, or non-Windows implementation. The image color check is a broad coverage guard, not an exact golden.

Recommended next substage: 07.2l, expose the active source/override choice and unsupported material features clearly in the Inspector, and exercise changing/clearing that choice through the existing command API in an Editor authoring smoke.
