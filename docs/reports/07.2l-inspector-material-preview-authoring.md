# 07.2l — Inspector material preview authoring

## Result

The `MeshRenderer` Inspector now tells the user which Scene View material path is active:

- A valid project material override.
- The glTF source material when no override is assigned.
- Imported vertex colors when the primitive has no source material.
- A visible vertex-color fallback when the explicit override cannot be resolved.

When a valid override is active and the primitive also has a source material, the Inspector says clearing the override returns to the glTF source. The Inspector states the actual preview scope: base-color factor and local UV0 texture only. Alpha, sampler transforms and other PBR properties are not rendered. New text is localized into Russian.

Editor smoke uses a separate source-material MeshRenderer. It invokes `entity.set_mesh_material_override` through the existing `CommandRegistry` to assign a registered project material, verifies that AssetId, invokes the same command to clear it, and verifies zero. It then clears only those test command-history entries so the smoke's existing keyboard Undo/Redo checks remain independent. The Inspector smoke checks the active override label, clear-to-source hint, and feature-limit text. Existing visual smoke still checks Scene View texture/fallback diagnostics and screenshot coverage.

## Limits and next step

Smoke drives the typed command and checks Inspector state; it does not automate ImGui mouse clicks. The material preview remains limited to the Windows x64 D3D11 Scene View, base color, and UV0. Game View, alpha, sampler transforms, other PBR roles, lighting and shadows remain unsupported.

Recommended next substage: 07.2m, first assess glTF sampler wrap/filter and texture-coordinate transform support for the existing base-color path, then define narrow fixtures and tests before implementation.
