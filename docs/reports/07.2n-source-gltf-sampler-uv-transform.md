# 07.2n — Source glTF base-color sampler and UV transform

## Result

Implemented a narrow Windows Editor Scene View path for source glTF base-color sampler settings and `KHR_texture_transform`. No third-party dependency, Scene format or `.astro-material` file format changed.

## Changes

- glTF import metadata now carries validated sampler wrap/filter enums and optional per-binding transform values. The existing fastgltf transform parser is enabled. `KHR_texture_transform.texCoord`, when present, takes precedence over the core binding's `texCoord`.
- `SceneMeshResolver` transfers the selected source base-color sampler and transform to the Editor.
- Scene View maps REPEAT, MIRRORED_REPEAT and CLAMP_TO_EDGE to BGFX U/V flags. Explicit nearest/linear filters are applied per draw. With omitted sampler/filter values, the preview uses BGFX's documented repeat/linear defaults.
- Offset, rotation and scale follow the Khronos order: scale, counter-clockwise rotation, then offset. The transform is applied to a CPU copy used for the GPU vertex buffer. Imported geometry/cache and original image bytes remain unchanged.
- Mipmapped minification filters use the existing vertex-color fallback and diagnostic because the upload creates a single mip level.
- Project `.astro-material` overrides keep their prior Clamp + Point behavior and have no transform data. This gap is explicit; no material format migration was made.
- Russian Inspector text now distinguishes source glTF sampling from project-override sampling and names the mip fallback.

## Verification

Pre-change Windows x64 Release baseline: build reported `ninja: no work to do`; CTest passed **58/58 in 21.86 s**.

Focused build and tests:

```powershell
cmake --build build/07.2d-release-clean --target astro_gltf_importer_tests astro_base_color_texture_tests astro_editor astro_editor_localization_tests --parallel 8
ctest --test-dir build/07.2d-release-clean -R '^(runtime\.render3d\.gltf\.import\.integration|runtime\.base_color_texture\.unit|editor\.localization\.unit|editor\.smoke)$' --parallel 1 --output-on-failure
```

Result: **4/4 passed in 4.27 s**. Integration tests cover explicit sampler values, omitted filter/wrap defaults, transform values and texCoord precedence, plus cache reconstruction. Unit tests cover identity, scale/rotation/offset order, non-finite input and overflow. Editor smoke verifies BGFX flags and a transformed source-material submission.

The first full CTest found four Access violations in standalone BGFX samples because one generated sample object still used the old `ResolvedSceneMesh` layout. Only that generated object was removed with target-scoped Ninja clean and rebuilt; no source file was changed by the recovery. The four sample smokes then passed **4/4 in 4.16 s**. Final Release build succeeded, and the subsequent full CTest passed **58/58 in 19.92 s**.

## Limits

- Windows x64/D3D11 Scene View only; not Game View, a cross-platform renderer, or a full PBR implementation.
- Only source glTF base-color uses sampler/transform data. Project overrides still use fixed Clamp + Point and cannot author transforms.
- UV0 only. A nonzero base-color texCoord, including an extension override, keeps the existing diagnosed vertex-color fallback.
- Mipmapped `minFilter` values fall back visibly; no mip-chain generation is implemented.
- Files declaring any `extensionsRequired` remain rejected by the importer's existing fail-closed policy, including files that require `KHR_texture_transform`.
- The smoke checks sampled submissions, sampler flags, broad screenshot coverage and fallback counters. It is not a pixel-exact visual golden or cross-driver comparison.

Recommended next substage: **07.2o — add sampler and transform authoring to project material overrides with a versioned format migration and tests**, keeping the current fallback for mipmapped filters until a separate mip-chain implementation is verified.
