# 07.2o — Project material sampler and UV authoring

## Result

Project material overrides now store base-color sampler and UV transform settings. `.astro-material` v2 adds U/V wrapping, minification/magnification filters and offset/rotation/scale. Schema-v1 files remain readable with the former Scene View defaults (Clamp + Nearest and identity UV transform); opening or registering them does not rewrite their source bytes. New `MaterialAssetData` defaults to v2.

The MeshRenderer Inspector edits a draft and writes only after an explicit **Save material settings** action. `AssetRegistry::saveMaterial` verifies the source has not changed outside the registry, validates referenced image AssetIds, atomically replaces the material file through a flushed temporary file, refreshes the registry's source hash/schema version, and preserves the material AssetId. A stale source is rejected without overwriting its bytes. Editing a v1 draft promotes it to v2 on save.

Scene View applies wrap/filter flags and the UV0 transform copy to project overrides, using the same one-mip path as source glTF materials. Editor smoke verifies project BGFX flags, transform submission and that the Inspector controls are present. Mipmapped minification remains a visible diagnostic with vertex-color fallback.

## Limits

Only base-color material sampling is rendered, only on the optional Windows D3D11 Scene View path with UV0. Mipmapped minification, Game View, alpha, other material texture roles, cross-platform validation and pixel-exact visual goldens remain unsupported. The Inspector does not provide GUI mouse automation; smoke verifies controls and the render submission state. No new dependency or Scene/command schema was introduced.
