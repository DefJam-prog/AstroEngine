# 07.2p — Bounded mip-chain upload and shared Scene View texture cache

## Scope

Implemented the next material-preview increment only. The Windows Editor Scene View can generate and upload mip levels for project and source glTF base-color textures, and reuse equivalent GPU textures across mesh instances. Material file and Scene schemas are unchanged.

## Implementation

- Added a bounded BGRA8 mip-chain preparation API. It converts sRGB source pixels to linear values, applies the linear base-color factor, then area-filters each level. Odd-sized source footprints are covered; input bytes are never modified.
- Added a common resolver for the six minification modes and mapped the selected texel and mip policies to BGFX flags. glTF `minFilter` omitted uses its `LINEAR` (non-mip) default.
- Added a Scene View texture cache keyed by decoded image content, dimensions, linear factor and mip-chain policy. Mesh references are counted; destroying or refreshing a mesh releases its reference, and the BGFX texture is destroyed after the final reference.
- Added bounds of 16 Mi source pixels, 96 MiB per packed upload chain and 256 MiB for live cached Scene View textures. Oversized or invalid uploads and cache pressure retain geometry and select diagnosed vertex-color fallback.
- Extended Editor smoke with two instances of the same project material. It confirms a mipmapped texture was submitted twice and a GPU cache hit occurred.

## Limits and next step

This validates local Windows D3D11 behavior only. It does not implement alpha blending, other material texture roles, Game View material rendering, other graphics backends, cross-driver pixel-golden tolerances or a quality/performance budget. The area filter is a basic box filter, not a high-quality offline texture processor. Recommended next work is a 07.2q assessment of alpha mode, blend state and depth ordering before implementing any transparent-material rendering.
