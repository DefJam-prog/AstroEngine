# 07.2s — Alpha-aware base-color mip chains

## Implemented

- OPAQUE mip filtering keeps the prior linear-space area average.
- BLEND mip filtering weights linear RGB by alpha, averages alpha, then unpremultiplies RGB for the existing straight-alpha shader and blend state. Transparent texel RGB no longer bleeds into visible filtered colors.
- MASK mip filtering applies the same fringe-safe color filter and scales mip alpha toward the source-level coverage fraction at the material's cutoff. A 256-bin alpha histogram and 24-step bounded scale search avoid rescanning each mip for every search iteration. When the requested fraction cannot be represented by a small mip's discrete pixels/8-bit alpha, the nearest coverage is used.
- Prepared texture cache keys include alpha mode and cutoff. Different MASK cutoffs cannot reuse a chain prepared for another cutoff.
- Added CPU tests for a transparent-color edge, a representable 25% MASK coverage, below/equal/above cutoff comparison and non-finite values. Existing Windows D3D11 Editor smoke exercises below-cutoff discard over a translucent overlap.

No source texture bytes, imported geometry, material asset schema, shader contract or external dependency changed.

## Limits

- MASK coverage is approximate where discrete mip texel counts or 8-bit alpha cannot encode the base-level coverage ratio; smallest mips have the largest quantization error.
- Exact/elevated cutoff shader output is covered by the CPU comparison contract, not a separate rendered-pixel assertion. The Editor D3D11 image smoke verifies below-cutoff discard and blend visibility.
- No image golden, performance benchmark, macOS/mobile build, or non-D3D11 backend was run. This is Scene View preparation, not Game View support.
