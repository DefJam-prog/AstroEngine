# 07.2y — partial-alpha MASK minification smoke

## Scope

Exercise mipmapped alpha-cutout rendering in the existing Windows Editor Scene View using a texture with genuinely partial alpha texels. Keep this as a disposable visual test; do not modify project/user images, material schemas, renderer APIs or dependencies.

## Implementation

Extended the smoke PNG generator with a 64×64 horizontal alpha ramp from 0 to 255 while retaining constant diagnostic-magenta RGB. Added two Editor smoke commands and CTest cases using the current MASK material path, cutoff 0.5, Repeat sampling, `LinearMipmapLinear`, and UV U scales 2 and 4. The existing screenshot classifier requires 100–650 visible magenta pixels in the Scene View crop, and the overlap check requires at least 32 visible translucent pixels below discarded mask samples. CMake runs each smoke in a unique temporary project and removes that project after the process exits; generated image bytes are not placed in checked-in or user resource folders.

## Results

Both smokes rendered with Direct3D 11, reported one mipmapped MASK texture submission, and passed the pixel-range/overlap checks:

| UV scale | Mask magenta pixels | Underlying blend pixels | Result |
| ---: | ---: | ---: | --- |
| 2 | 351 | 297 | pass |
| 4 | 331 | 286 | pass |

This confirms the existing preparation, upload and Scene View path works for this partial-alpha fixture at two minification scales. It does not expose which mip the GPU selected.

## Limits

The screenshot pixel ranges are intentionally broad and specific to the current D3D11 adapter. Tests do not compare golden images, read the selected hardware LOD, evaluate other GPUs/backends, or cover arbitrary partial-alpha patterns and cutoffs. The CPU-only cutoff sweep is documented in the 07.2x report.
