# 07.2z — partial-alpha MASK cutoff minification sweep

## Scope

Exercise the partial-alpha mipmapped MASK path at additional material cutoff values in the existing Windows Editor Scene View. Preserve the cutoff 0.5 near/far smoke introduced in 07.2y. Keep all generated images within unique disposable smoke projects.

## Implementation

Added four Editor command/CTest combinations using the same temporary 64×64 magenta alpha ramp from 0 to 255:

- `editor.scene_view_mask_mips.partial.cutoff25.near.smoke` — cutoff 0.25, UV U scale 2.
- `editor.scene_view_mask_mips.partial.cutoff25.far.smoke` — cutoff 0.25, UV U scale 4.
- `editor.scene_view_mask_mips.partial.cutoff75.near.smoke` — cutoff 0.75, UV U scale 2.
- `editor.scene_view_mask_mips.partial.cutoff75.far.smoke` — cutoff 0.75, UV U scale 4.

Each keeps Repeat sampling and `LinearMipmapLinear`. The smoke asserts a mipmapped MASK texture was submitted, the cropped Scene View contains between 100 and 650 magenta mask pixels, and at least 32 underlying blend pixels remain visible. The cutoff is printed in the Editor smoke summary for diagnosis.

## Results

All four D3D11 cases passed:

| MASK cutoff | UV scale | Mask magenta pixels | Blend-through pixels | Result |
| ---: | ---: | ---: | ---: | --- |

| 0.25 | 4 | 486 | 123 | pass |

## Limits

Pixel ranges are broad assertions for the current Windows D3D11 adapter. The tests do not capture exact GPU LOD, provide golden-image comparison, generalize to arbitrary alpha images/cutoffs, or establish behavior on other drivers and graphics backends. The generated ramp is disposable test data, not a user resource or production asset.
