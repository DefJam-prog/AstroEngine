# 09.3b — Editor confirmation and property application

## Scope

This substage connects the read-only `entity.set_property` preview from 09.3a to a direct Editor review flow. In the **AI Change Review** panel the user can preview changing the selected entity name, inspect its before/after values, cancel the proposal, or confirm it. Confirmation rechecks project and scene identities, Scene ID, command schema version, and the current typed values; it then applies the existing transactional command through `AIEditorApi`. The scene is marked dirty and the change participates in the usual Undo/Redo history.

The implementation remains local and in-process. This is not a permission system or security boundary. Only entity-name authoring is exposed in the UI. JSON/IPC, project filesystem access, permissions/allowlists, sandboxing, checkpoints, general rollback, and previews for arbitrary command payloads are not included.

## Tests

- `ai.codex_change_review.unit` covers no pending preview, read-only preview behavior, changed project/scene identity, stale-value rejection, refreshed preview, confirmed application, Undo/Redo, cancellation, and clearing an earlier proposal after a rejected replacement preview.
- `editor.ai_change_review.smoke` opens an isolated test project and uses synthetic SDL/ImGui pointer events to activate Preview and Confirm. It checks that the panel and diff were drawn and that the proposed name was applied. It is an automated UI event-path smoke, not a manual physical mouse test.
- `editor.localization.unit` remains part of the full regression suite for the added Russian strings.
