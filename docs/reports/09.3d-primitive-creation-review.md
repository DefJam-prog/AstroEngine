# 09.3d — AI-reviewed built-in primitive creation

## Scope

Extended the existing AI Change Review flow to create one built-in 3D primitive through the registered transactional `entity.create_primitive` v1 command. The Editor proposal includes a name, Cube/Plane/Sphere/Cylinder shape, optional selected parent, and visibility. Preview is read-only and shows the expected next Entity ID. Confirmation checks project path, scene path, Scene ID, next ID and the proposal again before executing the command. Normal Editor use selects the returned entity. Existing transaction code owns Undo/Redo, while the existing scene serializer owns persistence. Primitive geometry is in-memory; project asset files are not created or modified.

## Tests

The review unit test covers read-only preview, typed values, expected ID, changed project rejection, stale next-ID rejection, refreshed confirmation, stable-ID Undo/Redo, and cancellation. The Editor smoke drives the preview and confirmation controls, writes and reopens its temporary scene, and checks the resulting primitive's ID, name, parent, shape and visibility. Localization coverage was added. Existing name-review and SpriteRenderer-visibility smokes remain regression checks.

## Limits

This is a direct confirmation flow for one typed command, not a general AI approval system or security boundary. The preview's predicted ID becomes stale if another operation consumes that ID; confirmation rejects that preview and requires a new one. No remote transport, permissions model, filesystem allowlist or sandbox was added. Validation ran on Windows x64/MSVC Release with D3D11 for the Editor smoke; other operating systems and graphics drivers are not established by this run.
