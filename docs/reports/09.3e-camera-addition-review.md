# 09.3e — AI Change Review for Camera3D addition

## Goal

Extend the existing in-process AI Change Review by one bounded operation: propose and confirm adding the engine's existing `Camera3D` component to a selected scene entity. This slice does not introduce arbitrary AI command execution, a remote transport, or a permission boundary.

## Implementation

- Added read-only `previewAddCamera3D` to the project adapter. It requires the registered transactional `camera3d.add` schema and validates the typed target without mutating the Scene.
- Added pending-review and confirmation handling for Camera3D. Confirmation checks project root, scene path, Scene identity, target existence, and a fresh preview before delegating to `AIEditorApi`.
- Uses the existing `camera3d.add` transaction. New cameras remain inactive by default; normal command Undo/Redo and scene serialization own lifecycle and persistence.
- Added a dedicated Editor panel action, Russian localization, unit coverage, and an Editor-window smoke that previews, confirms, saves, and reloads a temporary scene.
- Kept the camera review smoke fixture on a scene entity that does not already have a Camera3D. This makes the smoke independent of existing active Game View camera setup.

## Validation

## Scope and limitations

- Camera creation is limited to one existing entity and the registered default `camera3d.add` operation.
- The camera starts inactive, so adding it does not silently change Game View output.
- The review is trusted in-process Editor UI. It does not isolate callers, authorize arbitrary commands, or provide OS-level security.
- No manual visual interaction was performed in the running Editor during this substage; UI behavior was exercised by the automated window smoke.
- The repository already had extensive unrelated tracked and untracked changes before this substage. They were preserved; no cleanup, commit, or GitHub push was performed.
