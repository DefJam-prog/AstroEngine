# 09.3f — AI Change Review for Camera3D lens settings

## Goal

Add one bounded AI review operation for changing the lens values of an existing perspective camera. Keep validation, Scene mutation, component identity, and Undo/Redo in the existing `camera3d.set_lens` transaction.

## Implementation

- Added an adapter preview for `camera3d.set_lens` v1. It requires that the command is registered and transactional, validates the requested payload, and snapshots the Scene ID, Entity ID, Camera3D Component ID, old/new FOV and clipping planes, and active state.
- Added review preparation and direct confirmation. Confirmation rejects changed project/scene identity, stale lens values, a replaced component, a changed active flag, and no-op values before delegating to `AIEditorApi`.
- Added the Editor form for vertical FOV, near plane, and far plane. Its diff shows each old/new value and states when the active camera will affect Game View. The operation does not switch or toggle the active camera.
- Added Russian localization, unit coverage, a new CTest window smoke, and checks that an active camera keeps its component ID and active state after confirmation and scene reload.

## Limitations

- Only FOV, near and far values for an existing Camera3D are covered. This operation cannot activate a camera, change transforms, or edit other camera settings.
- Changing an active camera's lens values intentionally affects Game View after confirmation; the review panel calls out that effect.
- The review model is a trusted in-process UI workflow. It is not a permission boundary, a sandbox, or a remote Codex executor.
- The mixed-DPI hardware scenario remains unavailable on this host.
- The worktree contains extensive pre-existing user changes. They were preserved; no cleanup, commit, or GitHub push was performed.
