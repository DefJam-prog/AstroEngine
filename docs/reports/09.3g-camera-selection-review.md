# 09.3g — AI Change Review for active Camera3D selection

## Goal

Add a bounded review workflow for selecting the active Camera3D in the edit Scene. Activation and explicit clearing must be visibly distinct, read-only until confirmation, stale-safe, undoable and persisted through the existing command/scene paths.

## Implementation

- Added `previewSetActiveCamera3D` for the registered transactional `camera3d.set_active` v1 command. It validates the typed payload and records Scene ID, current active entity/component identity, target entity/component identity, and whether the value changes. Entity ID `0` represents an explicit clear.
- Added pending review/confirmation APIs. Confirmation rejects absent pending state, project/scene mismatch, stale active camera or component identity, stale target identity, and no-op changes. A valid confirmation delegates to `AIEditorApi` and checks that Scene now reports the reviewed target. The existing command owns validation and Undo/Redo.
- Added separate Editor actions to preview activation of the selected Camera3D and to clear the currently active camera. The diff displays previous → target (or no active camera). Its warning explains that clearing removes 3D meshes from Edit Mode Game View; Play Mode keeps its separate runtime Scene.
- Added Russian localization, unit cases for stale previews, clear, no-op, cancellation and Undo/Redo, and two CTest window smokes that confirm and save/reload selection and clear behavior.

## Limitations

- This only reviews the current active-camera selection. It does not edit camera transforms, lens values, projection types, or arbitrary command payloads.
- Clearing affects the edit Scene. Play Mode has its own runtime Scene and keeps its camera; the preview states this explicitly.
- The review model is trusted in-process UX, not an OS/security boundary, general permission model, sandbox, or remote Codex executor.
- Mixed-DPI hardware behavior and manual visual interaction remain unverified on this machine.
- The worktree contains extensive pre-existing user changes. They were preserved; no cleanup, commit, or GitHub push was performed.
