# 09.3h — AI Change Review for Camera3D Transform: contract assessment

## Scope

Determine whether the current Scene, command and camera-pose APIs support an unambiguous AI-reviewed Camera3D transform change. This is an assessment-only substage; no transform behavior or command is implemented here.

## Findings

- `scene::Transform` stores `position`, `rotationDegrees` and `scale`; each `TransformComponent::value` is interpreted locally relative to its entity's parent.
- `render3d::sceneEntityWorldTransform` composes parent transforms, and `resolveSceneCameraPose` derives the camera's world position, forward/up basis and lens projection from that world transform. The hierarchy-aware path is already covered by `editor.scene_camera_pose.unit`.
- `Scene::setTransform` is a direct Scene API. `registerSceneCommands` has no `entity.set_transform` or equivalent typed transaction. The existing `entity.set_property` command is limited to the registered entity property schema; currently that schema exposes only editable `name` (plus read-only ID). It cannot be used to change Transform.
- The AI Change Review workflow applies through a registered transactional command so validation, audit and Undo/Redo stay on the existing command path. Calling `Scene::setTransform` directly from AI review would bypass that contract. Therefore no safe apply path exists for this slice.

## Proposed contract for a later implementation

1. Add a dedicated typed transaction, provisionally `entity.set_transform` v1, with one complete local Transform payload `{entity, position, rotationDegrees, scale}`. Do not overload `entity.set_property` and do not silently accept world-space values.
2. Validate all nine values as finite and enforce documented bounds before mutation. The transaction should capture the full before/after Transform, preserve the Transform Component ID, and provide deterministic Undo/Redo.
3. AI preview should label its editable values **Local Transform** and show their exact before/after values. For a Camera3D, it may separately display **Derived world camera pose** (position and basis) as read-only output.
4. At confirmation, revalidate Scene/entity/Transform Component identity and exact local before-value. Recompute the target camera world pose using the current parent chain; any intervening hierarchy, ancestor Transform or target Transform change must invalidate the preview. The payload remains local and is executed only by the typed transaction.
5. Keep projection/lens settings, active-camera selection and transform editing as separate reviewed operations. No renderer or external dependency change is needed for the proposed contract.

This contract is a recommendation, not an implemented API. In particular, numeric bounds, singular-scale behavior and the exact parent-chain snapshot representation need to be decided and tested before implementation.

## Outcome and next slice

AI-reviewed Camera3D Transform mutation is **not available** in the current project. The necessary typed transaction must be implemented and validated before adding the AI preview/UI. A suitable next substage is a separate Scene command contract for local Transform with finite/range validation, transactional undo/redo and Scene-command integration tests; the AI review should remain deferred until that command is accepted.

No source/API, test, dependency, generated asset, commit, or remote repository changes were made in this assessment. Existing user worktree changes were preserved.
