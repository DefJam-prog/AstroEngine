# 09.3i — typed transactional local Transform command

## Goal

Provide the missing typed command prerequisite for future AI-reviewed Transform edits. This slice only adds the Scene command and its contract; it does not add an AI Change Review panel, Inspector widget, or world-space transform API.

## Implementation

- Added `SetTransformPayload { entity, value }`, where `value` is a complete local-to-parent `Transform` containing position, Euler rotation in degrees, and scale.
- Registered `entity.set_transform` v1 as a transactional Scene command. Its schema lists the EntityId and nine numeric fields: `position_x/y/z`, `rotation_degrees_x/y/z`, `scale_x/y/z`.
- Dry-run validates through a copy of Scene and its existing `Scene::setTransform` validator. This preserves the current contract: all nine values must be finite. No arbitrary range constraints were introduced, and zero scale remains accepted.
- The transaction captures the full prior Transform and its ComponentId. Apply, Undo, and Redo use `Scene::setTransform` and check that the entity still has the same Transform ComponentId before changing values.
- Added integration coverage for stable catalog ordering/schema, read-only dry-run, missing entity, NaN, complete field changes, stable ComponentId, Undo, and Redo. Extended Scene unit coverage to verify that direct set preserves the ID and invalid values leave the prior Transform untouched.

## Limitations

- `entity.set_transform` accepts local values only. It does not derive or accept a world-space destination.
- Existing Scene validation requires finite values but does not constrain magnitude or reject zero scale. A singular composed world matrix may be diagnosed/rejected by Camera3D or render consumers.
- AI Change Review, Editor authoring controls, preview of derived world camera pose, and stale ancestor-chain confirmation checks are not implemented in this substage.
- No serialization schema change or new dependency was needed; existing scene serialization already persists local Transform.
- Extensive pre-existing user worktree changes were preserved. No cleanup, commit, or GitHub push was performed.
