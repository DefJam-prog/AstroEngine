# 09.3j — AI Change Review for local Transform

## Scope

Connected the existing transactional `entity.set_transform` v1 command to the in-process **AI Change Review** panel. The panel now offers a collapsible editor for local position, Euler rotation in degrees, and scale. Preview and confirmation use the existing command path; no world-space command, dependency, serialization change, or user asset modification was added.

## Behavior

- The read-only preview records Scene ID, Entity ID, Transform Component ID, local before/after values, and the local Transform plus parent link/Component ID for every entity from the target through the root.
- Confirmation re-creates the preview and rejects a changed project/scene identity, target Transform, parent link, ancestor Transform, or component identity. This protects the displayed derived camera result from stale hierarchy data.
- For an entity with Camera3D, the Editor copies the Scene, applies the proposed local Transform to that copy, and displays derived world position, target, and up before/after. These values are not sent to the command. If world-pose resolution fails (for example, because the hierarchy is singular), the UI reports that the derived pose is unavailable; the local preview remains visible.
- Applying delegates to `entity.set_transform`, retaining existing validation, transactional Undo/Redo, and stable Transform Component ID. Validation remains finite-only; zero scale is not newly rejected.
- Russian translations were added for all new controls and preview labels.

## Limits

The window smoke uses synthetic SDL/ImGui input and verifies save/reload; it does not substitute for a manual physical-mouse review. The confirmation UX executes inside the trusted Editor process and does not provide OS-level permissions or an AI security boundary. World-pose display is available only for entities with Camera3D and a resolvable hierarchy.
