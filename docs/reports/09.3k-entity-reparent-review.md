# 09.3k — transactional hierarchy reparent and AI Change Review

## Scope and decision

Implemented only substage 09.3k. Parent changes preserve local Transform: reparenting changes the parent link, retains descendant links and target Transform/component identity, and lets world poses be recalculated through the hierarchy. Preserving world pose is not offered because rotated/non-uniform-scale decomposition needs its own contract.

## Behavior

- Added typed transactional `entity.reparent` v1; `parent = 0` means Scene root. Dry-run validates on a Scene copy. Apply/Undo/Redo check the expected parent and stable Transform ComponentId.
- AI Change Review offers valid parents, displays before/after parent and affected subtree size, and previews derived Camera3D world position/target/up where resolvable.
- The adapter snapshot captures Scene/Entity/Transform identity, source and destination ancestor chains, target local Transform, and the affected subtree. Confirmation recomputes the preview and rejects stale state, no-op changes, invalid/cyclic targets, and changed project/scene identity before calling the registered transaction.
- Russian Editor labels and a window smoke were added. The smoke verifies read-only preview, changed derived camera pose, preserved local Transform and component identity, intact descendant relation, and scene save/reload.

## Limits and risks

The review snapshots the full moved subtree, so preview cost and memory scale with that subtree. The automated UI path uses SDL/ImGui synthetic input; physical-mouse review and non-Windows builds were not performed. The review remains trusted in-process UX, not an authorization/security boundary. No world-pose-preserving mode was added.
