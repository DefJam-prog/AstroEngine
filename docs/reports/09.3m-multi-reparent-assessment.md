

# 09.3m — оценка контракта группового переподчинения

## Scope

Оценить безопасную семантику перемещения нескольких выделенных сущностей между родителями в Hierarchy. Это assessment-only подэтап: implementation/API не менялись.

## Наблюдаемое состояние

- Editor хранит одно `std::optional<EntityId> selectedEntity`; модель набора выделения отсутствует.
- Hierarchy drag/drop 09.3l отправляет одну сущность.
- Существующая `entity.reparent` v1 принимает одну пару `{entity, parent}` и сохраняет локальный Transform.
- `EntityId` — `std::uint64_t`.
- `CommandTransaction` собирает шаги; commit выполняет их по порядку, отменяет успешные шаги в обратном порядке при ошибке следующего, Undo проходит в обратном порядке, Redo — вперёд. Ошибка самого rollback может оставить состояние требующим восстановления; это ограничение существующего transaction manager.
- `CommandFieldType::NumberArray` уже используется для трёх чисел цвета и не даёт документированной гарантии точного представления всех 64-битных ID внешним числовым транспортом. AI Editor API пока typed C++ фасад без JSON/удалённого вызова.
- Scene reparent меняет parent link без изменения порядка entities; мировой Transform выводится из иерархии.

## Рекомендуемый UX-контракт

1. Обычный клик оставляет одну выделенную строку; Ctrl+Click переключает членство строки в наборе. Shift-range selection не включать в первую версию.
2. Если drag начинается с уже выделенной строки, перемещается весь текущий набор. Если строка не выделена, сначала заменить набор этой строкой, затем начать drag.
3. Сохранять отдельную primary selection для текущего Inspector. В первом срезе multi-selection используется только для drag/drop; delete, Inspector edit и другие команды продолжают работать только с primary selection, чтобы не расширять семантику скрыто.
4. Перед reparent нормализовать набор до верхних выбранных корней. Если выбраны и предок, и его потомок, отправлять только предка: потомок остаётся в его поддереве и не получает отдельное изменение parent.
5. Разрешать цели entity и Scene root. Все ID/цель должны относиться к текущей Scene. Отклонять пустой набор, отсутствующие/дублированные ID, цель внутри поддерева любого перемещаемого корня, self-parent и любые циклы.
6. Если отдельный root уже имеет цель родителем, считать его unchanged и не создавать для него transaction step. Если весь набор unchanged, операция — no-op без записи Undo.
7. Сохранять local Transform и стабильный Transform ComponentId. World-space позиции могут поменяться. Не менять Scene entity storage order: отдельного sibling ordering контракта сейчас нет.
8. После успешного применения оставить перемещённый набор выделенным, обновить primary selection предсказуемо и раскрыть целевую ветвь. Для root-drop раскрыть корень без неожиданной смены primary entity.

## Рекомендуемый API/transaction contract

Сохранить `entity.reparent` v1 для обратной совместимости. Рассмотреть отдельную `entity.reparent_many` v1 с typed payload `{entities: vector<EntityId>, parent: optional<EntityId>}` (root может следовать текущему соглашению 0). Все элементы проверяются на копии Scene до выполнения. Успешные изменения упаковываются в одну CommandTransaction/history item, с stale guard для каждого исходного parent и Transform ComponentId. Это даёт одну Undo/Redo на drag и атомарное применение при обычной ошибке шага.

Перед публикацией схемы определить точное представление unsigned integer array. Не использовать floating-point NumberArray для EntityId без доказанного точного диапазона. AI Editor API не сериализует payload сейчас, однако каталог схемы должен оставаться недвусмысленным для последующего адаптера.

## Required tests before implementation acceptance

- Pure/unit: deduplication/normalization, selected ancestor plus descendant, empty set, stable command ordering, same-target no-op.
- Command integration: mixed old parents, root target, target in one selected subtree, unknown ID, duplicates, stale source parent/Transform ID, no mutation on validation failure, all-or-nothing rollback after a later step fails, exactly one undo/redo restoring all links and IDs.
- Editor smoke: Ctrl selection, drag from selected row, unselected-source behavior, entity/root drop, selection/Inspector focus, invalid-target feedback, save/reload.
- Localization test for all visible labels/errors; existing single-entity reparent tests remain unchanged.

## Risks and open decisions

- Group semantics must be clear when both parent and descendant are selected; normalization avoids duplicate movement and preserves subtree structure.
- Per-command execute calls cannot meet one-Undo/atomic-group behavior; do not loop `entity.reparent` from the widget.
- Scene order has no separate sibling rank; visually reordering siblings is not part of this contract.
- `uint64_t` IDs must not silently round through a generic floating numeric array.
- Transaction rollback is best effort if an undo callback itself fails; tests should exercise normal forced-step failure, while existing recovery-failure limitations remain documented.
- The proposal is not yet user-approved implementation scope. Await explicit confirmation before coding a batch command or multi-select UI.
