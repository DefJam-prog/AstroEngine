# 09.3p — групповой Inspector для local Transform

## Реализация

- Inspector получил режим общего выбора: число сущностей, блок **Transform (Local)** и девять полей position/rotation/scale.
- Различающиеся значения показываются отдельно как mixed. Новый ввод одного поля сохраняет остальные поля каждого Transform.
- Перед применением UI сравнивает snapshot Scene, EntityId, Transform ComponentId и Transform value. Устаревший snapshot блокирует Apply; смена выбора сбрасывает черновик с сообщением.
- После общего блока остальные редакторы явно подписаны как относящиеся к primary entity. Массовая правка других компонентов, материалов и скриптов не добавлена.
- `entity.set_transforms` v1 принимает `SetEntityTransformsPayload` со структурированными `{EntityId, local Transform}` assignments. Каталог объявляет `TransformAssignmentArray`. Все назначения валидируются до изменения live Scene, дубликаты отклоняются, no-op пропускаются, а изменения формируют одну Undo/Redo transaction.
- Успешное применение отмечает Scene dirty и использует штатное сохранение. Компонентные ID и поля, которые не редактировались, сохраняются.

## Ограничения и следующий подэтап

- Smoke напрямую задаёт numeric draft для проверки общего пути Apply; ручное редактирование текста в поле клавиатурой отдельно не автоматизировано.
- `TransformAssignmentArray` доступен типизированному C++ API и отражается в каталоге, но JSON/remote transport для него отсутствует.
- Автоматизация группового редактирования компонент, материалов или скриптов отложена до контракта совместимости.
- Ручная проверка мышью/клавиатурой и платформы, отличные от Windows, не проверялись.

Следующий разумный пункт — отдельная оценка поведения mixed-value полей при последовательном редактировании нескольких Transform-полей и UX отмены черновика; начинать его следует только после подтверждения пользователя.
