# 09.3q — клавиатурный ввод и устаревший черновик группового Transform Inspector

## Цель и объём

Проверить, что общий Transform Inspector принимает числовой ввод через фактический SDL/ImGui путь, держит его как черновик до Apply и не позволяет применить черновик после изменения исходного Transform. Изменение публичного Command API, формата сцены и зависимостей не требовалось.

## Изменения

- Smoke `editor.hierarchy_multi_transform_inspector.smoke` активирует mixed поле Position X, выделяет текст Ctrl+A, вводит `12.5` через SDL text event и подтверждает Enter.
- Smoke проверяет, что draft стал `12.5`, а Transform обоих объектов не изменились до Apply.
- Затем тест изменяет Transform одного объекта внешним действием, проверяет stale состояние, выключенный Apply и сохранение draft, после чего перезагружает выбор и проверяет очистку draft.
- После обновления snapshot smoke повторно применяет значение штатным общим обработчиком и проверяет одну запись истории, Undo/Redo, стабильность ComponentId и save/reload.
- Тестовое окно рисуется последним поверх Editor UI, чтобы Scene View и Hierarchy не перехватывали синтетический клик по полю.

## Ограничения и следующий шаг

Smoke посылает события приложению и проверяет ImGui; он не заменяет ручную проверку на физической клавиатуре. Остальные редакторы компонентов остаются только для основного выбранного объекта; внешний JSON/remote codec команды `entity.set_transforms` не реализован.

Рекомендуемый следующий подэтап: отдельно автоматизировать смену multi-selection при незаписанном draft и подтвердить показ сообщения о сбросе, не расширяя групповое редактирование других типов компонентов.
